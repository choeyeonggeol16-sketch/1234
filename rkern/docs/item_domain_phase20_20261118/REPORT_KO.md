# RKern 아이템 20차 — 과분리 통합 + 저수준 메모리/CPU 경로

기준: `RKern_Item_Consolidation_Memory_Phase19_FULL_SRC_20261118.zip` (19차 전체 SRC).

## 적용

- `SealedRuneLevel{55,70,80,85,90}Rewards.java` 5개 삭제. 정확히 기존 25개 분기와 직업별 독립 검사·보상 지급 순서를 유지한 채 `RuneRewardPackages.java`의 `stageLevel*`에 병합. `stageSealedReward`와 원래 트랜잭션 호출은 그대로 사용.
- `DominationTowerReturnHandler.java`: 변경하지 않는 층별 좌표 11개를 기록한 `HashMap<Integer,int[]>`과 11개 배열 대신 Java 21 `switch` 상수 분기 사용. 기존 13005 금지, 텔레포트 제한, 일반 귀환 `Getback` 우회, 소비 및 커밋 후 콜백은 유지.
- `OmanAmuletHandler.java`: 층별 위치를 담는 `HashMap<Integer,OmanLoc>` 및 위치 인스턴스 10개 대신 private `int[]` 좌표표 두 개. 검증·금지 스킬·아이템 ID 및 맵 대응은 동일.
- `NearbyItemTargetQueries.java`: 반경 밖의 PC를 만날 때 동일한 Chebyshev 타일 거리 계산을 두 차례 호출하던 부분을 한 번만 실행. 반경 안팎의 결과, 중복 메시지까지 기존 동작 유지. 실제 `Point.getTileLineDistance`는 순수 정수 연산임을 소스에서 확인.

생산 Java **수정 4개, 삭제 5개, 신규 0개**. 다른 아이템/네트워크/방송/NPC/DB 공통 소스는 변경하지 않음.

## 검증

`test_phase20_typed.py`: 원본 생산 Java와 변경된 생산 Java를 실제로 `javac --release 21`로 각각 컴파일한 뒤 동일한 테스트 모델에서 실행·비교.

- 룬 41,472가지: 25개 보상 ID + 예외 ID, 256가지 (상호 중복 포함) 직업 플래그, 재료 존재/부재, `stageSealedReward` 실패 주입. 원본/변경본의 단계별 호출·보상·예외 기록 SHA-256 일치.
- 귀환·부적 10,112가지: 지배탑 11층, 지배탑 외 맵, 13005, 금지 스킬, GM, 일반 귀환 금지, Getback null, 콜백 실행/보류, 이동부적 ID 범위, 상태 제한; 반환/좌표/소비/효과/메시지 로그 SHA-256 일치.
- 주변 타겟 2,310가지: 원본/변경본 반환 대상 개수 및 안내 패킷 수 일치. 대표 입력 세트에서 타일 거리 호출 158,456 → 91,140회.
- Java 21 전체 생산 소스 1,935개 구문 검사, 오류 0건.
- 19차 이전 원본 비교: 빙수 960가지, 이동 물약 17,280가지, 스타터 장비 1,024가지, 메시지 1,232가지 통과.
- 방송 114차: 10가지 오류 주입 및 수신자 5,000명 스트레스 검증 통과.
- 전체 ZIP CRC, 중복 경로, 수정·삭제 외 기존 모든 파일 바이트 일치 검사 포함.

## 한계

- 테스트용 게임 모델을 붙인 **수정 영역 한정 Java 타입 컴파일**이며, **전체 게임 의존성 타입 컴파일**은 아니다.
- 전체 게임 실행, 실제 MySQL/CacheD 장애·ACK 손실·재접속·서버 재시작, 라이브 아이템 사용 및 5,000명 운영 부하 테스트는 수행하지 않음.
- 맵 구조 제거는 장수명 할당/retained heap 감소를 위한 것이고, 서버 전체 메모리·GC 절감 폭은 아직 실측하지 않음.
- 20차는 기존 기능 보존에 집중했고, 기존 룬 보상·거래 구현 자체의 버그를 새로 수정했다고 주장하지 않음.
