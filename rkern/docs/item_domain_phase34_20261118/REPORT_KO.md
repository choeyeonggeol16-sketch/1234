# RKern 아이템 34차 — 지급 과정의 월드 임시 객체 및 중복 생성 정리

## 기준과 수정 범위
- 입력: `RKern_Item_WorldObjectLifecycle_Phase33_FULL_SRC_20261118.zip`.
- 변경된 생산 소스는 `Beginner.java`, `RankBuff.java`, `L1PetRaceTrap.java` 세 개뿐이며 신규 생산 클래스는 없음.
- `L1Inventory`, `L1World`, CacheD, 네트워크, 방송, NPC 상태 엔진은 변경하지 않음.

## 수정 내용
1. `Beginner.GiveItemToActivePc`: 초보자 즉시 지급에서 `ItemTable.createItem()`이 미리 월드에 넣은 객체를, 지급 거부·실패·스택 병합 시 `finally`에서 제거. 실제로 인벤토리가 새 인스턴스를 소유하면 유지. 이미 저장에 실패한 경우에는 403 성공 메시지를 보내지 않음. 스택/비-스택 지급 수량·ID·강화·기존 부분 지급 순서 유지.
2. `RankBuff.giveProtectionItem`: 랭커 가호 아이템을 이미 갖고 있으면 새 객체 생성 전에 반환. 신규 지급 시 거절·병합·예외에서 월드 임시 객체를 제거. 최초 지급의 버프/아이콘/능력치 흐름은 그대로 둠.
3. `L1PetRaceTrap`: 펫레이스 보상 지급 직후 메시지용으로 같은 아이템을 한 번 더 `createItem()`하던 경로 제거. 실제 지급 반환 객체의 `getNumberedName(1)`로 기존 한 개 지급 메시지 생성. 저장 실패에는 거짓 성공 메시지를 내지 않음. 보상 판정 난수, 재화 지급, 레이스 상태 변경은 변경하지 않음.

## 검증
- JDK 21 `JavacTask.parse()` 전체 생산 Java **1,925개** 구문 오류 0.
- 실제 33차/34차 소스에서 추출한 지급 메서드와 펫레이스 보상 블록을 Java 21로 타입 컴파일해 **85개 시나리오, 236개 단언** 통과. 스택 병합, 이미 가진 아이템, 용량 거부, 조회/저장 예외, 저장 반환 null, 다중 초보자 보상 순서를 포함.
- 정상 지급/병합의 인벤토리 내용과 사용자 메시지 동일; 거절/병합의 고아 월드 객체 감소를 확인. `storeItem()==null` 때의 거짓 성공 메시지는 의도적으로 막음.
- 33차 지급 회귀 2,306 체크; 32차 상자 원자성 1,381건; 31차 스타터 패키지 521건; 아이템 레지스트리 259,200건 및 물약·빙수·룬·이동 비교 통과.
- 방송 114차 오류 주입/5,000수신자 모의 회귀검사 통과(방송 코드는 변경 없음).
- 최종 ZIP CRC·중복 경로·33차 미변경 파일 바이트 동일성 별도 확인.
