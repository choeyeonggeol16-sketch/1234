# 보스 출현 예약과 재시작 복구

`CBossNpcMaker`가 일반 보스의 월드 등록과 수명을 관리한다. `CNpcSpawnDefine`은 기존 `spawnlist_boss_hot`의 설정 한 행이고, `CRespawnTimer`는 기존 월드 타이머에서 그 위치의 다음 출현을 실행한다. 기준 시간대는 기존 서버와 같은 JVM 기본 시간대다.

서버는 InnoDB 테이블 `boss_respawn_state`에 NPC 번호, X, Y, 맵을 키로 저장한다. 요일·시각·랜덤 지연·시간대의 설정 지문, 기준 시각 및 실제 추첨된 시각이 들어간다. 기존 운영 계정에 테이블 생성 권한이 없으면 기동 전에 [마이그레이션](../../../database/Net_boss_respawn.sql)을 적용한다. 이미 적용한 DB에서도 다시 실행할 수 있다.

GM의 보스스폰 리로드에서 같은 시간표의 예약을 유지한다. 재기동 때 지난 예약은 예정 시각에서 한 시간 이내이며 그 뒤의 다음 기준 시각 전이면 한 번 처리하고, 더 오래된 회차는 건너뛴다. 월드 등록과 수명 타이머가 확보돼야 출현을 처리한 것으로 기록한다. DB 응답을 잃으면 같은 실행 중에는 월드 등록 결과를 기억해 재등록을 방지한다. 실제 월드와 SQL은 서로 다른 시스템이므로 강제 종료 순간까지 두 시스템의 원자성을 보장하지 않는다. 이미 등장한 보스의 전투 HP·MP·좌표는 저장 대상에서 제외된다.

보스 이동은 알림을 만든 출현 개체와 설정 좌표를 검사한다. 클라이언트의 기존 응답 형식에 초대 번호가 없으므로 한 캐릭터에는 유효한 초대를 하나만 둔다. 새 초대를 발행한 뒤 늦게 도착한 이전 응답은 프로토콜상 구별할 수 없다.

## 검증

- MariaDB 11.8.9와 Net 설치본의 출현 설정 112개, NPC 108종을 사용했다. 가상 시계와 시험용 월드 등록 함수를 사용한 두 Java 프로세스에서 리로드·재시작 전후 예약 112개가 모두 일치했고, 기르타스 1회와 드레이크 세 자리의 독립 처리를 확인했다.
- 별도 시험에서는 실제 RKern 월드 등록 경로에 등록 예외와 수명 타이머 거부를 주입해 개체 정리를 확인했다. 타이머 한도, DB 트랜잭션 롤백, 커밋 응답 유실, 오래된 콜백을 검사했다.
- 실제 루프백 TCP 세션에서 기존 두 이동 응답 처리기, 중복 응답, 세션 교체 및 10초 만료를 확인했다. 시험 캐릭터에서 이동 호출에 전달되는 좌표를 기록했다. [회귀 시험 코드](../../tests/boss/)
