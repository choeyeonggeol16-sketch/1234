## 특별히 달라지는 의도된 동작

- 기존의 `consumeItem` 실패를 무시한 퀘스트 단계 변경·텔레포트를 차단함.
- NPC 71090 최초 지급은 퀘스트 단계 0에만 허용하며, 단계 변경/지급을 동일 SQL receipt로 확정함.
- DB receipt 확정 전 성공 메시지, 후속 HTML, 텔레포트를 전송하지 않음. 따라서 성공 통지는 비동기 커밋 완료 시점으로 이동함.
- 결합 교환에서 부분 성공을 허용하지 않으므로, 동일 사용 요청 내 여러 품목 중 하나라도 문제가 발생하면 전부 취소함.

## 검증하지 않은 범위

- 운영 MySQL/InnoDB 장애, CacheD ACK 소실·불확정 커밋·세션 교체 회수.
- 전체 프로젝트의 외부 의존성 포함 통합 빌드 및 실제 클라이언트 행동.
- 기존의 다른 NPC 제작/보상, 일반 아이템 지급/거래 전체를 전수 종결하지 않았음.

원본 대비 실제 변경 파일은 `CS_NpcAction.java` 1개이며 기존 네트워크·DB 공통 클래스는 수정하지 않았음.
