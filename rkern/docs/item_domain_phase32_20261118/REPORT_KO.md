# RKern 아이템 32차 — 구형 선물상자 원자 지급

기준: `RKern_Item_StarterKit_Atomic_Phase31_FULL_SRC_20261118.zip`.

## 원인·수정

- 아이템 `41303`/`41304`는 기존 `storeItem(아데나)` 및 `storeItem(랜덤 보상)` 실행 후, 마지막에 사용한 상자를 `removeItem(1)`로 차감했다. 중간 실패 시 아데나·랜덤 보상만 남거나 상자 소모가 이루어지지 않을 위험이 있다.
- `LegacyGiftPackageUse`와 `LegacyGiftGroupTwoUse`를 통합해 `LegacyGiftBoxes` 하나로 변경하고, `ItemActionDispatcher`에서 직접 연결했다. 장기 유지되는 배열/리스트와 아이템 사용마다 생성되는 컬렉션은 추가하지 않았다.
- 사용 아이템의 현재 인벤토리 객체 동일성을 확인하고 기존 `User.CheckAndSetPendingUseETCItem`→`L1InventoryTransaction`→`CDB.RequestUseItem`→`CacheD` 영속 영수증으로 *상자 debit(1) + 아데나 grant + 선택 보상 grant*를 하나의 트랜잭션에 준비한다.
- 성공 메시지는 CacheD 확정 및 원래 CIO owner의 재생 후 한 번에 보낸다. 실패·롤백·용량 부족 시 상자 차감과 보상 지급이 모두 확정되지 않는다.
- 기존 `_random.nextInt(120)+1`, `_random.nextInt(170)+1`의 **단일 난수 호출**, 보상 테이블 및 메시지 문자열/출력 순서를 유지한다. 보너스가 없는 기존 마지막 분기도 아데나 지급 후 `아이템을 획득하지 못하였습니다.` 메시지를 보낸다.
- 기존 *실패 시 부분 지급이 가능했던 동작*은 의도적으로 원자적 전체 실패로 변경한 것이다. 성공 경로의 아이템 ID·수량·메시지 및 확률은 변경하지 않았다.

## 검증

- JDK21 생산 `LegacyGiftBoxes.java` 타입 컴파일(동작 검증용 게임/CacheD typed stubs) + 원본 31차 두 처리 메서드와 동일 난수값 290개 전수 비교 및 실패 주입: **1,381건 통과**. 성공 경로의 290개 입력에 대해 지급 목록/메시지/소모 결과가 모두 같으며, 제출 전 인벤토리/성공 메시지는 변경되지 않는다.
- 지급 단계별 실패, CacheD 롤백, 제출/용량 실패, 소유하지 않은 소스 객체, 잘못된 아이템 ID를 확인한다. `docs/item_domain_phase32_20261118/test_legacy_gifts_atomic.py`에서 재실행 가능.
- 31차 스타터 패키지 521건, 30차 직접 라우터 2,112건, 효과 레지스트리 259,200건, 19차 물약·빙수, 20차 룬 보상·탑 이동·대상 거리 회귀검사 통과.
- 방송 114차의 오류 주입 및 5,000수신자 모의검사 통과. 방송 코드는 이번 차수에서 변경 없음.
- Java21 전체 `src` 구문 파싱: **1,925개 파일, 오류 0건**.
- ZIP 중복 경로·CRC, Phase31 원본 대비 변경 범위와 미변경 파일 바이트 동일성 검증 완료.
