# RKern/L1J 아이템 21차 — 과분리 통합 + 메모리 할당 개선

**기준:** `RKern_Item_Consolidation_Memory_Phase20_FULL_SRC_20261118.zip` (20차).

## 생산 소스 변경

- `EnchantmentSuccessEffects` + `EnchantmentFailureEffects` -> `EnchantmentOutcomeEffects`: 강화 성공/실패 후처리를 한 책임 클래스로 통합. 두 원본 메서드 본문은 문자열 생성식 10곳 외 동일하며 저장·아이템 변경·패킷·효과·로그 순서를 보존.
- `ClassRewardPackages` + `LevelAndEquipmentPackages` -> `ItemRewardPackages`: 두 클래스의 `begin → debit → stage → onFailure → commit` 중복 거래 진입점 1개로 통합. 기존 보상 종류별 `stage` 함수 분기와 반환 경계 보존. `ItemActionDispatcher`의 해당 호출부 6곳만 연결 변경.
- 강화 메시지: `new StringBuilder().append(pm + level)`에서 중간 문자열 생성이 필요 없는 `append(pm).append(level)`로 변경. 원본 메서드의 나머지 부분은 문자 단위로 보존.
- 보호 주문서 거절 메시지 19곳(룸티스·스냅퍼·문장·휘장·견갑·오림): `String.format`의 Formatter 및 varargs 생성 대신 숫자 문자열 연결. 한국어 메시지 텍스트와 인자 값은 보존.
- `ClanRaidBossSelection`: 빈 설정에 대한 `new int[0]` 3곳을 공유 `EMPTY_BOSS_IDS`로 변경. 길이 0인 배열만 공유하며, 유효한 NPC ID 목록과 config 갱신 경로는 변경하지 않음.
- **기존 클래스 4개 삭제, 신규 통합 클래스 2개, 원래 있던 생산 Java 9개 수정, 생산 Java 전체 -2개.** 다른 게임·네트워크·방송·NPC·CacheD 공통 코드는 변경하지 않음.

## 확인된 검증

## 메모리 측정

- 보호 주문서 오류 메시지 단일 구문의 `ThreadMXBean` 할당 마이크로벤치마크 (Java 21, 10만 회): **Formatter 약 584 B/호출 → 연결 약 104 B/호출**. 문자열 생성 경로만의 결과이며 서버 전체 GC·처리량 개선치가 아님.
- 클래스 개수 감소 자체가 게임플레이 요청당 heap 사용 감소를 보장하지 않음.

- 과거 일부 *구조 고정형* 검사 스크립트는 이미 삭제되거나 21차에 이름이 바뀐 클래스를 직접 찾으므로 더 이상 적용할 수 없음. 이 변경 부분은 `run_tests.sh`의 최신 타입/동작 비교 검사로 대체. 과거 파일명 기준 테스트가 통과했다고 주장하지 않음.
