# RKern 아이템 226~231차
기준: RKern_ItemUse_Lifecycle_Memory_Audit_Phase220_225_FULL_SRC_20261119.zip. 생산 Java 변경 6개, 신규/삭제 0개. NPC·네트워크 코어·방송·CacheD 구현 및 일반 전투는 수정하지 않음.

- 226: 탐 열매 사용에 기존 L1InventoryTransaction/CDB receipt 적용. 캐릭터 계정 소유권, 5개 활성 제한, 예약/기간 갱신 및 열매 차감을 한 트랜잭션에서 처리한다. 실패 시 효과 및 성공 완료를 호출하지 않는다. 기존 3/7/30일, 예약 순서 및 2초 제한 유지. 음수/0 대상은 자신, 명시된 존재하지 않는 양수 대상은 오류 처리(기존 자신에게 적용되는 fallback 제거). 다른 온라인 대상 동기화는 기존 세션 owner 경로 사용.
- 227: 탐 예약 취소에서 동일 계정과 첫 예약의 정확한 id/day/objid를 잠금 재검증하고 지급과 삭제를 한 receipt 처리. CS_ActionUi의 해당 아이템 처리만 서비스로 위임. 만료 예약 갱신도 캐릭터와 예약 행을 잠금 검증하며 DB 트랜잭션으로 갱신 및 삭제. 운영 DB에 characters/tam의 InnoDB 필요.
- 228: 탐 30일 효과의 signed int 밀리초 overflow를 방지하고 기존 만료 재동기화 경로 사용. 효과 ID 제거 이후 stop handler의 기존 AC/DR 미복원 문제를 해당 탐 스킬에 한해 수정.
- 229: 충전형 낚싯대의 미끼와 충전량 변경을 receipt 내 영속 처리. 기존 낚싯대별 확률, 보상 함수 및 다음 시간 유지. 일반/무제한 낚싯대의 기존 동작 유지.
- 230: 낚싯대 소진 교환은 제거와 지급을 동일 receipt로 묶음. 확인된 rollback에선 지급/효과가 없으며 취소/이동 뒤 늦은 콜백이 낚시 세션을 되살리지 않도록 검사. 새 타이머·워커 없음.
- 231: 기존 204~210차 검사에 이후 211~225차의 승인된 분기만 명시적으로 반영, 이전 낚시 테스트의 mock에 이동한 미끼 차감 경로 반영. 기존 결과 비교를 전면 완화하지 않음.

검증: 신규 추출 Java 21 모의 조건 2341건(탐 SQL 조건/실패 1152, 예약 취소 32, 시간 경계 5, 낚시 1152). 이전 198~203, 204~210, 217~219, 220~225 테스트 재실행 통과. 전체 Java 1913개 parse 오류 0. 디스패치 1658 ID 라벨, 동일 switch 내 중복 0. 실제 서버 전체 타입 컴파일, MySQL 트랜잭션/ACK 유실/동시 세션, 실제 낚시·탐 UI, JFR/heap dump 미검증. 낚시 기본 보상 지급은 기존 post-commit 보상 함수이므로 충전 receipt와 보상 자체의 장애 원자성까지 증명하지 않음. 충전형 낚시 tick에 영속 트랜잭션 비용이 추가되어 실제 동접 부하 측정 필요. 탐 예약 취소의 기존 동기 조회는 남아 있음. 운영 DB/외부 라이브러리 부재. 미연결 ID 53개 임의 변경하지 않음.
