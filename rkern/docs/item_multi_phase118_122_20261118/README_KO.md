# RKern/L1J 아이템 누적 118~122차 — 영속 소모·출력 실패·재사용 시간 (2026-11-18)

**기준:** `RKern_ItemOnly_Cooking_Atomic_PostCommit_Phase117_FULL_SRC_20261118.zip`.

**수정 범위:** 생산 Java 8개. NPC, 네트워크 코어, 방송, CacheD 공통 구현 및 이전 117차 생산 코드는 그대로 유지.

## 연속 변경

- **118차 — 이동 물약 35종:** 초록/용기/엘븐/유그드라 경로의 효과→직접 삭제를 기존 `UseDurableConsume`(CacheD) 영속 차감→효과 경로로 전환. 직업·디케이 사용 불가 시 거래 제출 방지.
- **119차 — 보호·마나 물약 15종:** 수중 호흡/파란 물약/지혜/불투명 물약도 같은 영속 차감 경로로 전환. 기존 지속시간·계열별 직업 조건 보존.
- **120차 — 효과 출력 보호:** `MovementPotionEffects`, `ManaPotionEffects`, `ProtectivePotionEffects`에서 효과음, 속도·아이콘·안내·실명 알림의 전송 실패를 독립 분리. 실제 스킬/이동속도 변경 예외는 숨기지 않음. `showFloatingEyeToInvis()`의 출력 예외도 독립 처리.
- **121차 — 변신 직접 소모 정리:** 고정형 변신 18종, 레벨 변신 주문서 9종 및 훈련용 42655를 차감 확정 후 변신하도록 전환. 고정·훈련형의 83레벨 이상 제한과 훈련장 맵 조건은 차감 전에 검사. 무료 4100290 및 이름으로 고르는 일반 변신 주문서는 기존 경로 유지.
- **122차 — 영속 커밋 후 재사용 제한:** `ItemActionCompletion.finishCommittedConsumable`으로 아이템 딜레이·남은 스택의 사용시각 갱신을 DB 커밋 뒤로 이동. 롤백 시 딜레이 미적용. 마지막 1개가 전부 삭제된 아이템은 존재하지 않는 행의 사용시각 저장을 시도하지 않음.

## 검증

- 변경 생산 Java 7개(`ItemActionDispatcher` 제외)를 Java 21 typed stub 환경에서 **직접 컴파일**, 임의의 패킷 장애 조합 포함 **419,631개** 검증 조건 통과. 고정/레벨/훈련 변신 **165개** 모의 거래 조건 통과.
- Java 21 `JavacTask.parse()`로 **1,923개 전체 Java 구문 검사, 오류 0**.
- 117차 기존 검사 재실행: **113차 54,150 / 114차 232,459 / 115차 154 / 116차 174 / 117차 요리 1,284 + 패킷 64** 조건 통과. 해당 기존 생산 파일은 바이트 동일함.
- ID 보존 검사: 이동 물약 **35**, 마나/보호 물약 **15**, 고정 변신 **18**, 레벨 변신 **9**, 훈련 주문서 **1**.
- ZIP 모든 CRC 검사 및 117차 원본 대조: 변경 생산 Java **정확히 8개**, 이전 기타 항목 byte-identical.

## 한계와 추가 작업

- 위 테스트는 **모의 CacheD/인벤토리·패킷 스텁**이며 실제 DB 트랜잭션, Windows 운영, 인게임, 고접속 부하, 전체 의존성 타입 컴파일을 대체하지 않음.
- 버프/변신 상태 적용 자체에서 예외가 발생하거나, 아이템 사용 승인 후 비동기 커밋 대기 중 레벨·스킬 상태가 바뀌는 문제는 추가 통합 검증이 필요. 출력 오류만 분리했으며 실제 월드 상태 오류는 예외를 숨기지 않음.
- 이름 선택형 변신 주문서, 스킬북 학습, 회복 아이템, NPC 소환·펫·충전형 장비 등의 직접 소모 경로는 **남아 있음**. 단순히 공통 함수 호출로 치환하면 경제 상태와 월드 상태 순서가 바뀔 수 있어 별도 거래 설계가 필요.
- 카드 DB↔메모리 수량 충돌 자동 재동기화와 실 MySQL 장애·다중 세션 검증도 미완성. 현재 기존 격리 정책 유지.

## 검사 실행

`tests/run_typed.sh`에서 실제 최신 생산 Java를 typed-double 픽스처로 컴파일·실행할 수 있음. 이 픽스처는 프로덕션 의존성 전체 컴파일이 아니다. 테스트 결과는 `tests/typed_results.log` 및 `tests/prior_regressions/` 참조.
