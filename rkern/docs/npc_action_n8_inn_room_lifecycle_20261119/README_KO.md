# N8 여관 예약·만료 경쟁 검수 (2026-11-19)

- MJINNMapInfo 단위 CAS 예약으로 동시에 여러 사용자가 입장해도 설정 정원을 초과하지 않도록 수정. 같은 inn_id에 연결된 여러 helper는 로딩 시 같은 맵 설정/카운터를 공유한다.
- 임대료 차감 전에 복제 맵과 기존 예약 타이머 등록을 확보하며, 실패 또는 지급된 열쇠가 없으면 방을 해제한다. 기존 1~20개 수량과 부분 임대 정책은 유지한다.
- 만료/마지막 열쇠 제거 동시 발생에서 방 종료, 사용량 감소, 타이머 취소, 키 인덱스 제거를 한 번만 실행한다. 키 인덱스 삭제는 소유 room identity를 확인한다. 반환에 실패한 키를 대상으로 환급하거나 방을 제거하지 않는다.
- 복제 맵 풀의 비어 있음 확인-할당 분리 경쟁과 중복/오래된 종료 통지에 의한 ID 중복 반환을 방어한다. 여관 누락 설정에서도 메뉴 예외를 방지한다. 기존 스레드/큐 재사용; 신규 생산 클래스 없음.

검증: 실제 수정된 MJINNHelper/MJINNRoom/MJCopyMapObservable 및 이전 NPC 입력 핸들러를 typed stub과 실행. 4,692 기존 조합, 27,958 검사 조건 + 동시 예약/키 반환/만료 100회 및 1,000 맵 ID 소진/이전 콜백/맵 복제·타이머 실패 2,215 검사 조건 통과. 이전 test_talk_amount_inn.py의 room 스텁 API는 이전 구현 전용이며 이 폴더의 test_inn_lifecycle.py가 동일 조합을 대체 검증한다. 전체 Java 1,928개 구문 오류 0, 직전 javac 진단과 바이트 단위 동일(531 errors, 5 warnings).

미해결: DB receipt 기반 임대료/열쇠/환급 원자화, 지급 오류 후 환급, 기존 MJMapCleaner 비동기 실제 맵 정리 및 지연 이동 완료 이전 맵 ID 재사용 위험. 공용 복제 맵 풀의 변경은 해당 allocator의 일관성 보완이며 다른 콘텐츠 인게임 회귀/실제 DB/의존성 포함 완전 컴파일은 미검증. 실제 스케줄러 및 CIO 통합 동시성 검증은 별도 필요.
