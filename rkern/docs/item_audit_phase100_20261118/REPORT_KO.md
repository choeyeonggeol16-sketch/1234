# RKern 아이템 1~100차 누적 검수·결함 보완

검수 기준: `RKern_ItemOnly_Consolidation_Memory_Safety_Phase73_100_FULL_SRC_20261118.zip`.

## 범위와 기준

- 최신 전체 SRC의 생산 Java 1,922개를 대상으로 파일 목록·프로젝트 내부 import·Java 21 구문·주요 회귀검사 검수.
- 보관된 6차 원본과 65차, 72차, 100차 소스를 대조했으며, 최신판에 포함된 6~100차 테스트 자료를 재실행함. 1~5차의 **각 차수별 완전한 독립 원본**이 모두 준비된 것은 아니므로 100개의 개별 차수에 대한 100% 이력 재현으로 주장하지 않음.
- 변경 원칙: NPC/퀘스트·네트워크·방송·CacheD 공통 구현은 **한 글자도 수정하지 않음**. 1~100차 기존 변경은 보존.

## 검수로 확인하여 고친 문제 (생산 Java 5개)

1. `WarriorSkillBookItems.java`: `getTemplateByItem()`가 `null`을 반환할 때도 최종 `removeItem(item, 1)`에 도달해 책이 사라지던 경로를 막음. 스킬 누락 시 안내 후 반환. 기존 성공 경로는 동일.
2. `SkillBookLearning.java`: 대응 스킬 `name` 또는 아이템 이름이 null일 때 `matches`가 NPE를 던지지 않고 불일치 처리하도록 변경. 정상 문자열의 판정은 동일.
3. `L1CardAlchemy1.java`, `L1CardAlchemy2.java`, `L1CardAlchemy3.java`: 선택 슬롯에 유효 카드 ID가 있다는 검사만으로 차감하던 경로에서, 합성 직전 실제 계정 **보유 장수 >1** 조건을 다시 검사함. 동일 카드 ID의 중복 슬롯도 거절. 선택 UI(`NeigeCard`)의 여분 카드 조건과 일치. 처리 메서드 안에는 새 배열, 컬렉션, 람다 객체를 생성하지 않음.

신규 합성 카드 수량 검사: 총 81개 카드 ID의 `Consumer` 차감 필드와 조회용 primitive getter가 일대일 일치함을 자동 확인. 원본에 없는 수량·중복 거절 경계 151개 입력을 Java 21 타입 컴파일로 검증함. 기존 정상 합성 42,000건의 결과·차감·패킷·난수 호출도 A/B 재검증함.

## 재실행 결과

`docs/item_audit_phase100_20261118/run_tests.sh`로 현재 생산 파일을 기준으로 다음 주요 시험을 재실행할 수 있음.

- 카드 합성 정상 성공/실패 42,000건 원본 대비 실행 로그 일치.
- 카드 도감/화면 11,532건, 자동 카드 선택 30,000건 원본 일치.
- 부정 카드 ID 및 아데나 차감 거절 3,714+18건; 새 실제 보유 수량 부족/중복 선택 151건.
- 스킬북 정상 Java 21 실행 경로 20건, 잘못된 스킬 레벨·스킬 데이터 누락(실패 시 미소모) 검증.
- 스타터 521건, 선물상자 1,381건, 월드 객체 수명 33차, 아이템 레지스트리 259,200건, 물약 66차, 카드 67~72차 비교 및 NPC 퀘스트 38~65차 기수 테스트 재통과.
- Java 21 전체 구문 검사 1,922개 오류 0건. 명시적 내부 Java import 누락 0건 (패키지 와일드카드는 따로 처리).

**오래된 검사 두 개의 별도 결과:** 19차 스타터 회귀 스크립트는 31차 거래 API로 수정된 메서드를 옛 시그니처로 컴파일하려고 하여 실패함. 6차 검사는 현재 파일이 6차 스냅샷과 동일한 해시인지 검사해서 실패함. 이는 현재 코드가 해당 과거 스냅샷과 달라진 결과로, 현재 API를 대상으로 수행한 31차·현재 회귀검사 성공과 구분함. 오래된 테스트를 모두 통과했다고 주장하지 않음.

## 전체 서버 빌드·인게임 검증의 한계

전체 `javac` 빌드를 시도했지만 현재 전달본에 **Javolution, Trove, JCTools, Agrona 등 외부 JAR**가 포함되어 있지 않아 타입 컴파일이 완료되지 않음. 또한 Java 21 `java.lang.foreign` 사용으로 빌드에는 `--enable-preview` 설정이 필요함. 구문 검사와 추출 생산 메서드의 typed stub 컴파일은 통과했지만 **전체 서버 의존성 타입 컴파일 성공은 아님**.

실제 MySQL·CacheD 커밋 실패, ACK 손실, 서버 재시작, 5,000명 연결을 통한 인게임 테스트는 실행하지 않았음. 특히 **카드 합성의 아데나 차감, 계정 카드 저장, 결과 아이템 지급은 아직 단일 영속 트랜잭션이 아님**. 이번 수량 재검증은 마이너스 장수의 대표적 경로를 차단하지만 원자성 전체의 해결책이 아니며, 경쟁·DB 장애 시 안전성을 보증하지 않음.
