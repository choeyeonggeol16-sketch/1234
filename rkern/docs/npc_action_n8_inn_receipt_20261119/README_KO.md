# N8 여관 임대·반환 receipt 감사
- 임대료(300/600 아데나 × 수량)와 객체별 열쇠 발급을 기존 L1InventoryTransaction으로 묶었다. 용량 부족 시 부분 임대 대신 전체 거부. 복제 맵/타이머 확보 후 제출; 제출 전 실패 또는 현재 소유자에 전달된 확정 롤백 시 방 반환.
- DB 확정 callback에서 열쇠 ID 등록, 소유자 replay 후 성공 HTML 발송. 기존 180분 열쇠 만료와 240분 방 만료 및 호텔명 유지. 미확정 결과의 임의 환급/재제출 없음.
- 모든 유효한 열쇠 차감과 개당 10 아데나 환급 원자화. 비정상 스택/수량 거부. 확정 replay의 CWorld.removeObject로 기존 방 인덱스 해제.
- 열쇠 ID int[] 재사용, 중복/늦은 완료 callback 방어. 신규 클래스/스레드/큐 없음.
- 실제 helper/room/기존 입력 핸들러/allocator와 typed stub으로 4,692 조합 27,987 검사 및 예약·종료 경쟁 100회 포함 2,215 검사 통과. 이전 lifecycle harness는 새 receipt harness로 대체 검증. Java 1,928 구문 오류 0, javac 진단 직전과 동일(531 오류, 5 경고). 추가 XML 회귀는 시간 제한으로 미완료.
- 미해결: 실제 CacheD/MySQL, 재시작 시 방 메타데이터 복원, ACK 손실, 공용 비동기 맵 정리 및 지연 이동 완료 전 ID 재사용 위험. 세션 종료로 롤백 callback을 실행하지 못하면 기존 타이머로 방 만료. 만료 이후 확정된 열쇠에 대한 복구 정책 미구현. DB 스키마/공용 맵 정리 구조 변경 없음.
