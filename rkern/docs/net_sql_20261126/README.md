# Net DB 쿼리와 설치본 검증

입력은 앞서 배포한 비공개 `RKern_net_b59fa545_ready_to_import.zip`이다. 이 파일에서 시작해 기존 서버 소스 `fdaee3dc`를 수정했다. 새 설치본의 `Net.sql`은 빈 DB용이며, 운영 DB에는 별도의 마이그레이션을 제공한다. [설치와 기존 DB 업데이트](../../../database/README.md)

## 데이터 보존과 호환성

MariaDB 11.8.9에서 수정 전 설치본 복원, 업그레이드 두 차례, 새 빈 DB에 최종 Net.sql 임포트, 보관용 SQL의 별도 DB 복원을 검증했다. 기존 설치본 274개 테이블 중 247개는 새 설치본에서도 원본과 행 수가 같았다. 서비스가 종료된 20개 테이블과 통합 전 게시판 7개는 별도 보관용 SQL에 들어 있다. 총 99행 모두 복원됐다. 그중 10개 게시글은 새 통합 게시판에도 이관했고, 번호·작성자·날짜·제목·본문·앱센터 분류를 대조했다. 신규 설치본은 통합 게시판과 PSS 일일 사용량을 포함해 활성 스키마 249개 테이블이다. 새 ZIP에 넣은 아이템 스크립트는 이전 배포본과 바이트 단위로 동일하다.

기존 DB용 정리는 데이터가 남은 테이블을 보존한다. 실제 입력을 업그레이드하면 빈 테이블 15개를 제거하고 운영 테이블 2개를 추가해 261개가 된다. 통합 후 수정·삭제한 글은 게시판 마이그레이션을 다시 실행해도 되살아나지 않는다. 복구용 펫 기록과 LFC 설정 등은 설치본의 별도 보관 파일에서 조회할 수 있다.

보스 방 열쇠, 설치 가구, 마을 정산 테이블은 기존 Net에서 MyISAM이었다. 세 기능은 코드에서 InnoDB 트랜잭션을 요구한다. 기존 행을 보존하면서 InnoDB로 변환했고, 방 열쇠 삭제를 롤백하면 3개 매핑이 모두 복구되는 것을 확인했다. 도감·출석 등 11개 테이블의 SQL 이름을 실제 Net 소문자 표기로 맞췄다. Gludio 던전 전용 스폰 데이터는 입력본에 없어서 이 던전의 동작은 검증 범위 밖이다.

## 쿼리 결과

MariaDB에서 테이블당 합성 데이터 40,000행을 넣고 수정 전후 쿼리 결과와 실행 시 읽은 행을 비교했다. 아래는 SQL이 실제로 검사한 행 수다. 한도는 예시로 IP당 5계정을 사용했다.

| 쿼리 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| TAM 캐릭터·예약 ID별 가장 오래된 예약 1개 | 39,994 | 1 |
| 존재하지 않는 TAM 소유자의 예약 조회 | 40,000 | 0 |
| 방 열쇠 ID로 매핑 3건 삭제 | 40,000 | 3 |
| 같은 IP에 계정 20개가 있을 때 생성 한도 확인 | 40,000 | 5 |
| 안 읽은 편지 8,000건의 존재 확인 | 8,000 | 1 |

조회 인덱스 4개는 TAM 캐릭터·예약 식별자별 FIFO, 계정 IP, 방 열쇠 ID를 다룬다. 우편은 기존 인덱스를 이용한다. 18개 조건에서 결과가 일치했고, 다른 이름으로 같은 인덱스가 있는 경우에도 중복 생성되지 않았다. [실제 실행 계획과 검사한 행](query-work.tsv)

창고와 소지품에 이미 있는 두 스택 사이에서 일부 수량을 이동할 때 소유자·아이템 종류·기존 수량 조건을 UPDATE 또는 DELETE에 넣었다. 해당 행을 처리하는 SQL은 4회에서 2회로 줄었다. 여섯 창고 유형의 변경 시도 54회와 수량 불일치, 동시 입고, 중복 ID 롤백을 검사했다. 인벤토리 로딩 시 보스 열쇠는 이미 사용 중인 DB 연결에서 한꺼번에 읽는다. 열쇠 10개에 대한 연결 대여는 11회에서 1회로 줄었고 키 매핑은 동일했다. [창고와 열쇠 회귀 테스트](../../tests/storage/WarehouseMoveSqlRegression.java)

GM의 동일 IP 계정 조회는 65계정에서 SQL 호출이 66회에서 3회로 줄었다. 빈 계정을 포함해 출력 205줄이 이전과 동일했다. 이번 측정은 SQL 작업량과 기능 보존을 검증했다. 운영 동접 기준 p99와 MySQL 5.7 실서버 성능은 별도로 측정해야 한다.
