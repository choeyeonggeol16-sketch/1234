# 스탯 저장과 초기화 직후 AC 갱신

기준 커밋은 `5087730a`다. 레벨 포인트 투자, 초기화 촛불 차감, 초기화 확정은 각각 캐릭터의 기존 CacheD 처리 순서 안에서 InnoDB 트랜잭션으로 기록한다. 같은 커밋에 영수증도 기록한다. 서버는 DB 커밋이 확인된 뒤 캐릭터 상태에 반영하고, 해당 세션에 결과를 보낸다. 기존 Net DB의 테이블을 사용한다. [저장 코드](../../src/l1j/server/server/storage/mysql/CharacterStatReceipt.java)

| 상황 | 처리와 검증 |
| --- | --- |
| 일반 스탯 투자 | 영구 능력치와 사용한 포인트를 같이 기록한다. 아직 자동 저장 전인 레벨에서 첫 포인트를 쓰면 DB의 기존 성장 이력을 확인하고 필요한 레벨·HP·MP 성장분을 함께 기록한다. DEX 변경 시 캐릭터 선택창이 읽는 AC도 갱신한다. 연속 투자 명령에서는 한 점이 확정된 뒤 다음 점을 처리한다. [투자와 연속 투자 시험](CreatureStatWireRegression.java) |
| 촛불 사용 | 직접 사용과 NPC를 통한 사용 모두 촛불 한 개 차감과 초기화 진행 표시를 한 트랜잭션에 넣었다. DB 커밋 직후 캐릭터 처리를 보류한 상태에서 두 값이 함께 저장됐는지 확인했다. 중복 사용과 DB 오류가 발생한 경우에도 수량을 확인했다. 직접 사용은 레벨 51 및 안전지역, NPC는 레벨 55 조건을 유지한다. [촛불 코드](../../src/l1j/server/server/model/item/function/StatReset.java) · [검증](../../tests/stats/StatResetCandleRegression.java) |
| 초기화 화면과 확정 | 기본 스탯을 두 번 제출해도 새 성장 이력을 뽑지 않는다. 캐릭터 생성 기준에 맞춰 기본 배분은 항목당 20·합계 75 이하로 제한한다. 기존 캐릭터 행을 일괄 수정하지 않는다. 최종 선택과 성장 이력, HP·MP, AC와 초기화 완료 표시를 함께 저장한다. DB 거절 뒤 같은 선택을 다시 확정해도 마지막 포인트는 한 번만 소모된다. [초기화 핸들러](../../src/l1j/server/server/model/network/core/cs/packet/CS_ReturnStatus.java) |
| 초기화 후 화면 | 미리보기 AC가 10으로 고정돼 있던 경로를 바꿨다. 일반·엘릭서 두 경로에서 완료 시 레벨·DEX와 현재 보정을 기준으로 AC를 계산하고, 초기화 창 종료 및 캐릭터 상태·방어력·스탯 상세 정보를 전송한다. 운영자 캐릭터 정보 조회가 Net DB에 없는 HP·MP 열을 읽던 문제와 직업 표기도 수정했다. [실제 송신·DB 대조](../../tests/stats/StatResetRegression.java) |
| 저장 중 장애 | 별도 JVM에서 실제 JDBC 커밋 직후, 캐릭터에 반영되기 전에 프로세스를 강제 종료했다. 일반 투자와 초기화 모두 새 세션에서 결과를 복원했고, 같은 영수증을 재시도해도 변화는 한 번이었다. 또한 DB가 갱신을 거부할 때, 이전 저장본이 늦게 도착할 때, 아이템 거래가 진행 중일 때도 검사했다. [강제 종료·롤백 시험](../../tests/stats/CharacterStatDurabilityRegression.java) |

Java 21 운영 소스 1,697개를 컴파일했다. 임시 MariaDB에서 실제 캐릭터와 아이템 테이블을 사용했다. 초기화 대상 행을 잠근 상태에서는 성공 패킷이 도착하지 않았다. 잠금을 푼 뒤 같은 접속에서 받은 암호화 TCP 패킷을 복호화해 AC·ER, 6개 스탯, HP·MP를 확인했다. 일반 경로의 레벨 89·90 캐릭터와 엘릭서 배분 캐릭터 모두 DB 저장값 및 새 로그인 로더의 계산값과 일치했다. 게임 클라이언트의 화면 렌더링과 운영 동접 부하는 이번 시험 범위 밖이다.
