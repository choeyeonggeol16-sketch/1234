PSS 2019 도보 탐색 V1 — 클라이언트 DLL + 전체 소스

적용
1. 게임 클라이언트를 완전히 종료합니다.
2. 게임 폴더의 기존 Pss2019.dll을 다른 곳에 백업합니다.
3. 이 ZIP의 Pss2019.dll을 게임 폴더에 복사해 교체합니다.
4. 기존 Pss2019.ini는 그대로 둡니다. PSS_Client_Apply.cmd를 다시 실행할 필요 없습니다.
5. 접속 후 기존 Play Supporter 아이템(900000901)으로 설정창을 열고 시작합니다.

변경 내용
- 몬스터와 주울 아이템이 없으면 짧은 목적지를 골라 걸어서 탐색합니다.
- 몬스터·아이템 처리는 기존 PSS가 매번 먼저 판단합니다.
- 목적지에 도착하면 계속 탐색하고, 이동 진전이 없으면 다른 방향을 시도합니다.
- 최근 지나온 위치와 막혔던 목적지를 고정 크기로 기억합니다.
- 일반 무타겟 대기에서 도보 탐색이 텔레포트 대체 분기보다 먼저 실행됩니다.
  텔레포트 허용 맵에서도 이 도보 탐색을 우선 사용합니다.
- 고정 사냥, 유효한 기존 경로, 이미 대기 중인 탈출·귀환 동작은 기존 처리를 사용합니다.
- 중지, 맵 변경, 월드 이탈 시 배회 상태와 소유한 이동 객체를 정리합니다.

테스트
컴파일과 모의 실행 검증을 완료했습니다. 실제 19.02.15.1002 게임에서의 이동·충돌·카메라
동작은 아직 확인하지 않았습니다. validation 폴더에 검증 범위와 로그를 넣었습니다.
처음에는 빈 공간에서 배회 → 몹 발견 후 공격 → 중지 → 텔레포트 금지 지역 순서로 확인합니다.

서버 소스나 DB를 추가로 수정하는 패키지가 아닙니다. 기존 아이템/클라이언트 자동 로딩
연결을 사용하고, 기존 PSS 전투 엔진과 네이티브 이동 함수를 재사용합니다.

끄기 / 되돌리기
게임 종료 후 백업한 Pss2019.dll을 돌려놓으면 됩니다.
또는 기존 Pss2019.ini 끝에 아래 항목을 추가하고 게임을 다시 실행합니다.

[PssRoaming]
Enabled=0

확인 로그
기존 PSS2019_trace.txt에 아래 두 줄이 나오면 배회 연결을 준비하고 붙인 상태입니다.
PSS idle walking ready: native Battle idle branch only
PSS idle walking attached; new targets retain native priority
실제 이동 시에는 PSS idle walking map=... position=... goal=... 로그가 최대 10초에 한 번 나옵니다.
ready/attached 로그만으로 실제 게임 이동 성공이 증명되는 것은 아닙니다.

source 폴더의 build.cmd는 MinGW i686-w64-mingw32-gcc로 DLL을 빌드합니다.
tests 폴더는 개발 검증용 소스이며 게임 폴더에 넣거나 실행할 필요 없습니다.
