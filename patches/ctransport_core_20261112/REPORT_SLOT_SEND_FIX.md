# CUserSocket 두 슬롯·송신 검사 수정 — 2026-11-14

요청한 1·2번만 수정했다. 원본 내부 필드 배치 변경과 접속 IP 제한 모드는 적용하지 않았다. IOCP128, 외부 ABI10/67exports, codec, 독립 PSS와 게임·DB 정책을 유지한다.

## 변경

- CUserSocket의 가상함수는 원본처럼 26개다. 슬롯 24는 원본 `0xa01790`처럼 기존 `+0x4f0`의 포인터 값을 읽는다. 원본 함수 이름·대상 객체의 전체 의미는 미확정이므로 `Slot24OriginalPointer`라는 어댑터 이름을 쓴다. L1의 해당 L2 예약 영역은 0이므로 정상적으로 null을 반환하며 Java 객체 주소를 만들어 넣지 않는다.
- 슬롯 25는 기존 실제 소켓 번호 `+0x4e8`를 반환하는 `SocketNumber()`에 연결했다. 기존 연결 색인·번호 부여·조회 기능을 다시 만들지 않았다.
- 슬롯 15에 원본의 `int margin` 인자를 반영했다. 슬롯 14는 연결 유효성과 현재 송신량을, 슬롯 15는 추가 여유량을 검사한다. 음수와 한도 초과는 거절하며 원본의 signed 덧셈 overflow는 재현하지 않는다.
- 송신량은 기존 FIFO 잔여량+예약량으로 계산한다. 같은 소켓 lock 아래 일반/공유 SEND 입구에서 가상 검사 함수를 사용하고, 직렬 실행자가 암호화 전에 다시 검사한다. 원래의 한도 초과 거절과 종료 처리를 사용한다.
- GracefulClose 전에 승인한 송신은 계속 drain할 수 있다. 새 송신을 막는 조건과 이미 승인한 요청의 실행 조건을 유지했다. 기존 Java SafeSend·512KiB 문장 margin 경로는 변경하지 않았다.

## 검증

- 원본 테이블을 첫 비실행 포인터까지 직접 읽어 CUserSocket 26/CSocket 24/Server 16 경계를 확인한다. 예전의 24개 고정 추출을 제거했다.
- 실제 가상 슬롯 호출 검사: 24의 null/기존 포인터 값 반환, 25의 실제 번호, 15의 int 전달·음수·INT_MAX·1.5MiB+512KiB 경계, 2MiB 경계, FIFO+예약량 합산.
- Linux ASan/UBSan: 객체 ABI·SEND/codec/FIFO 연결·참조 회수 및 전체 native 회귀 검사 통과.
- Linux TSan: 전체 native 동시성 회귀 검사 통과.
- Windows MSVC 빌드, 실제 슬롯 호출 및 DLL/Java FFM 회귀 결과와 배포 DLL hash는 함께 제공하는 WINDOWS_VERIFICATION.json에 기록한다. 출하 DLL과 Java SHA pin은 해당 성공 실행에서 생성한 파일을 사용한다.

검증은 위 범위의 수정과 회귀 확인이다. 원본 모든 함수·분기의 동일성, 슬롯 24 대상의 L2 게임 동작, 원본 대비 성능 우열을 주장하지 않는다. 2026-11-14 최종 차이 보고서의 3·4번은 이번 수정 범위 밖이며 기존 상태를 유지한다.
