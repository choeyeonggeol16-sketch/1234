# 49027 클릭 대상 충돌 확인 V6 — V5 서버 유지

사용자가 보낸 V5 DLL 로그에는 `native click did not select the verified next tile`과 중단 기록이 있습니다. V5 코드는 입력 승인 확인 실패와 목표 불일치를 같은 문구로 출력하므로, 기존 로그만으로 두 원인을 구분할 수는 없습니다. V6는 클릭 직전에 승인을 확인하고, 원본 클라이언트에서 재현한 대상 선택 충돌을 사전에 피합니다. Windows 실게임에서 이번 중단이 해소됐는지는 아직 검증하지 못했습니다.

## 적용

현재 `step-v5 sprite-cadence` 서버를 사용 중이면 **서버 재빌드 없이 DLL만 교체**합니다.

1. 게임을 완전히 종료하고 기존 dinput.dll을 백업합니다.
2. DLL ZIP의 `dinput.dll` 또는 전체 소스 ZIP의 `client-ready/dinput.dll`을 Mega.bin 옆에 넣습니다.
3. 게임을 다시 실행하고 캐릭터 접속 후 49027로 시작합니다. F9 보정은 필요 없습니다.

새 `client_io.log`에서 `native-tile-input-v6-20261111`을 확인합니다. 각 줄에 `tick=` 밀리초와 PID가 함께 찍힙니다. 전체 소스 ZIP의 서버 Java는 V5와 같으며, V4 이하 서버에서 처음 올리는 경우 V5 안내대로 Java 3개를 함께 적용해 서버를 재빌드해야 합니다. 서버 실행 JAR·외부 의존성·Mega.bin은 배포하지 않습니다.

## 바뀐 동작

- 기존에는 항상 한 타일의 같은 지점을 눌렀습니다. V6는 **서버가 승인한 그 타일 안의 10개 후보**를 원본 좌표 변환으로 각각 확인하고, 마우스 이동 메시지로 갱신된 대상과 아이템 이름 영역을 검사해 빈 지점에서만 누릅니다. 다른 타일이나 방향을 대신 누르지 않습니다.
- 아이템 이름 영역은 원본의 분류·이름 영역 계산 함수를 사용합니다. 원본 스캐너와 같이 이름 영역 계산 동안만 hover 컨텍스트를 해당 물체로 설정하고 즉시 복원합니다. 이동 목표·캐릭터 위치·카메라는 이 사전 검사에서 수정하지 않습니다.
- 모든 지점이 가려져 있거나 클라이언트가 특수 입력 상태이면 승인 유효기간 안에서 기다립니다. 만료·취소된 승인으로 버튼을 누르지 않습니다. 끝까지 입력할 수 없으면 기존 V5 서버의 제한된 재시도와 종료 정책이 적용됩니다.
- 입력 승인 확인을 DOWN 메시지 **직전**으로 옮겼습니다. V5는 DOWN 뒤에 확인해서 유효기간이 지난 경우도 목표 불일치로 보고했습니다. 실제 목표가 다르면 별도의 이유와 기대 목표·실제 목표·플레이어·hover 상태를 기록한 뒤 중단합니다. 실패 기록에는 정상 입력 로그의 128회 제한을 적용하지 않습니다.
- V5 서버의 걷기 간격·방향·출발 좌표 검사·한 칸 승인은 유지합니다. DLL에서 C_MoveChar 패킷을 직접 생성하지 않습니다.

지원하는 Mega.bin SHA-256: `09804d9579446fb9a630c39c1f1b2d08083718261d2f3e57b2e36f80ba865490`. 실행 파일과 관련 네이티브 함수의 코드 서명이 맞아야 시작합니다.

## 검증 범위

- 원본 x86 좌표/목표 192개·입력 대기 7개 검사를 유지하고, 10개 후보 × 8방향 × 8모드 × 3카메라의 **1,920개 좌표 왕복**과 각 ±2px 경계를 검사했습니다.
- 원본 DOWN 처리 함수 `0x472070`과 목표 선택 함수 `0x471A70`을 실행해 **기존 중심점의 아이템 이름 충돌 8개**를 재현하고, 같은 타일 안의 다른 후보를 사용한 8개에서 목표가 유지되는 것을 확인했습니다. 물체 분류·렌더링 영역·최종 이동 실행은 통제된 테스트 대체 함수입니다. 실제 Windows 메시지 전달·그래픽·네트워크를 실행한 검사가 아닙니다.
- 후보와 이름 영역 경계, 기존 상태 코어 10,000회·만료/취소 검사를 ASan/UBSan으로 실행했습니다. Windows PE32 DLL/호스트 EXE를 교차 빌드하고 DirectInput export/ordinal 1~7, 시스템 의존성과 버전 표시를 확인했습니다. Windows 호스트 EXE와 실제 게임은 이 환경에서 실행하지 않았습니다.
- 이 재현은 기존 로그에서 누락된 실패 원인을 전부 확정하는 검사가 아닙니다. 모든 후보가 물체에 가려진 상태, UI가 입력을 소비하는 상태, 실제 서버 재동기화의 다른 원인에서는 종료가 남을 수 있습니다. V6 로그는 승인 만료·포커스·목표 변경을 구분합니다.

재현: 원본 Mega.bin에서 기존 `tools/unpack_for_native_tests.py`로 분석 이미지를 만든 다음 `tests/mega_click_replay.py --client /path/to/Mega.bin --image /path/to/stage1-image.bin`을 실행합니다. Python 의존성은 `tests/requirements-native.txt`입니다. 사용자 실행 파일과 분석 메모리는 저장소/ZIP에 넣지 않습니다.
