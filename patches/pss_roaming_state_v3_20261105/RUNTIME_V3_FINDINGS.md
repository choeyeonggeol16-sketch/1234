# PSS 무대상 대기 분석 — V3 런타임 자료

입력: `PSS_Roaming_Code_20261105_081940_880.zip`. 실행 코드 75페이지와 고정 데이터 13페이지, 보고서를 분석했다. 이 문서는 분석 결과만 담으며 사용자 실행 메모리 원본은 공개하지 않는다.

## 확인한 상태

| 항목 | 수집 결과 | 해석 범위 |
| --- | --- | --- |
| 월드/실행 | `phase=3`, `running=1` | PSS 실행 플래그가 켜져 있음 |
| 현재 작업 | `Battle` | 전투 작업을 유지하는 상태 |
| 타겟 | `-1` | 캡처 순간 선택된 몬스터 없음 |
| 경로 설정 | 그룹 `+0x20`의 `+0x0D=0` | 경로 준비 분기의 조건이 꺼져 있음 |
| 고정 위치 설정 | 같은 그룹의 `+0x0E=0` | 현재 캐릭터 위치를 기준으로 탐색 |
| 경로 인덱스 | `-1` | 활성 경로 지점이 잡히지 않은 상태 |

기준 좌표 저장소가 `(0,0)`인 것은 오류의 근거가 아니다. `0x00686380`은 고정 위치 설정이 꺼져 있으면 저장 좌표 대신 현재 캐릭터 좌표를 가져온다. 현재 자료에서 설정이 0이므로 좌표를 억지로 덮어쓰는 수정은 근거가 없다.

## 실제로 확인한 노드와 코드

팩토리 `0x0067D3E0`의 문자열 비교 → 팩토리 → 생성자를 따라 이름을 확인했다. 생성자 주소만 보고 역할을 추측하지 않았다.

| 노드 | 생성자 | 업데이트 | 확인한 처리 |
| --- | --- | --- | --- |
| `BotSearchMonsterNode` | `0x00685780` | `0x00686560` | 대상이 없으면 `0x006867A0`으로 후보를 찾으며, 실패 시 `0x00686790`에서 시간 함수를 호출하고 결과 0으로 돌아감. 이 실패 분기 안에는 이동 호출이 없음 |
| `BotWalkTargetNode` | `0x0068D870` | `0x0068DA50` | `0x0068DAB8`에서 타겟이 -1이면 이동 처리 전에 결과 0으로 돌아감 |
| `BotPlayPath` | `0x0067EE00` | `0x0067F000` | 컨텍스트 `+0xCC`의 경로 객체를 사용하며, 객체가 없거나 준비되지 않았으면 실패 경로로 돌아감. 자동 무작위 배회로 볼 근거는 없음 |

몬스터 탐색의 기준 위치/범위도 코드에 있다. 고정 위치가 꺼져 있으면 현재 캐릭터 위치를 사용하며, `0x00686815`에서 검색 범위 값 10을 선택한다. 이 값은 후보 탐색 함수에 전달되는 값이며 화면의 정확한 가시 거리와 같다고 단정하지 않는다.

`BotSearchItemNode`는 별도 생성자 `0x006845F0`이다. 몬스터 탐색 노드와 혼동하지 않는다. 또한 `0x00679B20`은 `BotMonsterAttackCheckNode` 생성자로 확인됐으므로 이를 경로 이동 노드로 취급하지 않는다.

## 행동의 연결이 필요한 이유

클라이언트는 `0x0067E040`에서 **`playSupport.json`**을 데이터 로더로 읽은 뒤 `Battle`, `Return`, `Escape`라는 행동을 구성한다. `0x0067E300`은 **`Tag`, `Type`, `Children`**을 읽으며, 팩토리는 **`Sequence`, `Selector`, `Inverter`**와 위의 PSS 노드들을 지원한다.

현재 Battle 루트의 함수표는 `0x011B4094`, 업데이트는 `0x007A7350`이다. 이 함수는 자식의 결과가 0이면 즉시 0으로, 1이면 즉시 1로 돌아가고, 2이면 다음 자식으로 넘어간다. 모든 자식이 끝나면 2를 반환하는 **Sequence 방식**이다. 따라서 자식의 순서와 중첩된 Selector 등의 구성이 탐색 실패 후의 동작을 결정한다.

지금까지 확인한 사실은 **몬스터 탐색 실패 분기 자체에는 배회가 없고, 타겟 추적과 경로 재생은 별도 조건이 필요한 작업**이라는 점이다. 이는 몹이 없으면 멈추고 새 몹이 들어오면 공격을 재개한다는 관찰과 맞는다. 다만 현재 자료에는 자식 목록과 JSON 본문이 없으므로, 전체 Battle 트리에 대체 이동 동작이 없는지, 다른 조건에서 건너뛰는지는 아직 확정할 수 없다. 등록된 노드 이름에서 명시적인 무작위 배회 노드를 찾지는 못했지만, 그것만으로 모든 배회 기능의 부재를 단정하지 않는다.

## 다음 입력과 변경 범위

필요한 다음 자료는 클라이언트가 실제로 사용하는 **`playSupport.json` 본문**이다. 현재 작업 공간과 첨부 ZIP 18개의 파일 목록에는 그 파일이 없다. 게임 폴더에서 보이지 않는 경우 클라이언트 데이터 묶음에 포함돼 있을 수 있다. 원본을 확인하지 않고 새 JSON으로 덮어쓰거나 후속 클라이언트 버전의 파일로 바꾸지 않는다.

해당 파일을 확보하면 `Battle`의 탐색 실패 뒤 이동/대기/텔레포트 연결을 대조할 수 있다. 기존 노드의 조합으로 해결할 수 있는지, 별도의 배회 구현이 필요한지는 그 결과로 결정한다. **JSON만 고치면 해결된다는 보장은 아직 없다.** 서버의 패킷 번호나 시험 모드 값을 바꾸는 수정 역시 현재 근거가 없다.

이번 단계에서 게임 동작, DLL, 아이템, 서버 소스는 변경하지 않았다. 상태와 함수의 분기를 정적 분석한 결과이며 실제 명령 실행 이력을 기록한 것은 아니다.
