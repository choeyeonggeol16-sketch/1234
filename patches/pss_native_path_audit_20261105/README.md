# 기존 PSS 경로 기능의 입력 상태 확인

현재 설정창에 이동 경로/사냥 위치 항목이 보이지 않는다는 사용자 확인을 반영한 진단이다. **경로 설정과 입력 데이터가 실제로 준비돼 있는지** 읽는다. PSS가 원래 제공하는 경로 재생 기능을 살릴 수 있는지 판단하기 위한 자료다. 새 배회나 기존 기능 복구 패치가 아니다.

1. 게임에 들어가 PSS를 시작한다.
2. 이 ZIP을 별도 폴더에 풀고 **`PSS_Native_Path_Check.cmd`**를 더블클릭한다.
3. 바탕화면의 새 **`PSS_Native_Path_날짜시간.zip`**을 보낸다.

PID 입력은 없다. 클라이언트/DLL/서버 교체나 Apply 재실행은 필요 없다. 게임과 같은 권한으로 실행한다.

보고서에는 현재 설정/기본 설정 중 어느 쪽을 쓰는지, 경로 사용 플래그, 저장된 선택 인덱스, 네이티브 검사에 사용하는 상한의 원시값, 선택 항목 존재 여부, 실행 경로 객체 존재 여부와 실행 지점 인덱스가 들어간다. **저장된 선택 인덱스와 실행 지점 인덱스는 다른 값이다.** 원시 상한을 확인 없이 경로 개수라고 표시하지 않는다. `SelectedEntryChecked=false`이면 선택 항목 유무를 판정하지 않은 것이다. 선택 항목의 본문·이름·좌표도 복사하지 않는다.

추가 코드는 확인된 경로 객체 생성자 `0x0075EAA0` 및 경로 재생 함수들이 있는 두 페이지뿐이다. 생성자에 참조된 고정 함수표 후보도 최대 네 페이지 읽으며, 후보의 실제 의미는 오프라인 디스어셈블로 검증한다. 사용자 메모리 전체, 계정·비밀번호·채팅·인벤토리는 수집하지 않는다. 원본 JSON이나 사용자 설정 파일도 복사하지 않는다.

읽기 전용이다. 게임 함수 호출, 패킷 전송, 게임 파일·메모리 변경을 하지 않는다. 정확히 확인한 클라이언트 해시 두 개 및 월드 상태·PSS 코드 서명을 확인하고, 최대 3개 프로세스에서 코드/고정 데이터 최대 24KiB씩만 저장한다. 실행 상태는 동시에 바뀔 수 있는 스냅샷이다.

C# 컴파일·C#/PowerShell 구문 검사와 경로 활성화/조기 반환 분기의 실제 명령 8개 대조를 통과했다. 이 새 도구의 실제 Windows 게임 수집은 아직 확인하지 않았다.
