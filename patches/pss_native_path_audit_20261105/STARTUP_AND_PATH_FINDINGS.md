# 현재 시험본의 시작 처리와 기존 경로 활성화 조건

## 확인된 사실

현재 `Pss2019.dll`의 `code_ready()`는 `0x00669C20`의 코드가 `C3 CC CC CC CC`인지 확인한 후 패치한다. 이 지점은 바로 반환하는 코드다. DLL의 `restored_start()`가 그 자리에 들어가 리셋 `0x006688D0` → Battle 구성 `0x00669840` → 다음 작업 시작 `0x00669B20`을 호출하고 실행 플래그를 켠다. 이는 현재 DLL 소스와 사용자의 패치 성공 로그로 확인된다.

따라서 현재 동작을 **공식 PSS의 전체 시작/설정 초기화가 그대로 검증된 상태**로 취급할 수 없다. 이 사실만으로 시험본 시작 처리에 어떤 호출이 누락됐다고 확정할 수도 없다. 첨부된 린빈의 시작 코드가 왜 바로 반환하는지, 다른 버전의 정식 시작 순서가 무엇인지는 아직 확인되지 않았다.

Battle 시작의 `0x006590D0`은 설정 그룹 `+0x20`을 읽는다. 고정 위치 분기 다음, `0x0065915B`에서 그룹 `+0x0D`가 0이면 경로 준비를 건너뛴다. 1인 경우에는 그룹 `+0x08`의 인덱스와 `+0x14`의 상한을 검사하고, `+0x10`에서 선택 항목을 가져와 `0x00657DA0`을 거쳐 경로 객체를 만든다. 실제 객체 생성자는 `0x0075EAA0`이다.

`BotPlayPath`의 `0x0067F000`은 실행 컨텍스트 `+0xCC`의 경로 객체를 사용한다. 객체가 없거나 준비되지 않았으면 경로 재생을 진행하지 않는다. 이 경로에는 기존 걷기/경로 처리 기능이 있으며, 그것이 무작위 목적지 선택까지 제공하는지는 별도 문제다.

## 기존 자료의 정확한 한계

무대상 V3 자료에서는 경로 사용 플래그가 0이고 실행 지점 인덱스가 -1이었다. **이 -1은 저장된 경로 선택 인덱스가 아니다.** 기존 보고서는 저장된 목록/선택 항목을 읽지 않았으므로, 사용할 경로 데이터가 전혀 없다고 확정해서는 안 된다.

행동 목록 자료는 현재 Battle 60노드의 연결을 보여 준다. 무대상 대체 동작은 `MoveNextSelector`의 `Sequence(BotPlayPath, BotReturnNode)` 다음 `BotTeleportNode`다. 이 구성에 독립적인 무작위 배회 노드가 나타나지 않은 사실과 린빈 전체의 기능 부재는 구분한다.

사용자는 현재 설정창에 이동 경로/사냥 위치·범위 항목이 보이지 않는다고 확인했다. 따라서 화면에서 해당 옵션을 켜면 된다고 안내할 근거가 없다. 먼저 기존 설정의 경로 입력 상태와 시작 때 그 값이 사용되는지를 확인해야 한다. 이 단계에서 플래그를 임의로 1로 바꾸거나 경로 객체를 새로 넣는 변경은 하지 않았다.

이번 도구는 그동안 읽지 않은 저장된 선택/상한/선택 항목 존재 여부와 실행 경로 객체를 대조하고, 기존 경로 생성/재생 함수 두 페이지를 읽는다. 이 결과로 설정은 있는데 활성화만 빠진 경우와 경로 데이터 자체가 준비되지 않은 경우를 구분한다. 필요한 기능을 새로 만들어야 한다는 결론도 현재는 유보한다.
