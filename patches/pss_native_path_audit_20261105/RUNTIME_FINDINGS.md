# 기존 경로 기능의 런타임 확인 결과

입력은 `PSS_Native_Path_20261105_092428_288.zip`이다. 보고서와 경로 처리 코드 두 페이지를 확인했다. 사용자 원본 메모리/보고서는 공개 배포하지 않는다.

## 확인된 실행 상태

| 항목 | 값 | 해석 |
| --- | --- | --- |
| PSS 실행 | `true` | 실행 중 |
| 경로 설정 출처 | `default configuration fallback` | 현재 설정의 경로 그룹 대신 기본 그룹을 사용 |
| 경로 사용 플래그 | `0` | 경로 객체를 준비하는 분기 조건이 꺼져 있음 |
| 고정 위치 플래그 | `0` | 저장된 고정 위치를 사용하지 않음 |
| 실행 경로 객체 | `false` | 현재 경로 재생에 전달할 객체가 없음 |
| 실행 지점 인덱스 | `-1` | 재생 중인 경로 지점이 없는 상태 |
| 저장된 선택 인덱스 / 원시 상한 | `0 / 0` | 의미를 확정하지 않은 상태로 원시값만 기록 |
| 선택 항목 실제 검사 | `false` | 선택 항목 존재 여부는 판정하지 않음 |

마지막 두 항목만으로 저장된 경로 목록이 완전히 비었다고 단정하지 않는다. `SelectedEntryPresent=false`는 이번 경우 `SelectedEntryChecked=false`이므로 미확인 값이다. **확정된 것은 기본 설정을 사용하며 경로 실행이 꺼져 있고, 실행 경로 객체가 없다는 사실**이다.

## 코드에서 추가로 확인한 내용

- `0x0075EAA0`은 경로 객체 생성 시 전달받은 메시지를 내부 데이터로 복사한다. 내부 메시지 초기화는 `0x0077DD60`, 입력 복사는 `0x00782500` 호출로 이어진다.
- `0x0075EDB0`은 저장된 배열에서 인덱스를 증가시키며 다음 항목을 꺼낸다. 끝이면 -1로 되돌리고 null을 반환한다.
- `0x0075F590`은 이 경로 객체의 항목 수 필드가 0이 아닌지 검사한다. **이 객체의 필드 의미를 다른 설정 객체의 같은 오프셋에 그대로 적용하지 않는다.**
- `0x0075F040`은 경로 항목의 유형 값에 따라 다섯 처리로 분기한다. 준비된 동작 목록을 재생하는 구조다. 이것만으로 주변 사냥 목적지를 스스로 생성하는 자유 배회라고 볼 근거는 없다.
- 그중 `0x0075F5A0`은 목적 좌표와 현재 지도를 검사하고, 거리가 허용 범위 안이면 기존 좌표 이동 객체를 만들어 `0x0064FE70`을 호출한다. 생성에는 `0x0075E9D0`이 사용된다. **기존 클라이언트의 좌표 기반 도보 이동 진입점이 있다는 사실은 확인됐다.** DLL 외부 호출의 전체 수명/중단 동작까지 검증한 것은 아니다.

## 기존 관찰과의 연결

앞서 읽은 현재 Battle 60개 노드의 무대상 대체 동작은 `Sequence(BotPlayPath, BotReturnNode)` 다음 텔레포트였다. 현재는 경로 객체가 없으므로 경로 재생으로 걷기를 시작할 입력이 준비되지 않았다. 몬스터를 발견하면 타겟 좌표를 사용하는 별도 추적 노드는 동작할 수 있으므로, 타겟 발견 후에만 걷는다는 관찰과 모순되지 않는다.

이로써 **기존 경로 재생이 현재 동작하지 않는 입력 조건**은 확인했다. 다음 문제는 이 경로 설정/입력이 원래 어디에서 준비되는지다. 현재 UI에 해당 항목이 보이지 않는다는 사용자 확인도 있다.

현재 DLL은 바로 반환하던 시작 지점을 대체해 Battle을 시작하는 시험 구조지만, 그 사실만으로 DLL이 필요한 초기화를 누락했다고 확정하지 않는다. 제공된 버전이 지원하는 모드/UI/데이터와 시작 연결을 더 대조해야 한다. 반대로 NC의 완전한 자유 배회 기능이 이 버전에 들어 있다고도 현재 자료만으로 보장할 수 없다.

이번 단계에서는 기존 클라이언트/DLL/서버 동작을 변경하지 않았다. 경로 플래그만 강제로 켜거나, 검증되지 않은 입력을 넣는 수정도 하지 않았다.
