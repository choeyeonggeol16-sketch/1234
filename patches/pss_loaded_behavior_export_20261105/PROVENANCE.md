# 사용한 구조의 근거

사용자 V3 자료의 현재 Battle 타입은 `0x01184C78`이다. 시작/업데이트에서 사용하는 Battle 행동 루트는 객체 `+0x38`에 있다. 실제 루트의 함수표는 `0x011B4094`였다.

- `0x0067BFD0` → `0x007A7240` 생성자가 Sequence 함수표 `0x011B4094`를 설정한다. 업데이트는 `0x007A7350`이다.
- `0x0067BEE0` → `0x007A7010` 생성자가 Selector 함수표 `0x011B4084`를 설정한다.
- `0x006EBC20`은 컨테이너 객체의 `+0x24`를 반환한다. 업데이트는 그곳의 목록 머리를 읽어 노드의 `+0x08` 객체 포인터를 따라간다. `+0x28`은 목록 개수다.
- 행동 구성 함수 `0x0067E300`은 `Tag`, `Type`, `Children`을 읽으며 노드 `+0x0C`의 MSVC 문자열에 태그를 설정한다. 문자열 길이·용량은 각각 객체 `+0x1C`, `+0x20`이다.
- PSS 노드 이름/함수표 대응은 `0x0067D3E0`의 타입 비교 → 팩토리 → 생성자의 함수표 설정을 따라 확인했다. 실행 업데이트 함수를 호출하지 않는다.
- MSVC x86 RTTI의 CompleteObjectLocator와 TypeDescriptor는 이미지 주소 범위를 검사하고 컴파일된 타입 이름만 제한해 읽는다. 이를 통해 확인된 Inverter만 단일 자식으로 처리한다. 미확인 타입의 힙 내부를 검색하지 않는다.

원본 `playSupport.json`은 클라이언트가 요청하는 자산 식별자로 확인됐다. 원본 파일 위치나 압축 형식을 알아야만 행동 연결을 볼 수 있는 것은 아니다. 이 도구는 현재 만들어진 객체의 구조를 읽으므로 파일 위치 검색과 별개로 진행할 수 있다. 런타임 치환이나 설정에 따른 실제 상태를 담기 때문에 원본 파일을 완전히 복원한 결과로 취급하지 않는다.

사용자가 올린 코드·메모리 페이지는 이 도구나 공개 저장소에 재배포하지 않는다. 패키지에는 작성한 읽기 전용 소스와 합성 자료 검사 코드만 들어 있다.
