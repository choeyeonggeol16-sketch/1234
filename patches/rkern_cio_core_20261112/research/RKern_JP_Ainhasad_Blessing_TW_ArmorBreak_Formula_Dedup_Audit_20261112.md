### 1.3 부분 소모 잔여량의 대표 사례

- 표시상 축복 0%에서 자연 회복으로 1%가 되었고, 이후 해당 소모 기준 경험치 **2,200**을 사용하면 1% 완전 소모까지 **3,859**가 남는다.

- 단순히 정수 퍼센트를 저장하거나 회복 때마다 부분 소모치를 0으로 초기화하면 실측과 달라질 수 있다.
- 구현은 기존 자료 구조·영속화 체계에 맞춰 내부 정밀도와 표시용 정수 퍼센트를 분리한다. 특정 새 클래스·스레드·큐를 강제로 도입할 필요는 없다.

### 1.4 반드시 조사할 중복 구현·중복 적용 지점

1. **경험치 지급 경로:** 몬스터 사망, 파티 경험치 분배, 몬스터 경험치 2배 이벤트, 인던/특수 경험치, 펫·소환물 킬 기여 경로. 각 경로에서 축복 경험치 보너스가 **1회만** 붙는지 추적한다.

3. **UI·서버 상태 분리:** 퍼센트 표시, 실제 잔여 소모량, 임계치 변화를 각각 관리하되, UI 갱신이나 버프 재등록 자체가 소모를 재실행해서는 안 된다.
4. **재접속·재시작·CacheD:** 로그인 로드, 경험치 저장, 로그아웃, 캐릭터 재접속, 서버 재시작에서 소모 잔여량을 초기화하거나 두 번 반영하지 않게 점검한다. 실제 DB 실패/재시도 시 중복 확정이 일어나지 않아야 한다.
5. **보너스 겹침:** 축복 +100%, 201~700% 추가 +30%, 따뜻한 시선 +50%, 이벤트·혈맹·파티 보너스를 산정 단계별로 구분한다. 총 경험치에 일괄 곱하는 것과 축복 소모량의 기준을 혼동하지 않는다.
6. **회복 중복:** 자연 회복과 소모품 충전, 스케줄러 중복 실행으로 같은 시간 구간의 회복이 두 번 처리되는지 확인한다.
7. **경계 처리:** 0%, 1%, 199%→200%, 200%→201%, 700% 한계, 여러 퍼센트를 한 번에 소모하는 고경험치 킬을 검증한다.

**수정 명령:** 검색 결과 '축복 경험치 보너스 적용' 또는 '축복 소모'가 복수 위치에 있으면 호출 그래프를 그려 같은 이벤트에서 중복 실행되는지 증명한다. 진짜 중복일 경우 **단일 권위 계산 경로만 남기고 중복 계산 코드를 삭제·호출부 정리**한다. 기존 파티·캐시D·로그인·영속성 동작은 유지하고 불필요한 신규 워커나 큐는 추가하지 않는다. 반대로 단순 함수 호출 위임과 서로 다른 책임은 '중복'이라는 이유만으로 삭제하지 않는다.

- 2019 한국 리니지1 전체 직업·패시브·PvP/PvE에 동일한 1.58배가 적용된다고 단정하지 않는다. 이 문서는 **해당 실험 조건의 관찰값과 정수 처리 순서**를 비교하는 기준이다.

### 2.2 고정 피해 실험: DR 전 1.58배

연구자들은 무기 손상을 이용해 공격 피해를 고정한 뒤, 서로 다른 DR 대상에게 아머 브레이크를 적용했다.

| 조건 | 아머 브레이크 미적용 | 적용 후 관찰 | 검증 계산 |
|---|---:|---:|---|
| 기본 피해 30, 대상 DR 24 | 6 | **23** | floor(30 × 1.58) - 24 = 47 - 24 = **23** |
| 기본 피해 30, 대상 DR 18 | 12 | **29** | floor(30 × 1.58) - 18 = 47 - 18 = **29** |

이는 1.58배를 **DR 차감 전에 적용**하는 구조와 일치한다. 'DR을 먼저 빼고 피해를 1.58배' 계산하면 두 측정값을 재현하지 못한다.

### 2.3 다크엘프 복합 배율의 정수 처리 순서

대만 후속 글은 이도류의 더블 히트, 더블 브레이크, 무기 속성 추가타, STR/레벨/장비 추가타를 합한 **DR 이전 물리 피해**를 먼저 구하고 아래 순서로 처리한다고 분석했다.

    preDR = (무기 다이스·이도류·더블브레이크·속성·STR·레벨·버프·장비 등을 해당 버전 규칙으로 합산한 피해)
    afterArmorBreak = floor(preDR * 158 / 100)   // 아머 브레이크 적용 시 1회
    afterDR = afterArmorBreak - targetDR          // DR 차감은 1회
    afterBurningSpirits = floor(afterDR * 3 / 2)  // 버닝 스피릿츠 발동 시 1회
    result = 기존 서버의 하한/상한/사망/무효화 규칙에 맞춰 최종 확정

- 위 식은 **검증된 실험 조합을 설명하는 순서 모델**이며 모든 상황을 범용으로 바꾸라는 지시가 아니다.
- 특히 속성 저항에 따른 추가타 감소, 더블 히트와 더블 브레이크, 장비 추가타의 입력 계산 순서는 최신 RKern의 기존 로직을 먼저 대조한다.
- 원문은 **아머 브레이크 정수 내림 → DR 차감 → 버닝 스피릿츠 배율 → 최종 정수 내림**을 구별한다.
- 이 배율을 이미 적용한 피해를 다른 helper 또는 최종 커밋 단계에서 다시 곱하면 **1.58배가 중복 적용**되는 심각한 버그다.
- 다른 감소 효과(이뮨 투 함, PvP 보정, 별도 피해 감소, DR 상한 등)는 이 실험만으로 적용 단계가 증명되지 않는다. 확인 없이 일괄 변경하지 않는다.

### 2.4 후속 실측의 강한 회귀 예시

후속 검증에서 동일 공격 구성을 DR 이전 기본 피해 **177**로 설정하면 다음 수치가 나온다.

| preDR | 아머 브레이크 후 | DR | 버닝 스피릿츠 | 기대 최종 피해 |
|---:|---:|---:|---|---:|
| 177 | floor(177×1.58)=279 | 31 | ×1.5 | floor((279-31)×1.5)=**372** |
| 177 | floor(177×1.58)=279 | 27 | ×1.5 | floor((279-27)×1.5)=**378** |

원문에서 관찰한 최대 피해 **378**은 대상의 실제 DR이 31이 아닌 27이었던 초반 상태를 반영하면 설명된다. 원문은 이를 음식 버프 적용 차이로 정리한다. **관찰값에 안 맞는다고 배율 자체를 임의 변경하지 말 것.**

### 2.5 반드시 조사할 중복 구현·중복 적용 지점

1. **물리 공격 전체 경로:** PC→PC, PC→NPC, NPC→PC, 스킬 타격, 공격 패시브, 무기 특수 타격까지 추적한다. 대상의 아머 브레이크 상태에 따른 배율이 어느 단계에서 적용되는지 명시한다.
2. **배율 중복:** 공격 계산기와 별도 피해 helper, skill effect callback, 최종 피해 commit/receiveDamage 경로가 각각 1.58배를 곱하지 않는지 확인한다. 동일 타격에는 조건 충족 시 **단 한 번** 적용한다.
3. **DR 중복:** DR helper, 최종 HP 감소 경로, PvP 피해 보정에서 동일 DR을 복수 차감하지 않는지 확인한다. 서로 다른 감면 규칙은 구분한다.
4. **버닝 스피릿츠 중복:** 스킬/패시브 발동부와 일반 공격 피해부가 1.5배를 둘 다 적용하지 않는지 확인한다. 발동 확률은 이번 보고서의 범위 밖이며 기존 동작 유지.
5. **중복 경로의 부작용:** hit 판정, 속성 추가타, 일반 공격 중복 hit, 스킬 발동, MP/HP 흡수, 독·디버프, 전투 로그가 같은 타격에 두 번 실행되지 않게 확인한다.
6. **특수 분기 구분:** PC/NPC, 일반 공격/기술 데미지, 이도류/크로우/키링크, 면역 상태의 유효한 차이는 보존한다. 같은 계산 블록이 두 개라고 무조건 삭제하는 방식 금지.
7. **호출 흐름과 성능:** 기존 CIO/게임 상태 실행 정책을 유지한다. 핫패스에서 불필요한 new·박싱·임시 컬렉션·추가 큐를 도입하지 않는다.
8. **정수 처리:** 곱셈 전에 long 중간값을 사용해 오버플로를 막는지, floor/trunc/0 이하 하한 처리와 적용 순서가 실제 버전과 일치하는지 확인한다.

**수정 명령:** 동일 공격 이벤트의 아머 브레이크 배율, DR 또는 버닝 스피릿츠 배율이 여러 단계에서 중복 처리되면 **실제로 중복 코드를 삭제·통합하고 호출부를 정리한다.** 특히 기존 RKern 일반 공격 중복 제거 성과를 훼손하지 말 것. 별도 신규 구조를 만들지 말고 기존 소유 경로의 최소 변경으로 해결한다.

## 3. 중복 코드 발견 시 필수 수정 절차 (두 항목 공통)

**이 항목은 단순 권고가 아니라 구현 담당자에게 주는 필수 작업 지시다.**

1. **최신 RKern 전체 SRC만 사용.** 직전 변경 사항과 사용자 커스텀 코드를 보존한다. 기존 일반 공격 중복 제거 패치 및 CacheD 정책을 되돌리지 않는다.
2. **관련 사용처 전체 검색 후 호출 그래프 작성.** 축복 관련 검색 예: Ainhasad/AinhasadBlessing/Ain/Einhasad/Blessing, 경험치 지급·분배·CacheD 경로. 아머 브레이크 관련 검색 예: ARMOR_BREAK/ArmorBreak/158/1.58/DR, 공격 helper·피해 commit/receiveDamage·버닝 스피릿츠 경로. 검색어는 예시이며 실제 클래스 이름과 숫자 상수는 소스에서 확인한다.
3. **중복의 정의를 명확히 한다.** 서로 다른 정상 정책을 위한 분기는 중복이 아니다. **하나의 게임 이벤트에 같은 효과가 두 번 계산·확정되거나 완전히 동일한 계산을 여러 곳에서 관리해 어긋날 수 있는 경우**가 제거 대상이다.
4. **중복 발견 시 반드시 수정한다.** 중복된 계산을 삭제하고 기존 권위 경로 하나로 연결한다. 실사용 호출과 데이터 흐름을 정리해야 하며, 주석 처리 또는 단순 TODO 등록으로 끝내면 안 된다.
5. **코드가 실제로 다른 경우에만 계산식 수정.** 해외 2013~2015 실험 자료와 한국 2019 기준이 동일한지 검증하기 전 숫자나 게임 규칙을 무조건 바꾸지 않는다. 버전 차이는 보고서에 표시한다.
6. **성능·안정성 유지.** hot path에 불필요한 할당, 추가 동기 DB 호출, 새로운 worker/queue를 만들지 않는다. 캐릭터 경험치·축복 상태 갱신과 아이템/DB 확정성 및 장애 복구를 훼손하지 않는다.
7. **회귀 실행과 결과 제출.** 각 A01~A12, B01~B14를 검증하고, 변경 전 실패/변경 후 통과 증빙을 남긴다. Java 21 구문 검사·가능한 의존성 컴파일·동시성·실제 MySQL/재시작 시험 여부를 정확히 구분한다.
8. **작업 산출물.** 변경 파일 목록, 변경 위치 및 이유, 제거한 중복 계산의 호출 경로, 성능/GC 영향, 테스트 결과, 미검증 항목을 명시한다. 사용자가 코드 패치를 요청한 경우 최신 전체 SRC 기준으로 한 번에 검증된 파일을 제공한다.

### 완료 판정 (모두 충족해야 완료)

- [ ] 두 항목에 대한 실제 RKern 코드 사용처 목록을 확보했다.
- [ ] 하나의 경험치 지급에서 축복 보너스와 소모량이 각각 정확히 1회 적용된다.
- [ ] 하나의 타격에서 아머 브레이크·DR·버닝 스피릿츠가 각 적용 조건마다 정확히 1회 처리된다.
- [ ] 중복 코드가 있었다면 삭제 및 실제 호출 흐름 정리가 끝났다. 없었다면 **중복 없음**을 코드 근거와 함께 명시했다.
- [ ] 실측 수치와 버전 차이를 구별한 테스트 결과를 제출했다.
- [ ] 기존 공격 중복 제거, CacheD/경험치 영속화, PvP/PvE 예외 및 CIO 소유 실행을 보존했다.
- [ ] 검증하지 않은 통합/실서버 테스트를 통과로 표시하지 않았다.
