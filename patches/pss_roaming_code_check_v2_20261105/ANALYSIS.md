# 첫 PSS 런타임 자료에서 확인한 내용

수신 파일: `PSS_Roaming_Code_20261105_074459_915.zip`. 23개 코드 페이지와 보고서가 정상 수집됐다. 원본 덤프는 공개 배포하지 않는다.

- 실제 게임 프로세스에서 `phase=3`, `running=1`이다. 다른 동일 파일 프로세스는 `phase=0`으로 제외됐다.
- `0x00668C50`은 실행 중인 현재 작업의 업데이트 함수를 호출하고, 작업 완료 시 `0x00669B20`으로 진행한다.
- `0x00669B20`은 큐의 다음 작업을 시작하며, 기본 큐가 비면 `0x00669840`을 호출해 전투 큐를 재구성한다.
- `0x00669840`은 작업을 생성하는 팩토리들을 호출한다. 팩토리와 래퍼를 따라가면 실제 작업 생성자 `0x00657F10`, `0x006778E0`, `0x00678000`에 도달한다. 이 본문들이 첫 수집의 `0x00660000~0x0066FFFF` 범위 밖이었다.
- 현재 작업 객체는 관리자 `+0x24`에서 읽는다. 기존 수집의 `+0x20` 값은 활성 큐의 주소이므로 그 값만으로 현재 작업이나 빈 큐를 판정하지 않는다. 작업 이름 위치는 실제 진행 함수가 로그에 사용하는 MSVC 문자열 멤버 `+0x18`을 근거로 제한해서 읽는다.

따라서 **전체 전투 루프가 꺼졌다는 증거는 없지만**, 대상 없음 분기에서 이동/탐색을 선택하는지, 설정이 이를 제한하는지, 호출된 작업 자체가 대기하는지는 아직 확인되지 않았다. `Battle` 내부에도 이동 처리가 있을 수 있어 관리자 루프만 보고 배회가 없다고 단정하지 않는다. 서버의 LOCAL 시험 메타데이터를 GLOBAL로 바꾸거나 임의 주소를 실행하는 패치를 하지 않는다.

V2는 확인된 작업 본문을 포함하는 실행 코드 영역 `0x00650000~0x0067FFFF`, 참조된 고정 이름/함수표 `0x01187000` 페이지, 현재 작업의 타입·이름을 수집한다. 함수 호출 후보는 오프라인 디스어셈블로 다시 검증한다.

검증된 현재 작업의 함수표도 최대 한 페이지 추가로 읽는다. 함수표는 확인된 앞의 세 항목만 메서드로 취급한다. 초기 도구처럼 인접 타입의 항목까지 관리자 메서드로 표시하지 않는다. 추가한 도구는 C# 컴파일·구문 검사·호출 후보 범위 검사 7개를 통과했으며, V2의 실제 게임 수집은 아직 확인하지 않았다.
