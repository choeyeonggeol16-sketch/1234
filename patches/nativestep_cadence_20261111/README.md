# 49027 걷기 간격·입력 대기 수정 V5

V4 로그에서 네이티브 목표 입력이 동작하는 것은 확인됐지만, 사용자는 걷기가 부자연스럽다고 보고했습니다. 소스에는 성공한 걸음에도 고정 600ms 대기와 AI의 별도 걷기 타이머가 겹치는 경로가 있습니다. V5는 이 부분과 클릭 준비 확인을 수정합니다. 실제 Windows 게임에서 개선 정도는 아직 확인하지 못했습니다.

## 적용 — 서버와 DLL 모두 필요

1. 기존 서버 소스와 클라이언트 `dinput.dll`을 백업합니다.
2. ZIP의 `src`를 **처음 첨부한 서버 소스 또는 V4 전체 소스**에 덮어씁니다. 아래 Java 3개를 함께 반영해 기존 서버 프로젝트에서 빌드하고 서버를 재시작합니다.
   - `l1j/server/AutoHuntSystem/NativeStepSession.java`
   - `l1j/server/AutoHuntSystem/AutoHuntController.java`
   - `l1j/server/CharacterAction/Walk/WalkActionHandler.java`
3. 게임을 종료하고 `client-ready/dinput.dll`을 Mega.bin 옆에 넣습니다. 게임을 다시 실행하고 49027로 시작합니다. F9 보정은 필요 없습니다.

서버에 `step-v5 sprite-cadence strict-heading control armed`, 클라이언트 `client_io.log`에 `native-tile-input-v5-20261111`이 표시되어야 합니다. **DLL만 교체하면 서버의 고정 대기는 바뀌지 않습니다.** 전체 소스 ZIP은 서버 소스와 클라이언트 소스·DLL을 포함하며, 서버 실행 JAR과 외부 라이브러리는 포함하지 않습니다.

## 변경

- 성공한 걸음의 다음 승인 시점은 WALK 핸들러가 사용하는 캐릭터의 현재 sprite interval을 따릅니다. 예를 들어 원래 간격이 180ms면 600ms 대신 180ms를 기다리고, 1000ms인 캐릭터는 1000ms를 기다립니다.
- 배회와 아이템을 향해 걷는 경로에서는 별도 AI 타이머로 걷기 주기를 한 번 더 소비하지 않습니다. 실제 아이템 줍기 간격은 유지합니다.
- DLL은 원본 `0x471A70` 목표 선택 함수가 검사하는 입력 차단·상호작용·busy 상태를 먼저 확인합니다. 클릭을 받지 않는 상태에서는 승인 유효기간 안에서 기다립니다. 승인이 만료되거나 취소되면 클릭하지 않습니다.
- 실패/무응답의 600ms 복구 대기와 엄격한 방향·출발 좌표·한 칸 승인·이전 세션 차단은 유지합니다. V4의 실제 타일 투영·역변환과 정상 걷기/카메라 경로도 유지합니다.

지원 Mega.bin SHA-256: `09804d9579446fb9a630c39c1f1b2d08083718261d2f3e57b2e36f80ba865490`. 원본 실행 파일은 수정하거나 배포하지 않습니다.

## 검증과 한계

- 실제 NativeStepSession을 Java 8 대상 바이트코드로 컴파일하고 Java 21에서 실행했습니다. 7종 걷기 간격의 직전/정시 승인, 한 칸 승인, 세션 재시작, STOP, 방향/출발 좌표 검사, 실패·무응답 복구 대기를 통과했습니다. 예전 600ms 성공 대기를 되살리면 회귀 검사가 실패하는 것도 확인했습니다.
- 변경한 Java 3개의 구문을 파싱했습니다. 전체 서버 타입/의존성 빌드와 실행은 하지 않았습니다. 원본 서버의 SWT 등 외부 라이브러리가 이 첨부 소스에는 없습니다. 실제 서버 프로젝트의 기존 빌드 환경으로 재빌드해야 합니다.
- 원본 Mega.bin에서 복원한 x86 함수의 좌표/목표 192개 사례와 busy 질의/목표 선택 대기 7개 사례를 통과했습니다. 충돌·게임 상태 데이터는 통제된 fixture이며 전체 게임을 실행한 검사는 아닙니다.
- Windows PE32 DLL 빌드, DirectInput export/ordinal 1~7, V5 표시와 시스템 의존성을 확인했습니다. Windows 호스트 EXE는 빌드만 했습니다.
- 제공된 V4 로그에는 목표 선택 실패도 있습니다. V5의 대기 확인은 원본 함수의 명시된 early return 조건을 다루며, 물체에 가려진 클릭·UI 소비 등 모든 실패 원인을 해결했다고 단정하지 않습니다. 실제 연속 이동·사냥·카메라의 자연스러움은 Windows 실게임에서 추가 확인이 필요합니다.

서버 검사 재현: 이 폴더에서 `bash tests/run.sh` (Java compiler 모듈 필요). 네이티브 검사 재현은 `nativestep-client/tools/unpack_for_native_tests.py`와 `tests/mega_native_replay.py`를 사용합니다. 실제 실행 파일과 복원 메모리는 GitHub/ZIP에 넣지 않습니다.
