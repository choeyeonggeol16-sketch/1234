# PSS 설정서 → 원래 PSS 설정창 연결 시험본

인벤토리의 **900000901 / PSS 설정서**를 더블클릭하면 네가 스크린샷으로 확인한 원래 PSS 설정창을 요청한다. 설정·시작·정지는 그 창에서 한다. 설정서는 소모되지 않는다.

기준 서버는 마지막에 올린 `RKern_PSS_V10_InterServer_No2sDelay_ImmediateEnterWorld_FULL_SRC_20261104.zip`이다. 즉시 월드 입장 관련 파일 4개는 첨부본과 바이트 단위로 동일하다. 기존 V12의 2111 진단도 포함한다.

## 적용 순서

1. 서버를 끄고 기존 소스를 보관한다. **전체본의 `src`를 서버 프로젝트에 넣고 기존 `build.xml`·`lib`로 다시 빌드**한다. `src/META-INF/MANIFEST.MF`도 포함돼 있다. Java 21 기준이다.
2. 실제 게임 DB에서 `sql/PSS_Settings_Item_900000901.sql`을 실행하고 서버를 재시작한다. 다른 아이템이 이미 같은 ID를 쓰면 덮어쓰지 않는다. 마지막 SELECT에서 이름이 `PSS 설정서`인지 확인한다.
3. **게임 프로그램을 완전히 종료했다가 다시 실행해서 캐릭터로 입장**한다. 압축 안 `client/PssButton.exe`를 실행하고 해당 게임에 연결한다. EXE는 네가 올린 원래 `PSS버튼.exe`와 내용이 같고, `Pss2019.dll`을 이번 버전으로 바꿨다. 예전 DLL이 이미 들어간 게임에 새 DLL을 겹쳐 연결하지 않는다. 연결 도구는 켜 둔다.
4. 서버에서 `[PSS-WINDOW] companion bound player=...`를 확인한다. GM 채팅에 **`.psswindow`**를 입력하면 아이템 지급 전에 창 연결을 시험할 수 있다.
5. 기존 GM 아이템 생성 기능으로 **900000901**을 지급해 더블클릭한다. 그 창에서 설정하고 시작/중지를 누른다. 작은 외부 PSS 버튼창은 X로 숨겨도 아이템 요청을 처리한다.

**서버 소스만 교체해서는 연결되지 않는다. 클라이언트 보조 DLL도 같이 적용해야 한다.** 2111을 서버에서 보내 창을 여는 구현이 아니다. 이미 열린 것을 확인한 `PlaySupportUI::Show(true)` 경로를 게임 UI 스레드에서 호출한다.

## 포트

게임 포트가 **5000**이면 창 연결 포트는 **5001/TCP**다. 클라이언트는 게임에 접속한 서버 IP를 자동으로 찾는다. 별도 IP 입력이나 PID 입력은 없다.

외부 PC에서 접속한다면 서버 방화벽/공유기도 **5001/TCP**를 서버로 연결해야 한다. 게임 접속에 별도 포트 전달을 쓰고 있다면 이 포트도 전달한다. 같은 PC의 로컬 테스트는 공유기 설정이 필요 없다. 첫 등록 때 포트를 연다.

게임 포트가 다르면 `client/Pss2019.ini`의 `GamePort`와 `WindowPort`를 바꾼다. 서버 기본 창 포트는 `GAME_SERVER_PORT + 1`이고, 별도 지정할 때만 Java 실행 옵션 `-Dpss.uiBridge.port=포트`를 쓴다. 게임 포트/소켓 암호화/IOCP 수신 코드는 바꾸지 않았다.

## 원래 보조 도구를 그대로 사용하는 대안

새 DLL에서 자동 연결이 잡히지 않을 경우를 위한 **`client/source-link/PSS_Item_Link.cmd`**도 있다. 이 방법은 원래 DLL의 설정 버튼과 네가 성공한 1바이트 수정을 그대로 사용한다.

1. 원래 PSS 시험본 DLL로 게임에 연결한 상태에서 `PSS_Item_Link.cmd`를 더블클릭한다. 게임과 같은 권한으로 실행한다. 게임을 여러 개 켰다면 하나만 남긴다.
2. 콘솔에 나온 **`.psslink 32자리값` 한 줄을 게임 채팅에 한 번 붙여 넣는다.** 이 값은 해당 캐릭터 연결을 확인하기 위한 일회용 값이다. 서버는 채팅 전송/기록 전에 이 명령을 처리한다.
3. 콘솔에 **`READY`**가 나오면 설정서를 사용한다. 콘솔은 켜 둔다. 아이템을 사용할 때마다 명령을 입력할 필요는 없다. 재접속 후에는 새로 표시되는 값으로 한 번 다시 연결한다.

자동 연결용 새 DLL과 이 대안은 **동시에 쓰지 않는다.** 대안 실행 시에는 원래 DLL을 사용한다. 포트가 다르면 `PSS_Item_Link.cmd -GamePort 게임포트 -WindowPort 창포트`로 실행한다.

아이템 연결과 별개로 원래 도구의 설정창만 즉시 열고 싶으면 **`client/source-link/PSS_Open_Now.cmd`**를 더블클릭한다. 기존 PSS 도구가 연결된 게임을 자동 검색해 원래 설정 버튼을 요청한다. 파일 선택이나 PID 입력은 없다.

## 확인된 범위

- 사용자 게임: 원래 설정창 표시, 창 안 설정 후 시작 동작은 이미 확인됐다.
- 서버: 전체 Java **1,711개** 컴파일 통과. 기존 PSS/아이템 계약 **18그룹 1,116검사** 및 300회 동시 소유권 경쟁 검사 통과.
- 서버 보조 연결: 분할 수신, 등록 순서, 다른 IP/세션 거절, 재사용 거절, 연결 수 제한, 동시 클릭, 만료/로그아웃 정리 검사 통과.
- 새 DLL: 32비트 Windows 빌드 `-Wall -Wextra -Werror` 통과. 격리된 PE32 테스트에서 실제 thiscall/cdecl 호출, 18개 등록 프레임, 인증 후 OPEN 전달 통과. 이 테스트의 메모리 읽기·TCP 소유자 조회·UI 메시지는 환경 제약으로 테스트 대역을 쓴다.
- 소스 대안: 실제 C# 코드를 컴파일하고 실제 Java 연결 서버와 BOUND/OPEN 통신을 검증했다.
- **이번 아이템 전체 연결을 실제 Windows 게임에서 누르는 최종 테스트는 아직 못 했다.** 자동 등록용 클라이언트 송신 함수와 포트 연결은 실게임 확인이 필요하다. 자동 연결이 실패하면 위의 `.psslink` 대안으로 기존 도구를 사용할 수 있다.

**기존 서버의 GM 전용 PSS 시험 제한과 600초 제한은 유지했다.** 창을 여는 것과 PSS 시작 허용은 별개다. 이번 변경은 그 제한, 자동사냥 판단, 이동/텔레포트 규칙을 바꾸지 않는다.

대상 클라이언트는 네가 올린 원본 `19.02.15.1002`, SHA-256 `9C82129EFED1D93981782069E82DE79869920769AA0F67BC1183CA75CF621823`이다. 해시·로드 주소·함수 바이트·UI 객체가 맞는 경우에만 수정/호출한다. 클라이언트 파일은 수정하지 않고 실행 중 메모리만 사용한다. 원래 게임 실행 파일은 배포본에 넣지 않았다.

## 연결이 안 될 때 볼 위치

- 서버에 `companion listening port=5001`조차 없다: 새 서버 소스 적용, 게임 로그인 완료, 새 DLL 연결을 확인한다. 대안의 `.psslink`도 이 등록을 시작한다.
- listening은 있고 bound가 없다: 포트 전달/방화벽, DLL 폴더의 `PSS2019_trace.txt`, 설정한 게임 포트/창 포트를 확인한다.
- bound는 있고 창이 안 뜬다: `.psswindow`와 작은 원래 설정 버튼을 각각 눌러 본다. 새 DLL 로그의 `PSS UI object/vtable differs` 또는 `PSS UI show requested`를 확인한다.
- 게임에서 `PSS 연결을 확인한 뒤 다시 사용해 주세요`가 뜬다: 보조 도구가 아직 해당 캐릭터에 연결되지 않은 상태다. 설정서는 소모되지 않는다.

새 코드 원문과 빌드 명령은 `client/source`, `client/source-link`, `tests`, `validation`에 포함했다. 로그의 전송 요청 성공은 실제 창 표시를 보증하는 클라이언트 응답이 아니다.
