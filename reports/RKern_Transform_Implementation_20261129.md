# RKern 변신 통합 및 검증 결과

최신 통합 브랜치 기준점은 `79aa968`이며 변신 지시서 `43bba4f`를 반영했다. 기존 공성·스킬 습득 작업과 `database/Net.sql`을 함께 포함한다. 배포 DB 변경은 없다. [변신 지시서](RKern_NC_Transform_Full_Refactor_20261129.md)

## 구조 및 호출 경로

| 경로 | 적용 방식 |
| --- | --- |
| 정의·GM 리로드 | `CTransformDB`가 기존 DB에서 이름, 스프라이트 ID, 랭킹 인덱스를 만든다. 리로드 실패 시 이전 스냅샷을 유지한다. `CTransformCommonData`는 외형·조건을, `CTransformCombatData`는 장비·행동 판정을 맡는다. |
| 일반 변신·스킬·NPC·보스 | 캐릭터의 `Transform`·`CancelTransform`을 사용한다. 스킬 진입·종료는 `PumpStartTransformSkill`·`PumpEndTransformSkill`로 연결한다. PC 무기한 효과와 NPC 유한·무기한 효과를 유지한다. |
| 주문서·카드·마법서·NPC 유료 변신 | 선택과 조건을 먼저 검증한다. 기존 CacheD receipt가 차감을 확정하면 소유 실행 경로에서 적용한다. 축복 주문서는 목록을 열 때 수량을 유지한다. 마법서 목록은 무효 선택 후 다시 사용할 수 있다. |
| 장비·세트·슬롯 변경 | `CanUseItem`이 외형의 장비 조건을 확인한다. 장착 슬롯에서 호환되지 않는 아이템을 해제한 뒤 외형을 알린다. 장비가 유발한 변신은 해당 장비 또는 세트가 소유한다. 용기사 체인소드 동작 번호는 착용 캐릭터 상태에서 계산한다. |
| 로그인·사망·부활·직업 변경 | 저장된 링·일반 변신의 복구 순서와 무효 저장값을 처리한다. 사망 외형을 기록한 뒤 변신을 정리한다. 일반 부활과 직업 변경도 공통 해제를 사용한다. |
| 개인상점 | `CTransformForModeChange`가 8개 상점 외형을 관리한다. 일반 입점은 활성 전투 외형을 기억하고 종료 시 복원한다. Action UI 입점은 기존처럼 변신을 해제한다. |
| 자동혈맹 | 기존 가입 전용 변신 해제 메서드의 생산 호출 0건을 확인했다. 실제 가입 실행 경로는 유지했다. |

캐릭터 외형·장비·효과가 확정된 뒤 변신 패킷을 보낸다. 투명·GM 은신·유령의 변신 외형과 모션 방송을 거른다. 일반 변신에서 장비 소유 및 NPC 타이밍 휠을 재사용한다. 적용 중 NPC 타이머 입장이 거부되면 기존 외형과 효과를 유지한다.

## 검증

- Java 21 preview 생산 Java 1,724개 전체 타입 컴파일과 `git diff --check`를 통과했다. 생산·테스트 소스에서 구형 `PolyTable`, `L1PolyMorph`, `doPoly`, `undoPoly` 참조가 0건이다.
- 격리 MariaDB에 통합 `Net.sql`을 설치해 820개 고유 변신 스프라이트와 리로드 복구를 검사했다. 반지 1,000회 적용·교체·해제 후 HP와 여섯 스탯의 누적 오차가 없었다. 용기사 공유 무기 정의, 장비 해제, 상점 복원, 로그인 복구, 사망 상태에서의 적용 차단과 부활 정리를 시험했다.
- NPC 타이머의 유한·무한 효과, 과거 만료의 새 변신 보호, 타이머와 NPC 큐 입장 거부를 재현했다. MariaDB SQL 오류를 주입해 주문서 차감 롤백과 외형 유지도 확인했다.
- 참조 회귀 검사에서 개인상점 89개 검사, 인벤토리·버프 스냅샷, 로그인 수화, 파티·월드 조회/스킬 범위·외형·공성, 스프라이트 타이밍, 스킬 습득·직업 변경·스탯 초기화가 통과했다. 암호화 루프백 외형 방송에서 최대 500 수신자와 4개 동시 송신원을 검증했다.

## 합성 PC 5,000명 부하 비교

동일 Java 21 JVM 설정과 DB를 사용해 소켓이 없는 PC 5,000명의 반지 변신 적용·해제를 배치마다 반복했다. 기준 브랜치의 해제 API 호출 전에는 실경로처럼 기존 변신 타이머를 제거했다. p99는 5,000쌍으로 구성된 100개 배치 기준이다.

| 측정 항목 | 기존 통합 코드 | 이번 변경 |
| --- | ---: | ---: |
| 적용·해제 1쌍 CPU 시간 | 1,576 ns | 861 ns |
| 배치 p99 경과 시간 | 11.732 ms | 7.966 ms |
| 스레드 할당량 | 296 B/쌍 | 296 B/쌍 |
| 활성 상태와 해제 상태의 GC 후 힙 차이 | 1,258,072 B | 1,250,168 B |
| 해제 후 GC 힙 편차 | +18,072 B | +10,168 B |
| 활성 PC 유한 타이머 | 0 | 0 |

GC 후 힙 수치는 프로세스 추정값이다. 장비 판정은 장착 무기·방어구만 확인하며 변신 해제의 가방 순회와 공유 무기 템플릿 쓰기를 제거했다. 실클라이언트 화면과 운영 서버 5,000명 동접은 검증 범위 밖이다. 유료 변신은 차감 확정 후 적용 직전에 조건을 다시 확인한다. 그 사이 사망이나 맵 변경으로 조건이 달라지면 외형이 적용되지 않을 수 있으며 차감 취소는 기존 receipt에서 제공하지 않는다.
