### 1.3 서버 로직 검수 기준

1. **명중과 피해를 분리**한다. 맨손이 반드시 맞는다고 처리하지 않는다. 명중 로직은 해당 버전의 정확한 구현을 유지하며, 확인되지 않은 공식을 새로 만들지 않는다.
2. 명중한 일반 맨손 공격에 대해서만 최종 피해 후보가 `1` 또는 `2`인지 검사한다. 무기 다이스, STR, 장비/MD 추가타, 공격 버프, 대상 DR을 통과한 계산 결과가 되면 일본 관찰과 다르다.
3. 특수한 `피해 1 고정` NPC 분기가 있다면 일반 맨손 피해와 구분한다.
4. 활 변신의 맨손 공격은 **피해 0을 출력하는 공격**이 아니라 **공격 모션 자체가 생성되지 않는 사례**였으므로, 공격 허용 판정과 애니메이션 경로를 함께 확인한다.
5. 맨손 공격이 흡혈, 반격, 스킬 발동, 위협도, 무기 손상 등의 주변 효과와 어떻게 결합되는지는 위 원문만으로 확정할 수 없다. 이런 경로를 독단적으로 바꾸지 않는다.

## 2. 속성 저항

### 2.1 실험 원문

  https://recordgame.blogspot.com/2015/09/blog-post_13.html
- NPC 대상 속성 공격 검증 방법:  
  https://recordgame.blogspot.com/2015/09/npc.html

### 2.2 관찰된 핵심

- 기존 **속성 계수 구간** 방식 대신, 캐릭터 화면에 표시되는 **속성 저항 퍼센트**를 쓰는 계산을 관찰했다.
- **속성 저항이 100%를 넘어도 더 큰 감면 효과가 없었다.** 100%와 110% 또는 130% 조건에서 결과가 같았다는 기록이 있다.
- **음수 속성 저항**은 속성 피해를 증가시킬 수 있다.
- 원문의 직접 통제된 비교는 주로 **PC→PC**이다. PC→NPC, NPC→PC 전체에 같다는 것은 연구자의 추정이며 별도 검증이 필요하다.
- 마법 피해는 INT 계수, MR, DR 및 마법 추가 피해가 결합되므로 **물리 무기의 속성 추가타 계산식을 그대로 모든 마법 최종 피해에 적용해서는 안 된다.**

### 2.3 무기의 물리 속성 추가타 공식

원문이 제시한 실험 기준식:

```text
R = 해당 속성의 대상 저항(%), 상한 100
B = 물리 공격에 붙는 해당 속성의 추가타 (양의 정수)
속성 추가 피해 = FLOOR(B * (1 - R / 100))
```

자바의 **비음수 정수** 영역으로 확정된 후라면 부동소수점 연산 없이 `long` 곱셈 / 100 정수 나눗셈으로 같은 바닥 내림값을 만들 수 있다. 저항 -20%를 0%로 강제하는 코드는 잘못된 결과를 만들 수 있으므로 피해야 한다. 원본의 100% 상한만 유지한다.

| 대상 저항 | 속성 3단(B=5) | 속성 4단(B=7) | 속성 5단(B=9) |
|---:|---:|---:|---:|
| -20% | 6 | 8 | 10 |
| 0% | 5 | 7 | 9 |
| 20% | 4 | 5 | 7 |
| 40% | 3 | 4 | 5 |
| 60% | 2 | 2 | 3 |
| 80% | 1 | 1 | 1 |
| 90% | 0 | 0 | 0 |
| 100% | 0 | 0 | 0 |
| 110% | 0 | 0 | 0 |

> 위 표는 원문의 2015년 3/4/5단 속성 추가타 기준값(5/7/9)을 사용한 **공식 계산 결과**이다. 해당 단계별 기본 추가타가 2019년 버전에서도 동일한지는 별도로 DB/설정 및 실측과 비교해야 한다.

### 2.4 속성 마법의 예외적 계산 순서

원문에는 다음 구조의 **당시 마법 피해식**이 제시돼 있다.

```text
FLOOR(
    기본 마법 피해 * ROUNDDOWN(
        1 + 3/32 * (INT + β - 12) - 속성 저항률,
        소수 둘째 자리
    )
)
→ 이후 MR 효과 및 별도 피해 감소 등의 판정을 검토
```

여기서 `β`는 연구자의 마법 증폭 관련 표기다. `ROUNDDOWN(..., 2)`는 소수점 두 자리 버림을 뜻한다. 위의 전후 처리와 마법 추가타, DR 위치를 모두 확정한 최종 구현식으로 오인해서는 안 된다.

**가장 중요한 반례:** 해당 연구에서는 방어측의 **화속성 저항 100%**인데도, 공격자의 INT 계수가 높은 마그마 애로우가 실측 피해를 남겼다. 예컨대 연구자의 조건에서는 동일한 공격이 화저항 0%일 때 18, 화저항 100%일 때 8로 관측되었다(동일 MR·DR 조건). 즉 100% 저항 시 모든 화속성 마법이 반드시 피해 0이라는 규칙은 틀릴 수 있다.

### 2.6 구현 방향 (소스 검수 후 적용)

1. `물리 무기 속성 추가타`, `속성 마법 기본 피해`, `마법 추가타`, `물리 DR`, `마법 MR`을 계산 파이프라인에서 구분한다.
2. 동일한 속성 저항 수치를 읽더라도 **어떤 피해 성분에 적용하는지**를 구분한다.
3. 100%를 초과하는 저항은 실측 기준상 더 이상 감면시키지 않으며, 음수 저항은 잃지 않는다.
4. 공통 정수 계산은 primitive/무할당 경로를 유지한다. 하지만 부동소수점→정수 치환 전에 모든 부호·반올림 경계 테스트를 통과시킨다.
5. 최신 2019년 기준 데이터에서 물리 속성 부여 단계 기본값(5/7/9)이 맞는지를 먼저 확인한다.


### 2.7 필수 추가 지시: 속성 저항 계산 중복 탐지 및 실제 중복 제거

**작업 지시:** 최신 RKern 전체 SRC에서 속성 저항이 **중복 구현되어 있거나 하나의 피해 성분에 2회 이상 적용된다면, 해당 중복을 반드시 수정**한다. 단순 TODO·보고만으로 끝내지 않는다. 반면 물리 무기 속성 추가타와 속성 마법의 **의도된 별도 계산 경로**까지 하나로 합치는 변경은 금지한다. 같은 저항 수치를 읽는다는 사실만으로 중복이라고 판단하지 않는다.

**확인 범위(실제 클래스·메서드명은 최신 SRC에서 검색하여 확정):**

1. 공격 패킷/스킬 핸들러 → 물리·마법 데미지 계산기 → 최종 피해 확정(`receiveDamage` 등)까지 호출 체인을 추적한다. PC→PC, PC→NPC, NPC→PC, NPC→NPC를 가능한 범위에서 각각 확인한다.
2. 공격/스킬 처리부, 공통 피해 계산기, `Resistance` 등 저항 관련 유틸리티, 무기 속성 단계·마법 속성·속성 강화/약화 버프 처리에 **동일 속성 추가타 또는 같은 마법 피해 성분을 반복 감면하는 지점**이 있는지 검사한다.
3. '저항 스탯 합산 중복'과 '피해 감면 중복'을 구별한다. 장비·버프·패시브의 같은 보너스를 두 번 더하는 경우도 검사한다. 다만 원본 규칙상 서로 다른 효과가 누적되는 경우는 유지한다.
4. **중복이 확인되면 기존 소유 계산 경로 하나로 정리**하고, 중복된 호출·분기·공식만 제거한다. 새로운 병렬 계산기, 중복 캐시, 신규 워커/큐를 만들지 않는다. 계산 입력 및 반환 형식은 가능한 그대로 두고 primitive·무할당 경로를 선호한다.
5. 예외를 유지한다. 물리 속성 추가타와 INT 증폭형 마법, 별도 마법 추가타, MR/DR은 **서로 다른 피해 구성 요소**다. 무작정 `elementResist` 하나로 통일하거나 MR·DR까지 제거하지 않는다. 100% 상한, 음수 저항, 정수 버림, 마법 처리 순서도 보존한다.
6. 변경 전후 테스트에서 **속성 저항 0/20/40/60/80/90/100/110/-20, 다중 속성, 무기와 마법의 복합 피해, 버프 중첩, 대상 타입별 경로**를 비교한다. 계산 경로의 각 단계에서 속성 추가타 감면 횟수를 추적해 **동일 피해 성분당 의도한 횟수(일반적으로 1회)**만 적용되는지 확인한다.
7. 결과 보고서에는 중복 발견 여부, 정확한 클래스·메서드·호출 경로, 제거한 중복 코드, 영향을 받은 피해 유형, 테스트 결과를 남긴다. **미발견이면 중복 없음으로 확인한 범위를 명시**하고 불필요한 수정은 하지 않는다.

**중복 감면 오류의 예시(가상의 예, 실제 RKern에서 발견됐다는 뜻 아님):**

```text
원본 속성 추가타 B=9, 저항 R=40%
정상: floor(9 * 0.6) = 5
잘못된 이중 적용: floor(floor(9 * 0.6) * 0.6) = 3
→ 같은 속성 추가타에 저항이 두 번 적용되면 피해가 과도하게 감소한다.
```

| ID | 추가 회귀 테스트 | 기대값 / 검사점 |
|---|---|---|
| E13 | 속성 저항 40%, 추가타 9, 전체 피해 파이프라인 | 속성 추가타 결과 `5`가 재감면되지 않음 |
| E14 | 장비+버프가 같은 속성 저항을 제공 | 각 효과의 합산 횟수 및 상한 처리 확인; 동일 효과 중복 산입 금지 |
| E15 | 물리/마법 계산기와 최종 `receiveDamage` 호출 연동 | 동일 피해 성분의 감면이 중복 실행되지 않음 |
| E16 | 2개 이상 속성 추가타가 공존 | 각 속성별 독립 저항, 교차 감면 및 중복 감면 금지 |
| E17 | PC→PC / PC→NPC / NPC→PC / NPC→NPC | 대상 타입별 실구현 분기를 확인하고 누락·중복 방지 |
| E18 | 100/110/-20 저항, MR/DR 결합 | 상한/음수/감면 순서가 수정 전 검증 규칙에서 퇴행하지 않음 |

**수정 완료 기준:** 실제 중복이 있다면 제거 후 회귀 테스트 통과, 없다면 실제 소스 호출 체인 점검으로 미발견을 확인했을 때만 해당 감사 항목을 종결한다. **아직 최신 SRC를 확인하지 않았으므로 중복 존재나 수정 완료를 주장하지 않는다.**

## 3. 판정 및 남은 검증

| 항목 | 일본 원문으로 확인 | RKern 최신 SRC 확인 | 2019 한국 본서버 일치 검증 | 수정 여부 |
|---|---|---|---|---|
| 맨손 1~2, 추가타/DR 무시, 변신 제한 | 확인 | 미실시 | 미실시 | 수정 없음 |
| 물리 속성 추가타 % 계산·상한·음수 | 확인(PC→PC 중심) | 미실시 | 미실시 | 수정 없음 |
| 속성 마법과 물리 속성 추가타의 처리 분리 | 원문 구별 확인 | 미실시 | 미실시 | 수정 없음 |

**추가 필수 점검:** 속성 저항의 스탯 합산 중복 및 동일 피해 성분에 대한 중복 감면을 추적하고, 확인된 중복은 실제 코드에서 수정해야 한다. 물리/마법의 의도된 별도 경로는 보존한다.

**최종 판단:** 위 두 항목은 일본 본서버 실험 기반의 유효한 RKern 검수 대상이다. 현재 새 소스 파일이 제공되지 않았으므로 수정할 클래스나 코드 위치를 확정하지 않았고, 이 보고서만으로 현행 RKern이 잘못됐다고 주장하지 않는다. 검수 기준과 회귀 사례는 확보했다.
