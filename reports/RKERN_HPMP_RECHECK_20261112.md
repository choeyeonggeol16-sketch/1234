# HP/MP 통합본 재점검 및 보완 결과

대상은 `aab3d06`의 전체 src입니다. 기존 초기화 경로를 포함해 네 가지 문제를 추가로 재현하고 보완했습니다. 이전 수정은 그대로 포함하며, 재점검 ZIP의 Java 변경은 4개 파일입니다.

| 우선 | 발견한 문제 | 보완 |
|---|---|---|
| P1 | CharacterTable.storeCharacter가 PC 모니터를 잡고 사용자 잠금을 기다리는 반면, 스냅샷/레벨업은 사용자 잠금 후 synchronized getter를 호출하여 교착 가능 | 실제 저장 진입점의 잠금을 사용자 잠금으로 통일. 신규 생성 경로도 같은 순서 적용 |
| P1 | 초기화 핸들러가 스냅샷과 같은 잠금을 사용하지 않고, pc.save 바깥의 직접 스냅샷 경로는 초기화 중간 스탯과 이전 성장 이력을 함께 저장 가능 | 초기화 메시지 전체를 사용자 잠금으로 보호. 정상 저장의 초기화 확인도 잠금 안으로 이동. 직접 스냅샷은 미완료 초기화를 예외로 거부 |
| P1 | type2 완료/type3 엘릭서 메시지가 목표 레벨까지의 성장 이력 완성 여부를 확인하지 않아 일부 이력만 가진 고레벨 캐릭터를 확정 가능 | 목표/현재/재분배 레벨 일치 및 2~목표 레벨 전체 성장 이력 확인 후 완료 처리. 미완성 요청은 HP/MP 변경 전에 거부 |
| P2 | 일반 초기화 완료에서 HP/MP를 채운 뒤 영구 스탯 배분을 복원하여 25/35/45 최대치 보너스만큼 현재 HP/MP가 부족 | 최종 영구 배분 뒤에 HP/MP 전체 회복과 알림 수행 |

## 재현과 검증

`logs/recheck-before.log`에는 이전 통합본에서 네 개의 독립 재현이 실패한 결과가 있습니다. 수정 후 동일 문제의 검사와 추가 메시지 경로 검사는 `logs/recheck-test.log`에서 통과했습니다. 기존 검사만 반복하지 않고 실제 CharacterTable 저장 진입점, 직접 스냅샷, 공개 초기화 메시지 핸들러까지 검사 범위를 넓혔습니다.

- Java 1,696개 전체 컴파일: 오류 0, 기존 API 제거 예정 경고 5개.
- 실제 저장 진입점과 스냅샷의 동시 실행에서 교착 없음. 저장소 대역은 실제 CharacterSnapshot을 생성하며 CacheD 실행은 제외합니다.
- 초기화 중 직접 스냅샷 거부/정상 저장 생략, 시작 표시만 있는 상태의 저장 허용을 확인했습니다.
- type2/type3의 조기 완료 요청은 기존 HP/MP/이력을 변경하지 않고 거부합니다.
- 실제 일반 완료 본문에서 영구 WIS45 복원 후 현재 MP가 최종 최대 MP까지 채워짐을 확인했습니다. 해당 검사는 이후 월드/비동기 저장 부수효과 전에 중단합니다.
- 공개 핸들러의 잠금 소유와 실제 79개 레벨업 메시지가 2~80 성장 이력을 모두 만들고 완료 조건을 통과함을 검사했습니다.
- 기존 공개 시트 7,200개 평균 대조, 360개 MP 범위/360,000회 추첨, 자연회복, 레벨 왕복/재시작, JDBC/H2 저장 및 동시 스냅샷, 마법중첩/물리 피해 검사를 재실행해 통과했습니다.
- 전체 ZIP CRC/해시/모든 소스 바이트, 이전 통합본에 diff 적용 후 동일 ZIP 내용 재현을 확인했습니다.

## 적용 및 검증 범위

전체 src ZIP은 기존 IOCP·스레드풀·마법·물리·HP/MP 수정을 모두 포함합니다. **기존 `RKern_HPMP_GROWTH_20261112.sql`이 필요하며, 이미 적용한 DB는 다시 실행하지 않습니다. 추가 SQL은 없습니다.** 이전에 SQL을 적용하지 않았다면 서버 종료와 DB 백업 후 한 번 적용하고 UTF-8/Java21 및 기존 FFM 옵션으로 재빌드합니다.

운영 DB는 접속하거나 수정하지 않았습니다. Windows 실게임, 운영 MySQL/CacheD 데몬, 실제 초기화 UI부터 저장/재접속까지의 통합 동작과 운영 부하는 미검증입니다. H2의 기존 MySQL IF 식 어댑터와 테스트 환경 대역은 이전 검증 안내와 같습니다. 공개 연구 시트와 일치한다는 결과를 NC 본서버 재현율로 해석하지 않습니다. 과거 성장 이력이 없는 캐릭터의 기준점 아래 수치 보존 정책도 이전 버전과 같습니다.
