# MJBin 구버전 Ctrl 2회 자동공격 이식 조사 (2026-11-13)

자료: 사용자 제공 MJ 프리서버 `mjlin.bin` / 복호화 코드 덤프 (`mjlin_loaded_code_00400000_0180D000.bin`, PE32 x86, VA 기준). **정적 디스어셈블리만 수행.**

## 1. Ctrl 입력 2회 판정 — 원본 기계어 확인

키 입력 처리 함수: `0x00A88790`.

- `0x00A8881F–0x00A8883C`: 입력 플래그 `0x4000`과 Ctrl 관련 입력 코드 `0x1011`을 사용하여 일시적인 공격 모드 `0x015D8E4F`를 갱신.
- `0x00A88852–0x00A88868`: 캐릭터 컨텍스트 `[eax+0x2D4]` 카운터를 최댓값 **2**까지만 증가시키거나 0으로 초기화.
- `0x00A8887E`: 처리 메시지 `0x101` 확인 (`WM_KEYUP` 값에 대응). 코드 문맥상 Ctrl 키 해제 시점 판정.
- `0x00A88898–0x00A888A6`: 현재 시각과 `[eax+0x2D0]` 저장 시각 차이 비교. `cmp ecx,0x1F4` / `jae 0xA88924`로 **500ms 미만**의 조건.
- `0x00A888AD–0x00A888B4`: `[eax+0x2D4] >= 2` 확인.
- `0x00A888B6–0x00A888BD`: 별도 잠금/제한 플래그 `[0x015D9879]` 검사. 구체적인 사용자 상황별 의미는 미확정.
- `0x00A888D2–0x00A888FF`: 현재 `0x015B38BE` 플래그를 반전하여 `0x00965230` 또는 `0x00EB0D20` 호출.
- `0x00A88904–0x00A8891F`: 카운터·타임스탬프 초기화. `0x00A88924–0x00A88929`: 윈도우 미충족 분기에서 타임스탬프 저장.

판정 의사코드 (추출된 분기를 표현, 원본 소스코드 아님):

```text
Ctrl down:
    pressCount = min(2, pressCount + 1)
Ctrl up:
    if (now - previousTime < 500ms && pressCount >= 2 && !blocked):
        setAttackMode(!attackMode)
        pressCount = 0
        previousTime = 0
    else:
        previousTime = now
```

구체적인 카운터 변경은 `0x1011`, `0x101`, `0x4000`의 조합에 의존하므로 이 의사코드를 단독 키 이벤트 핸들러로 복사하면 모든 상황이 같다고 보장되지 않는다.

## 2. 상태 전환 함수와 2개 구현 경로

`0x00965230`:
```asm
0x00965233 mov al, byte ptr [ebp+0x8]
0x00965239 mov [0x015B38BD],al
0x0096523E mov [0x015B38BE],al
```
즉 새 모드를 **두 전역 상태값**에 기록. UI/관련 메시지까지 후속 처리.

`0x00EB0D20`:
```asm
0x00EB0D23 mov al, byte ptr [ebp+0x8]
0x00EB0D2B mov [esi+0x10],al
0x00EB0D2E mov [0x015B38BD],al
0x00EB0D33 mov [0x015B38BE],al
```
다른 클라이언트 객체 경로에서도 동일한 전역 상태값을 변경하고 `0x13A3/0x13A4` UI 상태를 변경.

## 3. 전투 조건 두 종류를 정확히 분리

`EnemyAttackConditionAttackMode`, 판정 메서드 `0x0094B2D0`:
```asm
mov al, byte ptr [0x015D8E4F]
ret 4
```
**현재 Ctrl 공격 모드 입력 상태**를 읽을 뿐, 반복 자동공격 루프는 아님.

`EnemyAttackConditionPvpAttack`, 래퍼 `0x0094B3C0`:
대상 포인터를 `0x0094A1A0`으로 전달.

`0x0094A1A0`은 우선 객체 가상함수 `vtable[0x80]`로 구분값을 얻고, `0x015B38BE`(위 두 번 Ctrl로 전환되는 모드)을 검사. 켜진 경우 `0x00B984B0`, 구분값 `2/3`, 소속·이름 비교 등을 사용해 PvP 대상 허용 여부를 계산한다. **어떤 구분값이 실제로 어떤 캐릭터 유형을 나타내는지는 추가 추적 필요.**

`0x0094A950`에서도 **두 번째 전역 상태값 `0x015B38BD`**를 읽어 대상 필터를 변경하는 별도 분기가 있음.

## 4. 자동공격 대상 지정 이벤트

MSVC RTTI `SetAutoAttackTargetEvent@Lineage` TypeDescriptor `0x0157D428`, vtable `0x011E3964`.
생성자 `0x0092F380`:
- `[esi+0x8]`에 대상 ID/핸들로 추정되는 인자를 저장
- `[esi+0xC]`에 별도의 bool 인자를 저장

`0x00A31F90`:
- 0x10바이트 이벤트 객체를 할당하고 `0x0092F380`으로 생성
- `0x00A2EAE0`, `0x00E71780`을 거쳐 이벤트 등록/전달
- `[ebx+0x274]`에 대상 인자를 유지

`0x00A31F90` 직접 호출 지점 15곳을 확인: `0x68DB2B`, `0x68E0C6`, `0x9BD7C2`, `0xA82ED1`, `0xAD786E`, `0xADFB7C`, `0xAE783F`, `0xB9EBB4`, `0xB9F4DD`, `0xB9F9B8`, `0xEC93C6`, `0xEC94A0`, `0xEC954B`, `0xEDA13B`, `0xEDA1A4`.

**이 이벤트가 실제 공격 패킷을 재발행하는 소비자와 연결되는 완전한 호출망은 아직 확정하지 않았다.** 단순히 위 이벤트를 구버전에서 생성하는 것만으로 반복 공격이 구현된다는 증거는 아직 없다.

## 5. 구버전 이식 경계

1. **입력 게이트**: Ctrl 두 번, 500ms 미만, 다른 입력 상태 및 제한 검사.
2. **모드 영속**: `0x015B38BD/BE`처럼 'Ctrl 누르는 동안'의 임시 플래그와 구별되는 유지 상태 관리.
3. **타겟 검증**: `EnemyAttackConditionAttackMode`와 `PvpAttack`을 혼동하지 말고 모드 ON 시 PvP 필터 변화 적용.
4. **공격 실행**: `SetAutoAttackTargetEvent`의 소비자 및 실제 공격 반복/중지 전이를 구버전 코드에서 확인해 연결.
5. **종료 조건**: 대상 소멸·사망·이동 불가·무기 해제·UI 모드 OFF·로그아웃 등을 검증.

`AutoAttackCastSpell`이라는 별도의 RTTI도 존재하지만 이는 자동공격 물리 타격의 반복 루프와 동일하다고 단정할 수 없음.

### 검증 상태

- **확정**: 2회 Ctrl / 500ms 비교 / 2개 모드 상태값 / PvpAttack 하위 함수의 상태참조 / 타겟 이벤트 생성·게시.
- **미확정**: 자동 타격 주기, 패킷 직렬화·재송신 호출 경로, 공격 대상 변경과 취소의 정확한 전이, 특정 구버전에서의 이식 가능 API.
