# MJBin 2019 Ctrl 두 번 자동공격 — 구버전 클라이언트 DLL 이식 통합 기술 보고서

- 작성일: 2026-11-13
- 목적: **신버전 MJBin에서 확인된 Ctrl 2회 자동공격 기능**을 구버전 리니지1 클라이언트에 32비트 DLL로 연결하기 위한 분석 근거와 이식 계획 기록.
- 대상: 사용자 제공 **MJ 프리서버 측** mjlin.bin 및 런타임 메모리 덤프. **NC 정식 본서버 실행 파일이라고 단정하지 않는다.**
- 분석 형태: x86 정적 디스어셈블리. 실제 구버전 클라이언트에 DLL 삽입·후킹, 전체 공격 반복 실행, 실게임 접속 테스트는 수행하지 않았음.
- 결론: **Ctrl 2회 / 500ms / 공격 모드 유지 / PvP 필터 참조 / 타겟 이벤트 발행 경로는 확인. 그러나 자동공격 반복 실행기를 완전히 분리한 상태는 아니다.** 구버전에 DLL 연결은 설계 가능하지만 완성·호환성 검증 전이다.

## 1. 전체 구조: 무엇이 자동공격을 만드는가?

~~~text
[클라이언트 입력 이벤트]
          │
          ▼
0x00A88790  Ctrl 관련 입력 및 시각/횟수 검사
          │
          ├── 500ms 미만, 카운트 >= 2, 추가 제한 통과
          ▼
0x00965230 또는 0x00EB0D20   토글 상태 변경
          │
          ├── 0x015B38BD : 유지 모드 플래그 #1
          └── 0x015B38BE : 유지 모드 플래그 #2
                    │
                    ├── 0x0094A1A0 : PvP 타겟 조건 분기
                    └── 0x0094A950 : 별도 타겟 필터 분기

[타겟 선택 이벤트 — 별도 연결 경로]
0x00A31F90 → new 0x10-byte SetAutoAttackTargetEvent
               → 0x0092F380 생성
               → 0x00A2EAE0 → 0x00E71780 이벤트 게시
               → 타겟 관련 필드 +0x274 기록
               → [이벤트 소비자 / 실제 공격 반복 / 취소] **미확인**
~~~

**핵심 구분:**
1. 단순 **Ctrl 누름 상태**와 **Ctrl 두 번으로 토글되어 유지되는 모드**는 다르다.
2. **PvpAttack 타겟 조건**과 **타겟 이벤트**는 다른 역할이다.
3. 이벤트가 존재한다고 그 자체로 타격 패킷 재전송 루프의 구현이 증명되지는 않는다.
4. **PSS 사냥 BotConductor**와 **Ctrl 두 번 자동공격 모드**를 동일 시스템으로 가정하지 않는다.

## 2. Ctrl 두 번 감지: 기계어 단위 검증

진입 함수 **0x00A88790**. 의미 있는 분기 및 값:

| VA | 실측 명령/분기 | 의미 |
|---|---|---|
| 0x00A88824 | and eax, 0x4000 | 현재 입력 상태의 플래그 검사 |
| 0x00A8882B / 0x00A8883A | mov byte [0x015D8E4F], 1 / 0 | 임시 공격 모드 플래그 ON/OFF |
| 0x00A88832 | cmp edi, 0x1011 | 내부 입력 식별자 검사 |
| 0x00A88852 | cmp dword [eax+0x2D4], 2 | 카운트 최대 2 조건 |
| 0x00A88860 | inc dword [eax+0x2D4] | 입력 카운트 증가 |
| 0x00A8887E | cmp dword [ebp+0x10], 0x101 | Win32 WM_KEYUP에 해당하는 메시지 값 검사 |
| 0x00A8889A | sub ecx, [eax+0x2D0] | 이전 기준 시각과의 차이 |
| 0x00A888A0 | cmp ecx, 0x1F4 | 500ms 비교 |
| 0x00A888A6 | jae 0x00A88924 | **500ms 이상이면 토글 분기 건너뜀** |
| 0x00A888AD | cmp dword [eax+0x2D4], 2 | 카운트 >=2 조건 |
| 0x00A888B6 | cmp byte [0x015D9879], 0 | 추가 제한 상태 |
| 0x00A888D2 | cmp byte [0x015B38BE], 0 | 현재 유지 모드 |
| 0x00A888D9 | sete al | 유지 모드 반전 값 계산 |
| 0x00A888E0 | call 0x00965230 | 상태 전환 경로 1 |
| 0x00A888FF | call 0x00EB0D20 | 상태 전환 경로 2 |
| 0x00A88904..1F | 카운트/시각 0으로 저장 | 조건 처리 후 입력 상태 초기화 |
| 0x00A88924..29 | 새 기준 시각 저장 | 시간 창 조건 미충족 처리 |

직접 확인한 핵심 명령:

~~~asm
0x00A88898  mov ecx, esi
0x00A8889A  sub ecx, dword ptr [eax+0x2D0]
0x00A888A0  cmp ecx, 0x1F4
0x00A888A6  jae 0x00A88924
0x00A888AD  cmp dword ptr [eax+0x2D4], 0x2
0x00A888B4  jl 0x00A88904
0x00A888B6  cmp byte ptr [0x015D9879], 0x0
0x00A888BD  jne 0x00A88904
0x00A888D2  cmp byte ptr [0x015B38BE], 0x0
0x00A888D9  sete al
~~~

**정확한 경계는 500ms '이내(<=)'가 아니라 500ms '미만(<)'**이다. **0x1011은 이 클라이언트 내부의 입력 구분 코드**로 취급해야 하고, Win32 VK_CONTROL이라고 섣불리 등치하지 말 것. 실제 입력 핸들러가 어떤 플래그와 메시지를 조합하는지도 이식 시 보존해야 한다.

### 복원 의사코드 (실제 NC/MJ C++ 소스 아님)

~~~cpp
// 2019 이미지에서 관찰한 조건을 요약한 개념적 의사코드
onClientInput(event):
    updateTemporaryCtrlAttackMode(event)
    updateDoublePressCounter(event) // internally limited to 2
    if (event.internalId != 0x1011 || event.message != 0x101):
        return
    elapsed = nowMillis - previousTimestamp
    if (elapsed >= 500):
        previousTimestamp = nowMillis
        return
    if (count < 2 || additionalBlockFlag != 0):
        clearDoublePressState()
        return
    setPersistentAutoAttackMode(!currentPersistentAutoAttackMode)
    clearDoublePressState()
~~~

초기 시각이 0일 때의 호출 순서, 타이머 원천 및 타 이벤트로 카운트가 초기화되는 조건까지 완전한 동일 실행을 보장하는 코드는 아님.

## 3. 공격 모드의 세 상태값

| 주소 | 코드 출처 | 역할 |
|---|---|---|
| 0x015D8E4F | 0x0094B2D0 등 | **일시적 Ctrl 공격 모드** |
| 0x015B38BD | 0x00965230 / 0x00EB0D20 | **토글 후 유지 플래그 A** |
| 0x015B38BE | 0x00965230 / 0x00EB0D20 | **토글 후 유지 플래그 B** |

**0x00965230**에서 직접 관찰한 기록:

~~~asm
0x00965233  mov al, byte ptr [ebp+0x8]
0x00965239  mov byte ptr [0x015B38BD], al
0x0096523E  mov byte ptr [0x015B38BE], al
~~~

**0x00EB0D20**에서도 같은 두 전역 주소에 새 상태를 저장한다. 추가로 자기 객체의 +0x10 필드를 갱신하고, **0x13A3/0x13A4** UI 값과 연동되는 코드가 확인됨.

구버전 이식 시 Ctrl 누르고 있는 동안의 공격 허용(PK 강제 공격 등)과, Ctrl을 놓은 후 유지되는 자동공격 토글을 **같은 bool 하나로 처리하면 동작이 달라질 수 있다**.

## 4. EnemyAttackConditionAttackMode

확인 함수: **0x0094B2D0**

~~~asm
0x0094B2D0  mov al, byte ptr [0x015D8E4F]
0x0094B2D5  ret 4
~~~

- **[기계어 확인]** 전역 임시 공격 모드의 byte 값을 반환한다.
- 자체적으로 공격 대상 저장, 공격 시작, 반복 타격이나 네트워크 패킷 송신을 수행하지 않는다.
- 따라서 이 함수를 구버전 DLL로 복사해도 'Ctrl 두 번 자동공격'이 구현되는 것은 **아니다**.

## 5. EnemyAttackConditionPvpAttack

래퍼 함수: **0x0094B3C0**

~~~asm
0x0094B3C3  mov eax, [ebp+8]
0x0094B3C6  add ecx, 4
0x0094B3C9  push dword ptr [eax]
0x0094B3CB  call 0x0094A1A0
~~~

**하위 판정 0x0094A1A0**:

1. 대상의 vtable **+0x80** 위치의 함수를 호출해 구분값을 얻는다.
2. **0x015B38BE**의 유지 모드를 검사한다.
3. 모드 값과 **0x00B984B0**의 결과, 구분값 **2 / 3**에 따라 분기한다.
4. 한 경로에서는 대상과 현재 사용자/컨텍스트의 문자열을 바이트 단위로 비교한다.
5. 서로 다른 문자열 비교 결과 등 특정 조건에서 **AL=1**, 나머지 경로에서 **AL=0**을 반환한다.

확인된 명령 예시:

~~~asm
0x0094A1AC  mov eax, [eax+0x80]
0x0094A1B2  call eax
0x0094A1B4  cmp byte ptr [0x015B38BE], 0
0x0094A1C1  call 0x00B984B0
0x0094A1CA  cmp bl, 3
0x0094A1CF  cmp bl, 2
0x0094A21B  mov al, 1
0x0094A223  xor al, al
~~~

**주의: 반환 AL=1이 '공격 가능'인지, 조건 충족/배제 후보인지는 상위 조건 집합의 AND/OR·반전 경로를 끝까지 봐야 정확히 확정할 수 있다.** 객체 분류값 2·3의 구체적 의미도 아직 미확인이다. 함수를 단순히 '모드가 켜져 있으면 모든 PC 공격 허용'이라고 구현하면 안 된다.

**0x0094A950**에서도 나머지 플래그 **0x015B38BD**를 확인하는 별도 타겟 필터 분기가 있다. 구버전으로 복원할 때 두 플래그의 의미를 분리 추적해야 한다.

## 6. SetAutoAttackTargetEvent — 지정과 게시

- RTTI 타입: **SetAutoAttackTargetEvent@Lineage**
- TypeDescriptor: **0x0157D428**
- vtable: **0x011E3964**
- 이벤트 생성자: **0x0092F380**
- 대상 이벤트 생성·게시 함수: **0x00A31F90**

**0x0092F380** 생성자 구조에서 +0x8에 전달 인자를, +0xC에 추가 bool 인자를 저장하는 코드를 확인함. 첫 인자는 문맥상 **타겟 식별자/핸들 유력**, 구체적 타입은 미확정.

**0x00A31F90**이 하는 일:

~~~text
대상 인자 확인
    └─ 0x10 바이트 객체 할당
        └─ 0x0092F380 생성자 호출
            └─ 0x00A2EAE0 래핑/전달 준비
                └─ 0x00E71780 이벤트 전달
                    └─ 호출자 객체 [ebx+0x274]에 대상 인자 저장
~~~

이벤트 전달 전후에 참조 카운트/정리 코드가 있어 객체 수명도 함께 관리된다. **구버전에서 그냥 이벤트 포인터를 저장하거나 가상함수를 복사하는 방식은 위험하다.**

직접 확인했던 **0x00A31F90 호출 위치 15곳**:

- 0x0068DB2B, 0x0068E0C6
- 0x009BD7C2
- 0x00A82ED1
- 0x00AD786E, 0x00ADFB7C, 0x00AE783F
- 0x00B9EBB4, 0x00B9F4DD, 0x00B9F9B8
- 0x00EC93C6, 0x00EC94A0, 0x00EC954B
- 0x00EDA13B, 0x00EDA1A4

**[미확인]** 이벤트를 실제로 소비하는 함수 및 공격 반복 트리거, 타겟 해제 통지, 네트워크 공격 명령 생성 위치. 해당 부분이 구버전 DLL 이식 완성의 가장 큰 공백이다.

## 7. AutoAttackCastSpell, PSS BotConductor와 혼동 금지

**AutoAttackCastSpell** RTTI가 존재한다는 사실과, 물리 일반공격을 반복시키는 동작은 같은 것이 아니다. 스킬 자동 발동 클래스라는 이름만으로 공격 루프라고 판단할 수 없음.

PSS 측 **BotConductor::Next(0x00669B20)**, BotSearchMonsterNode, BotWalkTargetNode, BotAttackNode 등은 플레이서포트 자동사냥의 행동 노드 구조이다. Ctrl 2회로 지정 대상 자동공격하는 **UI 공격 모드와 범위/목적이 다르다.**

             │ Ctrl 2회 / 500ms 미만
             ▼
          [모드 상태 전환/화면 표시]
             │
             ▼
          [기존 클라이언트 타겟 객체 조회]
             │
             ▼

             │
             ▼

             │

             ├─ 타겟 변경·사망·거리·맵·무기 변화
             └─ 모드 OFF / 취소
                    │
                    ▼
            [서버 권위의 전투 처리]
~~~

### DLL에서 맡을 책임

1. **x86 클라이언트 프로세스와 동일 아키텍처**로 빌드. 64비트 DLL은 x86 클라이언트에 직접 로드 불가.
2. 기존 클라이언트의 **입력/메인 이벤트 처리 흐름**에 Ctrl 두 번 토글을 연결. 독립 키 폴링 스레드로 기존 입력과 경쟁시키지 않음.
3. 기존 클라이언트의 **현재 타겟, 대상 유효성, 공격 준비상태, 공격 재사용 타이밍**을 찾아 재사용.
4. 기존 **공격 전송 함수**에 명령을 전달하되 서버 검증과 기존 속도 제약을 우회하지 않음.
5. 모드 OFF, 사망, 타겟 소멸, 맵 전환, 로그아웃, 클라이언트 종료 시 안전히 중단하고 참조 해제.
6. 게임 클라이언트 내부 함수 호출은 **실제 구버전의 thiscall/cdecl/stdcall, 구조체 정렬, 이벤트 소유권**을 확인한 이후 적용.

### 하지 말아야 할 것

- MJBin 함수의 일부 기계어만 복사해 독립 DLL이 된다고 가정.
- 반복 공격 루프를 **공격 속도 임의 상수**로 생성하거나 타이머마다 패킷을 과다 전송.
- PvP 필터에서 단일 bool만 보고 안전지대/파티/혈맹/공성 관계를 무시.
- DllMain 내부에서 긴 작업, 후킹 초기화, 스레드 작업을 모두 수행.
- 서버의 실제 데미지·HP·공격 쿨다운 결정권을 클라이언트 DLL로 옮김.

## 9. 구버전에서 찾아야 할 정확한 대응 함수

| 우선순위 | 구버전 분석 대상 | 왜 필요한가 |
|---|---|---|
| P0 | 윈도우 키 입력/게임 입력 디스패처 | Ctrl 토글의 정확한 전달 위치 및 중복 처리 방지 |
| P0 | 현재 공격 대상 설정/해제 함수 | 마우스 선택·타겟 변경·타겟 초기화 |
| P0 | 일반 공격 실제 실행 및 패킷 송신 연결 | **지정 대상에 대해 공격이 반복되는 핵심 경로** |
| P0 | 자동공격 모드 종료/정지 이벤트 | 공격 중지·상태 복원·과잉 전송 방지 |
| P1 | PC/NPC/펫/서먼 구분 및 PvP 조건 테이블 | 필터 원본 의미와 구버전 객체 구조 대응 |
| P1 | 공격 애니메이션, 재사용 타이밍, 공격 상태 변수 | 서버와 속도·행동 충돌 방지 |
| P1 | 유저 사망·맵 이동·로그아웃 이벤트 | 수명·메모리 안전 |
| P2 | 버튼 표시/단축키 UI 문자열 | Ctrl 토글의 시각적 피드백 |

구버전 바이너리에서 위 주소/호출 규약을 찾기 전에는 **“그냥 DLL만 연결하면 자동공격이 된다”는 검증된 결론을 내릴 수 없다.**

## 10. 안전한 개발 순서

**1단계 — 차이 분석**: 같은 조건에서 2019 MJBin과 구버전의 입력·공격 함수 흐름을 비교. 구버전에 원래 자동공격 루프가 있는지 없는지 확인.

**2단계 — DLL 스켈레톤**: x86 DLL 로딩, 클라이언트 버전 식별, 최소 후킹/콜백 연결과 원상 복구만 검증. 공격 기능은 아직 활성화하지 않음.

**3단계 — Ctrl 모드**: 임시 Ctrl 입력과 토글 모드를 분리, 2회/500ms 미만, 3번째 입력, 입력 취소, UI 반영 검증.

**4단계 — 타겟 이벤트**: 기존 게임 타겟 설정/해제 함수 재사용, 잘못된 포인터·객체 소멸·세션 전환 처리.

**5단계 — 공격 실행 및 정지**: 기존 클라이언트 공격 처리에 연결해 타이밍을 유지. 서버의 유효성 및 속도 판정은 그대로 유지. 공격 실행에 새로운 별도 네트워크 프로토콜이나 우회 패킷을 만들지 않음.

**6단계 — 회귀 테스트**: 타겟 다수, 범위 밖, 타겟 사망, PvP, Ctrl 유지, 모드 해제, 버전 간 주소/구조체 차이, 장시간 반복 후 종료/재실행.

## 12. 남은 역분석 / 완성 기준

**최상위 미완료 작업은 아래 3가지**:

1. **0x00E71780에서 SetAutoAttackTargetEvent의 최종 소비자까지 추적**: 어떤 객체에서 어떤 타겟 상태가 어떻게 바뀌는가.
2. **실제 일반 공격 명령 진입점·실행 주기·중지/재시도 분기 확인**: 유지 모드 ON에서 공격 입력과 패킷 경로가 어떻게 달라지는가.
3. **구버전 클라이언트 바이너리 확보 후 대응 함수 비교 및 연결 테스트**: 버전별 이벤트 ABI/상태값/호출 규약 확인.

이 3가지가 검증되어야 자동공격 DLL을 **완성했다**고 말할 수 있다. 현재는 **구현할 수 있는 정적 설계 근거를 확보한 단계**이다.
