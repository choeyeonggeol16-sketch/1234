# RKern 스킬 습득 구조 적용 및 검증

기준 통합팩은 `d3e1381c`이고, 구현 지시서는 `98ef99ee`에서 가져왔다. 신설 패키지는 `l1j.server.server.model.character.skill.acquire`이다. 공성, 주거, 출석, 버프, 기존 DB 설치본은 같은 통합 브랜치에 포함되어 있다.

## 적용 경로

| 기존 경로 | 적용 후 |
| --- | --- |
| `SkillsTable` 정의 로딩과 조회 | `CSkillDB`의 불변 정의와 primitive ID 조회. `L1Skills`는 SQL 정의, 기존 `CSkillInfo`는 런타임 효과를 담당한다. 정의와 습득 인덱스는 함께 교체되며 리로드 실패 시 이전 버전을 유지한다. |
| 클래스별 NPC 목록, 일반·클래스별 마법서, 전사 인장 | `CSkillAcquireDB`의 클래스·단계 비트마스크와 아이템 ID 인덱스. 항목 이름 기반으로 등록되던 책은 기존 이름 일치 정책도 유지한다. |
| `SkillCheck`, `L1PcInstance.skillList`, `spellCheck` | 공통 크리처인 `L1Character`의 `AcquireSkill`, `DeleteAcquireSkill`, `HaveSkill`, `GetAcquiredSkillLevel`. 정렬된 불변 `int[]` 스냅샷 한 개를 읽는다. 레거시 전역 맵과 캐릭터 보유 리스트를 제거했다. |
| NPC 구매와 호룬 교환, 마법서, GM 스킬마스터 | `CSkillAcquisition`, `CSkillBook`, `CSkillMaster`가 기존 CacheD receipt에 작업을 등록한다. 재화 및 영구 습득 행을 함께 커밋하고 원래 세션의 CIO에서 공개한다. |
| 재접속, 생성, 캐릭터 삭제와 직업 변경 | 영구 스킬 SQL을 `CSkillAcquireStorage`로 모았다. 로그인은 한 번의 SELECT로 ID를 복원하고 기존 패킷 슬롯 규칙을 쓴다. 전직은 변경권과 직업 정보, 영구·패시브 스킬, 착용 상태를 한 receipt에서 처리한다. 장비 효과 제거는 착용 당시 클래스를 기준으로 한다. |
| 장비·혈맹·변신·패시브 | 영구 습득의 출처로 혼합하지 않는다. 마법 투구가 제공하는 시전을 허용하고, 해제할 때 겹치는 영구 스킬은 보존한다. 혈맹·변신 조건, 상태효과 및 패시브의 별도 데이터 경로를 유지한다. |
| GM 조회와 캐릭터 컬렉션 | 접속 캐릭터의 GM 조회는 보유 스냅샷을 읽는다. 보관 캐릭터의 컬렉션은 DB 로더에서 공통 영구 읽기를 사용한다. 기존 GM 일괄 지급 명령은 접속 캐릭터용이다. |

NPC 정상 요청의 기존 클래스·레벨, 비용, 호룬 1단계 반복 비용과 상위 단계 처리, 스킬 패킷의 슬롯과 속성 인코딩을 유지했다. 동일 선택 중복은 한 건으로 처리하고 잘린 교환 요청에서는 차감하거나 습득하지 않는다. 구매 시 이미 배운 스킬은 비용에 포함하지 않는다.

`Net.sql` 설치 후 아이템 로더 검증에서 PSS 설정 아이템 `900000901`의 기본 옵션 행이 빠진 것을 발견했다. 설치 데이터의 옵션값을 확인해 `etc-item-base.txt`에 등록했다. ETC 4,418종과 장비 1,773종의 필수 행을 대조했다. `character_skills`는 InnoDB이며 기본 키는 `(char_obj_id, skill_id)`다. DB 스키마와 SQL 설치본은 그대로 사용했다.

## 검증

- OpenJDK 21.0.13에서 전체 생산 Java 코드를 의존성과 함께 컴파일했다.
- `Net.sql`을 격리된 MariaDB에 설치해 259개 테이블과 스킬 정의 872건을 읽었다. 주요 습득 및 삭제 테이블의 InnoDB 엔진과 기본 키를 확인했다.
- `SkillAcquisitionRegression`은 실제 TCP 연결과 CIO, CacheD, MariaDB로 실행했다. 정의 재로딩 실패, 보유 조회와 외부 읽기 경쟁, 마법서 계열과 전사 인장, NPC 클래스 경계와 가격, 중복 요청과 중복 SQL 행, 비용 부족, 호룬 부분 구매, 영구 스킬과 장비 출처 중첩, GM 일괄 지급, 직업 변경 rollback 및 성공, 원래 세션 종료와 DB 복원 상태를 검증했다.
- 로그인 hydration, 스킬 범위, SPR 타이밍, 인벤토리 인덱스, 파티, 월드 등록 및 가시성, 공성, 인스턴스 종료, 출석, 버프, 아지트 회귀를 실행했다. MariaDB에서 별도로 출석·버프·아지트, CacheD 입장·receipt 중복 방지·인벤토리 로딩 및 창고의 접속 종료를 확인했다. 스탯 초기화 촛불 테스트는 운영 코드와 같은 월드 위치 등록과 캔슬레이션 정의를 제공한 뒤 개인·NPC 경로 모두 통과했다.

## 조회 부하 측정

5,000명의 합성 보유자에게 동일한 ID와 50% 적중 요청을 사용했다. 레거시는 두 목록과 기존 `CYieldLock`을 재현했다. 4,096개 조회의 묶음 300회에서 호출당 CPU와 묶음 평균의 지연 백분위를 계산했다. 박싱 캐시에 없는 ID를 사용했다. 단위는 ns이며 힙 수치는 별도 JVM에서 GC 후 같은 보유자 기본 상태를 뺀 MiB다.

| 캐릭터당 스킬 수 | 조회 CPU 기존 → 적용 | p95 기존 → 적용 | p99 기존 → 적용 | 추가 힙 기존 → 적용 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 45.9 → 3.3 | 62.0 → 3.3 | 89.5 → 7.3 | 작은 증가량은 GC 측정 오차 범위 |
| 32 | 74.8 → 13.3 | 96.2 → 17.3 | 292.5 → 48.7 | 6.92 → 0.43 |
| 128 | 222.8 → 19.8 | 267.0 → 23.7 | 441.0 → 41.5 | 26.58 → 2.27 |
| 256 | 298.9 → 23.7 | 368.1 → 30.4 | 404.6 → 46.7 | 53.85 → 4.74 |
| 872 | 2444.5 → 44.7 | 2835.8 → 66.4 | 5012.1 → 81.5 | 181.42 → 16.50 |

조회 할당은 합성 조건에서 16 B/회에서 0 B/회로 줄었다. 단건 습득·삭제는 스냅샷 복사를 하므로 보유량에 따라 쓰기 할당이 증가한다. 스킬 128개 조건에서 습득과 삭제 1쌍은 48 B에서 1,064 B, 457.4 ns에서 645.6 ns로 측정됐다. 묶음 습득과 로그인 복원은 스냅샷을 한 번에 반영한다.

NPC와 캐릭터의 실제 운영 분포, 실클라이언트 화면, 운영 중 전체 서버 초기화 및 운영 규모의 CIO 지연은 별도 환경이 필요하다. 위 수치는 합성 부하 결과이며, 실제 운영 캐릭터당 보유 스킬 최대 수는 이 설치본으로 산정할 수 없다.
