- 작성일: **2026-11-11**
- 대상: **RKern/L1J (Java 21)** — 연구·설계 문서. **현재 서버 소스에는 이 문서의 새 통합식을 적용하지 않았음.**

## 1. 기호 정의 및 공격·방어 주체

| 기호 | 정의 | 소유자/주의 |
|---|---|---|
| `D` | 이번 타격에 이미 결정된 마법 다이스/기초 위력 값 | 공격 스킬; 평균치가 아니라 **타격별 실제 굴림** |
| `INT` | 연구식에 투입할 INT 값 | 공격자 |
| `SP` | 연구식에 투입할 SP 관련 값 | 공격자; 표시 SP를 무턱대고 더하면 중복될 수 있음 |
| `MB`, `ML` | 2016년 원식에 남아 있는 보정 인자 | 정의와 실제 RKern 통계/버프 매핑은 소스·원문 재검증 필수; 이름만 보고 의미 확정 금지 |
| `ER` | 해당 마법 속성에 대한 저항 **퍼센트** | 방어자; 불/물/바람/땅 중 **해당 속성만** 선택 |
| `Class` | 방어자의 클래스 기본 계수 | **공격자 클래스가 아님** |
| `WIS` | 방어자 WIS | 방어자 |
| `MR` | 방어자 마법 저항 | 방어자 |
| `MH` | 공격자 마법 적중 | 공격자 |
| `MD` | 별도의 추가 마법 피해 항목 | 공격자/스킬 효과; 바깥 덧셈의 적용 여부는 스킬별 확인 |
| `DR` | 최종 피해 감소 | 방어자 |
| `floor(x)` | 수학적 내림: `⌊x⌋` | 음수 입력 시 Java `(int)` 절단과 다름 |
| `floor2(x)` | 소수 둘째 자리까지 버리고 내림: `floor(x*100)/100` | 계수마다 **중간 절삭**을 시행해야 함 |

**INT/SP/MB/ML 정의는 구현 전 확정해야 한다.** `getSp()`가 이미 INT/레벨 유래 수치를 포함한다면 단순히 `INT+SP`로 입력하면 두 번 더해질 수 있다. 기존 `getTrueSp()`, 마법 보너스, 아이템 추가 SP, 레벨 보정 등의 호출 경로를 실제 코드로 조사한다.

## 2. 2016년 일본 마법 데미지 잠정식 [2016 잠정]

일반 타격:

```math
Damage_{2016}=\left\lfloor\left\lfloor D\times A\right\rfloor\times B\right\rfloor+MD-DR
```

크리티컬 타격(크리티컬 적용 단계가 **MR 적용 전**에 위치):

```math
Crit_{2016}=\left\lfloor\left\lfloor\left\lfloor D\times A\right\rfloor\times1.5\right\rfloor\times B\right\rfloor+MD-DR
```

INT·SP 증폭 계수:

```math
A=\operatorname{floor2}\left(1+\frac{3}{32}(INT+SP-MB-ML-12)\right)
```

방어자 클래스·WIS 계수:

```math
C=Class-0.02\times\left\lfloor\frac{WIS}{2}\right\rfloor
```

MR 감소 계수:

```math
B=\operatorname{floor2}\left(C\times(MR-MH)^{-0.3}\right)
```

**적용 범위:** `MR-MH >= 10` 영역의 잠정 근사식으로 기록한다. `MR-MH`가 9에서 10으로 넘어갈 때, 또는 0 이하에서 음수의 `-0.3` 거듭제곱이 발생하는 경우에는 무조건 `Math.pow`를 호출하지 않는다. `max(10, MR-MH)`로 슬쩍 올려버리는 것도 근거 없는 규칙 추가다. **저MR 경계는 독립 실측 후 결정하거나 기존 검증된 처리 경로를 유지**한다.

### 2.1 방어자 클래스 기본 계수

| 방어자 클래스 | 약호 | `Class` | 정수 100배 보관 |
|---|---|---:|---:|
| 군주 | PRI | 2.30 | 230 |
| 기사 | KNI | 2.40 | 240 |
| 요정 | ELF | 2.20 | 220 |
| 마법사 | WIZ | 2.00 | 200 |
| 다크엘프 | DE | 2.20 | 220 |
| 용기사 | DRK | 2.40 | 240 |
| 환술사 | ILL | 2.20 | 220 |
| 전사 | WAR | 2.40 | 240 |

클래스 번호는 RKern의 **실제 방어자 직업 enum/클래스 ID**에 맞춰 연결해야 하며, 미확인 클래스는 임의로 기사 계수 등에 매핑하지 않는다. 신규 직업도 추가 확인 전 자동 적용하지 않는다.

### 2.2 클래스 계수와 WIS 적용 예

- 기사의 `WIS=20`이면 `C = 2.40 - 0.02 × floor(20/2) = 2.20`.
- 마법사의 `WIS=20`이면 `C = 2.00 - 0.02 × 10 = 1.80`.
- 같은 MR·MH와 다이스라 해도 **방어자** 직업·WIS에 따라 `B`가 달라진다.
- 이미 WIS 효과가 `MR` 수치에 반영되어 있더라도, 이 잠정식은 `C`에서 WIS를 별도로 사용한다. 기존 서버의 WIS 기반 마법 방어 보정을 **중복 적용하지 않도록** 해야 한다.

## 3. 2015년 속성저항 실측식 [2015 실측]

일본의 2015-09-13 속성저항 연구는 **속성저항을 MR계수에서 곱하는 방식이 아니라 INT 계수에서 차감**하는 형태를 보고했다.

```math
A_{element,2015}=\operatorname{floor2}\left(1+\frac{3}{32}(INT+\beta-12)-\frac{ER}{100}\right)
```

여기서 `INT+β`는 **당시 2015년 자료의 표기**다. 이 값을 2016년 `INT+SP-MB-ML`와 동의어로 **확정하지 않는다.** 아래 통합식에서는 2016년의 독립 계수 `A`에 속성저항 `-ER/100`을 넣는 **결합 가설**을 사용한다.

- 연구 범위에서 `ER`의 효과는 **-100% ~ +100%**로 취급한다. +100% 초과는 2015 연구 기준 추가 방어 효과가 없었다.
- 마법이 **무속성**이면 해당 원소 저항을 임의로 적용하지 않는다 (`ER=0`).
- 속성 마법 이외의 물리 속성 타격은 별도 산식으로 분리한다.
- 2015년 연구는 **PC→PC 테스트**이며 PC→NPC/NPC→PC로의 일반화는 연구자의 추정이라는 단서가 있다.
- `ER=50`은 최종 데미지의 절반이 아니라 `A`에서 **0.50**을 빼는 뜻이다.

## 4. 클래스·WIS·MR·속성저항 결합 후보 [조합 가설]

우리가 RKern에 이식하려는 **검증 후보식**:

```math
A_E=\operatorname{floor2}\left(1+\frac{3}{32}(INT+SP-MB-ML-12)-\frac{ER}{100}\right)
```

```math
C=Class-0.02\left\lfloor\frac{WIS}{2}\right\rfloor
```

```math
B=\operatorname{floor2}\left(C(MR-MH)^{-0.3}\right),\quad MR-MH\geq10
```

일반:

```math
\boxed{Damage=\left\lfloor\left\lfloor D A_E\right\rfloor B\right\rfloor+MD-DR}
```

크리티컬:

```math
\boxed{Critical=\left\lfloor\left\lfloor\left\lfloor D A_E\right\rfloor\cdot1.5\right\rfloor B\right\rfloor+MD-DR}
```

**절대 혼동 금지:** `ER`을 `B`나 `C`에서 또 차감하거나, `D*A_E*B`를 한 번에 곱한 다음 마지막에만 내림하지 않는다. `MD`를 `A_E` 내부에 섞지도 않는다. 다만 이 **통합 적용 위치·순서 전체**는 단일 원문에서 실측 확정된 것이 아니므로 테스트 전 운영식으로 교체하지 않는다.

### 4.1 순서: 타격 1회당 계산 파이프라인

1. 공격자의 스킬별 다이스를 **기존 규칙 그대로 1회 굴려서** `D` 산출(다이스 수, 고정 가산, 무기 발동 마법 여부 보존).
2. 마법의 **속성 종류**를 판별하고 대상의 해당 저항 `ER`을 확보(무속성은 0).
3. `INT/SP/MB/ML`을 올바른 소유 객체에서 조회한 뒤 `A_E`를 **소수 2자리 내림**.
4. `base = floor(D*A_E)`.
5. 크리티컬 타격이면 `base = floor(base*1.5)`; 확률·대상/스킬 자격 판정은 기존 로직 유지.
6. 방어자 클래스·WIS로 `C`, `MR-MH`로 `B` 계산; `B`는 **소수 2자리 내림**.
7. `resisted = floor(base*B)`.
8. `result = resisted + MD - DR`.
9. 최종 0/1 최소 데미지, 무적, PvP 추가 감면, 특수 실드, 반사/흡수, 다중 타격 등 **기존 RKern 후처리 정책**을 유지. 어느 단계에 들어가는지는 실제 소스로 확인하고 이중 적용을 막는다.

### 4.2 확인용 숫자 예시 (후보식; 운영 실측 보증 아님)

2016 실험 시트에서 이전 대화 중 검토한 값에 맞춘 **계수 예시**: `D=9`, 저항 0에서 `A=4.09`, `C=2.06`, `MR=73`, `MH=23`, `MD=17`, `DR=1`.

`MR-MH=50`; `B=floor2(2.06×50^-0.3)=0.63`.

| ER | `A_E` | `floor(9*A_E)` | 일반 최종값 | 크리티컬 최종값 |
|---:|---:|---:|---:|---:|
| -100 | 5.09 | 45 | 44 | 58 |
| 0 | 4.09 | 36 | 38 | 50 |
| 50 | 3.59 | 32 | 36 | 46 |
| 100 | 3.09 | 27 | 33 | 41 |

**해석:** `ER=100`이어도 `A_E`가 0이 아닐 수 있다. 속성저항 100이 곧 데미지 0이라는 뜻은 아니다. 표의 `ER≠0` 열은 **2015+2016 결합 가설로 계산한 테스트 벡터**이며 본서버 실측치는 아니다. `ER=0`의 38은 이전 대화에서 조회했던 2016 시트 사례와 대응하는 값이다(현재 세션에서 실험 시트 재조회는 별도로 수행하지 않음).

### 4.3 2016-06 추가 피해 관련 실험 [2016 별도 실측]

별도의 일본 연구 기록에서 화염저항 100%의 폭탄/메테오완드 실험:

| 상황 | 관측값 | 의미 |
|---|---:|---|
| INT+β 고정 12, MD=0, DR=0 | 0 | 기초 성분이 속성저항으로 상쇄 |
| MD=8, DR=1 | 7 | 별도 추가 피해가 저항 100 후에도 남음 |
| MD=13, DR=5 | 8 | 별도 추가 피해가 저항 100 후에도 남음 |

이 실험은 **MD가 속성저항 100으로 함께 사라지지 않는다는 점**은 지지하지만, 모든 마법에서 `MD`가 `MR`보다 항상 뒤인지까지 단독 확정하는 증거는 아니다. 따라서 2016 잠정식의 `+MD-DR` 순서를 그대로 테스트 대상으로 삼되 추가 실측을 요구한다.

## 5. Java 21 참고 구현 [RKern 설계; 서버 적용 전]

다음은 **계산 순서 비교용 순수 함수**다. 실제 서버에 새로운 객체·큐·워커를 추가하라는 뜻이 아니며, 기존 RKern 마법 데미지 계산 메서드 내부로 흡수할 후보 코드다. `MR-MH<10`에 임의 보정값을 넣지 않도록 **명시적으로 처리 대상에서 제외**한다. 게임에 직접 붙일 때는 해당 영역을 기존 검증 경로로 위임한다.

```java
// Reference only. Merge into the existing damage owner after call-chain audit.
static double floor2(double x) {
    return Math.floor(x * 100.0) / 100.0;
}

static int calculateCandidate(
        int rolledDice, int attackerInt, int attackerSp,
        int mb, int ml, int targetElementResistPct,
        int targetClassCoefficient100, int targetWis,
        int targetMr, int attackerMagicHit,
        int addedMagicDamage, int damageReduction,
        boolean critical) {

    final int effectiveMr = targetMr - attackerMagicHit;
    if (effectiveMr < 10) {
        // Never invent an MR=10 clamp; use the existing verified path.
        throw new IllegalArgumentException("MR-MH below validated range");
    }

    // 2015 elemental resistance scope. Neutral magic passes 0.
    final int er = Math.max(-100, Math.min(100, targetElementResistPct));
    final double a = floor2(1.0
            + (3.0 / 32.0) * (attackerInt + attackerSp - mb - ml - 12)
            - er / 100.0);
    final double c = targetClassCoefficient100 / 100.0
            - 0.02 * (targetWis / 2);
    final double b = floor2(c * Math.pow(effectiveMr, -0.3));

    int base = (int) Math.floor(rolledDice * a);
    if (critical) {
        base = (int) Math.floor(base * 1.5);
    }
    return (int) Math.floor(base * b)
            + addedMagicDamage - damageReduction;
}
```

**참고 구현 경계:** 이 함수는 **소수점 절삭 연구 검증용**이라 최종 0/1 클램프, 저항의 잘못된 입력 거부, 계수/스탯 범위 검증, 오버플로 처리, 스킬별 예외, 캐릭터 클래스 ID 매핑을 의도적으로 포함하지 않는다. 서버 통합 시에는 실제 규칙에 따라 처리해야 한다.** Java 부동소수점의 표현 오차가 0.01 임계값을 건드리는지 BigDecimal/실측 oracle로 비교한다. 무턱대고 `epsilon`을 더해 맞추지 않는다.

**핫패스 성능:** 실제 부하에서 `Math.pow`가 비싸면 `effectiveMr`의 유효 범위에 대해 **정적 primitive `double[]` 역수 계수 테이블**을 사전 계산해 `C * powTable[mr]`로 계산할 수 있다. 수치 동등성 검사 전에는 교체하지 않는다. 캐시와 인덱스 범위 정책을 확정하고 allocation-free 호출을 유지한다. 과도한 객체화·`BigDecimal` 운영경로 사용·추가 스레드·DB 조회는 금지한다.

## 6. RKern 적용 작업 순서 [구현 체크리스트]

- [ ] **실제 최신 전체 SRC 기준 확인:** 소스 누락 없이 현행 마법/스킬/무기발동 마법의 **공격자→대상→피해 적용** 호출 체인을 찾는다. 외부 L1J의 `L1Magic` 구조를 RKern의 실제 구조라고 가정하지 않는다.
- [ ] **원본 비교 기준선 기록:** 변경 전 다이스·INT/SP·MR·속성저항·최종 데미지 및 타격별 후처리 순서 수집. 로그는 테스트 모드에서만 제한적으로 기록.
- [ ] **스탯 매핑:** 공격 INT, 실제 추가 SP, MB/ML의 의미 및 중복 여부를 소스/실측으로 확정. `getSp` / `getTrueSp` 등 유사 통계는 직접 계산 경로를 추적.
- [ ] **속성 매핑:** 스킬별 무속성·땅·불·물·바람 종류를 실제 DB/스킬 설정에 맞춰 대응. 다중 속성/마법무기/고정 피해는 별도 처리.
- [ ] **방어 클래스 매핑:** PRI~WAR 계수와 `target.getClassId()`류의 **실제 클래스 타입** 연결. PC 이외 NPC에 클래스 계수를 억지로 적용하지 않는다.
- [ ] **MR·WIS 중복 제거:** 기존 MR 단계/기존 WIS 보정을 식과 함께 이중 적용하지 않는다. 현재 저MR 처리 경로는 유지.
- [ ] **단계별 절삭 구현:** `A_E` → `floor(D*A_E)` → 치명타 내림 → `B` 내림 → `floor(base*B)` → `MD` → `DR` 순서 보장.
- [ ] **후처리 연결:** 기존 PvP, 특수 버프/디버프, 실드, DR, 불사/무적, 반사, NPC 특수 규칙, 다단타/도트 피해의 정책을 보존하고 해당 계수 적용 범위를 통제.
- [ ] **저MR 분기 정책:** `MR-MH={-1,0,1,9,10,11}` 모두 실측 또는 기존 검증 로직으로 다루고, 9↔10 불연속/역전 현상은 별도 조사.
- [ ] **검증 통과 후 최적화:** Java 21 전체 타입 컴파일 → 실제 타격단위 회귀 → 부하 비교 → 수치 동등성 확인한 뒤 필요 시 `Math.pow` 테이블. 불필요한 새 객체·스레드·큐·락 추가 없음.
- [ ] **출시 기준:** PC→PC와 PC↔NPC의 표본/속성/클래스/기술별 데미지 대조 없이 ‘본서버와 동일’로 선언하지 않는다.

## 7. 테스트 매트릭스 및 수락 기준

### 7.1 단위·골든 벡터

1. **원식 재현:** `D=9, A=4.09, B=0.63, MD=17, DR=1` → 일반 `38`, 크리티컬 `50`.
2. **속성 결합 후보:** 같은 고정 입력에서 `ER=50` → 일반 `36`, 크리티컬 `46`; `ER=100` → 일반 `33`, 크리티컬 `41`.
3. **속성 한계:** `ER=-150,-100,-99,0,99,100,150`; -150과 -100, 150과 100은 2015 모델의 **동일 계수**가 되어야 한다.
4. **WIS 짝·홀:** `19,20,21`에서 `floor(WIS/2)`가 각각 `9,10,10`인지 확인.
5. **방어자 클래스:** 기사·마법사·요정 등 클래스만 변경한 입력에서 **공격자 클래스가 아니라 방어자** 클래스가 `C`를 바꾸는지 확인.
6. **저MR:** `MR-MH = -10, 0, 1, 8, 9, 10, 11, 50, 100, 101`; 10 미만은 후보 `Math.pow`를 호출하지 않고 기존 경로로 처리.
7. **타격마다 다이스:** 고정 평균으로 대체하지 말고 굴림 최소·최대·중간값별 비교.
8. **크리티컬 절삭:** `floor(base*1.5)`와 `floor(base*B*1.5)`의 결과가 서로 다른 경우를 분리해 검증.
9. **추가 피해:** `MD=0/8/13`, `DR=0/1/5`, `ER=100`, INT+β=12 고정 폭탄 케이스에서 실측 `0/7/8`과 비교(스킬 특례 확인 후 적용).
10. **부동소수 경계:** `floor2(C*pow(...))`가 xx.x999999999 부근에 오는 값, 음수 `A_E`가 발생하는 비정상 스탯, 큰 `D`로 overflow를 유발하는 값 별도 방어.

### 7.2 실제 게임 테스트

| 축 | 최소 확인 항목 |
|---|---|
| 주체 | PC→PC, PC→NPC, NPC→PC, NPC→NPC 구분 |

| 마법 | 일반 공격 마법, 다이스 마법, 고정 다이스, 마법무기 발동, 폭탄/메테오완드 유사 특수 스킬 |

### 7.3 수락 기준

- 원문/시트로 확정된 수식 결과와 **모든 해당 테스트 벡터에서 정확히 일치**.
- 연구에서 미검증인 영역은 기존 동작 유지 또는 실측 합의를 거친 정책으로 명시.
- 기존 일반 공격/스킬/마법무기/CacheD/네트워크 브로드캐스트에 회귀 없음.
- 전투 핫패스의 새로운 per-hit `new`/boxing/임시컬렉션/DB 호출 없음.
- 통합 컴파일, 정적 검사, 실제 게임 전투 및 Windows IOCP 환경 검증은 **각각 별개 수락 항목**으로 기록.

## 8. 구현 시 주의해야 할 차이

1. **2015년 MR 모델을 2016년 `B`와 섞지 않는다.** 2015 자료에는 MR 단계 감소 모델이 등장하므로 연도별 실측식은 서로 다른 스냅샷이다.
2. **`MD` 적용 시점:** 2015 자료에서 추가 피해가 MR 영향 범위에 놓였던 사례와, 2016 잠정식의 마지막 `+MD`는 차이가 있다. 최신 모델을 구현하기 전 스킬별 실측 필요.
3. **속성저항 100%:** `INT+β=12`인 속성 기본마법과 고INT 마법의 결과가 다를 수 있다. `ER=100`이라고 최종 피해를 무조건 0으로 만들면 안 된다.
4. **최종 최솟값:** 음수/0/1 데미지를 어떻게 처리하는지는 이 근사식만으로 확정되지 않음. 기존 서버 규칙 또는 실측에 따라 적용.
5. **PC/NPC 적용:** 2015 속성 공식의 PC→PC 실측을 NPC 전체에 무조건 일반화하지 않는다.
6. **분리된 범위:** 회복마법, 디버프 명중확률, 상태이상, 물리 속성피해, 출혈/도트 등은 이 **일반 공격마법 피해** 공식과 별도로 취급.
7. **과거 수치와 현행 서버:** 2016 연구식은 2026 클라이언트·콘텐츠 밸런스의 정확한 구현 증거가 아니므로 적용 조건을 명시.
