## 2. HPMP-01 — 최대 HP·MP 25/35/45 보너스의 판정 스탯

### 일본 NC 2016 공식 [확인]

- CON 25/35/45에서 최대 HP 증가 **+50/+100/+150**이 단계별로 추가된다. 45에서 누적 **+300**.
- WIS 25/35/45에서 최대 MP 증가 **+50/+100/+150**이 단계별로 추가된다. 45에서 누적 **+300**.
- 레벨업 포인트·엘릭서 등에 의한 영구 스탯과 장비/버프의 임시 증가를 구분한다. NC 파워위키는 레벨업 MP 증가량이 장비·물약 등의 임시 스탯 영향을 받지 않는다고 명시한다.
- 보너스를 **순수 CON/WIS** 기준으로 처리한다는 점은 Phil 연구 및 당시 순수 스탯 보너스 모델에 기반한 구현 판단이다. 공식 안내 문구가 모든 내부 getter의 정의까지 공개하는 것은 아니다.

### RKern 선행 정적 검수

`L1Character.java`의 `getMaxHp()` 및 `getMaxMp()`, 선행 검수 기준 748~790행 주변에서 각각 다음처럼 `getTotalCon()`, `getTotalWis()`에 대해 구간 검사를 수행하는 것으로 보고됐다.

~~~java
if (getAbility().getTotalCon() >= 25) maxhp += 50;
if (getAbility().getTotalCon() >= 35) maxhp += 100;
if (getAbility().getTotalCon() >= 45) maxhp += 150;
// WIS / maxmp도 동일 구조
~~~

**결과**: 영구 CON 24 + 장비 CON 1이면 보너스 HP +50이 발생할 수 있다. 영구 WIS 44 + 장비 WIS 1이면 최상위 MP 구간이 잘못 열릴 수 있다.

### 수정 요구

1. 클래스 생성 기본값 + 레벨업 영구 배분 + 엘릭서 등 **영구 스탯**을 읽는 실제 API/필드를 확인한다.
2. HP/MP 25·35·45 판정에는 **영구·순수 스탯**을 사용한다. 물리적으로 `getTotalCon()`을 치환하는 것만으로 다른 기능을 망가뜨리지 않도록 getter의 소비 지점을 검토한다.
3. 이미 영속 저장된 기본 max HP/MP에 동일 보너스가 누적돼 있다면 중복 적용을 방지한다.
4. 장비/버프 장착·해제 시 최대 HP/MP에 반영되는 **다른 일반 스탯 효과**까지 제거하지 않는다.
5. 사망·부활·재접속·저장·스탯 초기화 경로에서 일관성 확인.

**재현 조건**: 영구 CON 24/25/34/35/44/45 × 임시 CON 0/+1; WIS도 동일 매트릭스. 각 경계에서 +50/+100/+150 한 단계씩만 열려야 한다.

## 3. HPMP-02 — 클래스별 HP 증가량의 +3 편차

Phil의 공개 자료 및 2016년 일본 클래스 보너스 정리에는 **CON 12 기준 클래스별 기본 HP 레벨업 증가량**이 아래와 같이 나타난다.

| 클래스 | 일본 연구 모델 | RKern 선행 검수: `CalcStat.increaseHp` | 차이 |
|---|---:|---:|---|
| 군주 | 12~13 | 15~16 | +3 |
| 기사 | 17~18 | 17~18 | 일치 |
| 요정 | 10~11 | 13~14 | +3 |
| 마법사 | 7~8 | 7~8 | 일치 |
| 다크엘프 | 11~12 | 14~15 | +3 |
| 용기사 | 13~14 | 16~17 | +3 |
| 환술사 | 9~10 | 12~13 | +3 |
| 전사 | 17~18 | 17~18 | 일치 |

**관찰:** `CalcStat.PureHp()`는 일본 연구 모델 쪽과 일치하지만, 레벨업 실제 `increaseHp()`와 일치하지 않는다고 선행 검수됐다.

**중요 제한:** 위 차이는 **Phil/2016 일본 연구 모델 대비** 차이다. NC가 2019년에 이 값을 유지했는지 추가 확인하기 전에는 본서버 확정 오류라고 단정하지 않는다.

**수정 요구**:

- 실제 레벨업에 사용되는 메서드가 `increaseHp`인지 전체 호출 경로를 확정.
- `PureHp()`, `increaseHp()`, 캐릭터 생성 초기 HP, 표시용 HP 성장, DB 저장 단위가 같은 클래스·CON 규칙을 참조하도록 통합.
- 단순히 5클래스에서 `-3`만 하는 패치를 먼저 내지 말 것. 계산 단계에 포함된 기본값·레벨 보정·상태별 보너스가 재사용되는지 확인.
- CON 12 외에 11, 13, 16, 20, 25, 35, 45 및 **레벨 50/51 경계**를 테스트.
- 이미 생성된 캐릭터를 로그인할 때 무조건 다시 산출하지 말 것.

**오차 예시**: 동일 CON을 계속 유지한 79회의 레벨업에서 매번 +3이면 약 **+237 HP** 누적 차이가 된다. 이는 차이 구조를 보여주는 **산술 예시**이며 실제 80레벨 캐릭터 전원의 차이를 의미하지 않는다.

## 4. HPMP-03 — 실제 MP 성장과 표시용 구간의 24/360 불일치

선행 검수에서는 **8클래스 × WIS 45구간 = 360조건 중 24조건**에서 `CalcStat.increaseMp()`의 실제 증가 범위가 `MinincreaseMp()` / `MaxincreaseMp()`와 다르다고 보고했다. 해당 검사는 **RKern 내부 비교**이지 일본 본서버 재현율이 아니다.

| 클래스 / WIS | UI·표시용 최소~최대 | 실제 레벨업 최소~최대 |
|---|---:|---:|
| 기사 / 45 | 6~10 | 4~8 |
| 마법사 / 45 | 20~32 | 10~22 |
| 마법사 / 35 | 16~24 | 16~26 |
| 요정 / 18 | 5~10 | 4~9 |
| 용기사 / 15 | 3~4 | 3~5 |
| 환술사 / 45 | 16~26 | 16~26 (정상 대조군) |

**수정 요구**:

1. MP 실제 증가값과 화면 안내가 **같은 원천 규칙**에서 나오도록 조정.
2. 일본 연구의 MP 증가식은 WIS에 대해 **3·5 배수의 구간 변화**, 클래스별 계수와 절삭 단계가 있다. 캐릭터별 클래스 계수를 한 개의 선형식으로 대체하지 않는다.
3. 순수 WIS만 레벨업 증가량에 적용한다. 장비 WIS와 버프로는 과거 레벨업 획득 MP가 재작성되지 않아야 한다.
4. 모든 360조건의 범위·레벨 경계·희귀 고WIS(35/45) 테스트를 자동화한다. 무작위 표본은 최대·최솟값과 분포까지 대조.
5. 클라이언트 표시용 구간이 실제 서버 계산과 다른 경우 **어느 쪽이 2016 NC 규칙에 맞는지 판별한 뒤** 한쪽으로 맞춘다. UI와 실제 코드만 일치한다고 본섭 재현이 증명되는 것은 아니다.

## 5. HPMP-04 — MP/HP 자연회복 중복 항목 가능성

Phil 모델 중 MP 기본 자연회복 예시:

~~~text
MPR = floor(totalWIS/5) + floor(level/40) + pureWISBonus
~~~

참고로 연구자가 사용한 순수 WIS 보너스의 25/35/45 단계는 **+1/+2/+5**다.

선행 검수에서는 `CRegenController.java`가 WIS 관련 회복량을 산출하면서 `CalcStat.엠회복틱()`을 **별도 가산**한다고 보고했다. `level=80, WIS=20`, 특별한 버프가 없는 조건에서 **일본 모델 6 vs RKern 계산 11** 사례가 보고됐다.

**수정 요구**:

- 회복 한 틱의 전체 성분을 **기본 WIS/레벨/순수 WIS/클래스/장비/버프/물약/이벤트**로 나눠 덤프한다.
- `CRegenController`와 `CalcStat`이 **동일 WIS 계수**를 각각 더하는지 직접 증명해 제거.
- 회복 주기(ms), 무게 한계, 전투/이동/수면 상태, 최소값, 초과 회복량 제한은 기존 서버 규칙을 유지.
- HP 자연회복도 동일한 이중 가산 여부와 CON/레벨 보정 확인.
- 2015 Phil 모델과 2016·2019 NC 운영값을 혼합하지 말고 기준을 확정한다.

**판정**: 중복 가산은 **검수 우선 후보**. 전체 호출 및 항목 중복의 재검증 없이 `엠회복틱()` 자체를 삭제하지 않는다.

## 6. HPMP-05 — CON/WIS 45 무게 초과 회복 예외

**[NC 공식 확정]** 2016년 일본 NC 안내는 순수 스탯 45의 특수효과로 다음을 제시한다.

- CON 45: 무게 초과 시에도 **정상 HP 자연회복량의 절반** 적용.
- WIS 45: 무게 초과 시에도 **정상 MP 자연회복량의 절반** 적용.

`CRegenController.java`의 선행 검수 경로는 무게 초과시 HP/MP 회복을 중단시키고 위 예외가 관찰되지 않았다.

**수정 요구**:

1. 무게 판정을 통과했을 때의 **정상 회복량을 먼저 산출**한다.
2. 무게 초과이고 영구 CON 45 이상인 경우 정상 HP 자연회복량의 1/2; 영구 WIS 45 이상인 경우 정상 MP 자연회복량의 1/2.
3. HP와 MP는 **각각 독립 판단**. CON45만 있는 캐릭터는 HP만 예외; WIS45만 있으면 MP만 예외.
4. 1/2로 발생하는 **홀수 회복량의 정수 절삭 규칙은 추가 원문·실측이 필요**하다. 임의 `Math.round`를 확정 규칙으로 넣지 않는다.
5. 자연회복 예외가 전투 이벤트의 직접 회복, 장비 효과, 도트힐을 잘못 허용하지 않도록 호출 경로별 분리.

**테스트**: CON44/45, WIS44/45, 무게 정상/초과, 1/2 둘 다 충족, 회복 기본량 짝수/홀수, HP/MP 만충, 죽음/로그아웃/맵 이동.

## 7. HPMP-06 — 레벨다운에서 HP/MP 재추첨 위험

선행 검수에서는 `L1PcInstance.levelDown()`이 **레벨업 때 실제 얻었던 HP/MP 이력값을 역연산하지 않고 새 랜덤 증가량을 추첨해 차감**하는 것으로 보고됐다.

**잠재 문제**: 레벨 업 → 레벨 다운 → 재레벨업을 반복할 때, 같은 스탯·장비에서도 최대 HP/MP가 드리프트할 수 있다.

**수정 요구**:

- 기존 코드/DB에 레벨별 HP·MP 증가 이력 또는 저장 가능한 확정 수치가 있는지 먼저 확인.
- 레벨다운 시 이전 레벨업에서 확정된 증가량을 **정확히 제거**하도록 설계하되, 과거 자료가 없으면 사용자가 아닌 개발자 임의의 복구 수치를 생성하지 않는다.
- 기존 캐릭터의 레벨·스탯·HP/MP 데이터와 거래/로그아웃/CacheD 저장 경로의 확정성을 유지.
- 테스트는 `L→L+1→L` 왕복 시 HP/MP 정확성, 재접속/재시작·DB 저장, 스탯 재분배, 버프/장비 교체, 다회 반복.
- 필요한 경우 저장 형식 변경의 범위를 **별도 설계·원자적 마이그레이션**으로 검토. 새 테이블/워커를 즉흥적으로 도입하지 않는다.

**판정**: 소스에서 정확한 레벨다운 구현과 지속 저장 데이터가 재확인되기 전에는 **확정 버그가 아닌 위험 후보**로 취급.

## 8. HPMP-07 — 공식 HP/MP 연구표 전수 대조 절차

원본 시트: [Phil 『リネージュ ステータスリニューアル関連』](https://docs.google.com/spreadsheets/d/1P7unh7Sky0a_Iafq_9iqKBfMoUzsKDERUwSs899qpLY/edit).

시트에 **『HP一覧』, 『MP一覧』, 『HP一覧（データ元）』, 『MP一覧（データ元）』, 『データ』** 탭이 있으며, 『데이터 원본』은 클래스 계수·각 스탯에 따라 이전 레벨의 값을 누적하는 계산식으로 구성되어 있다.

- 캐릭터별 기초 HP/MP부터 확인하고 **클래스 × 레벨(50,51,55,60,65,70,75,80,85,88) × 해당 클래스가 허용하는 순수 CON/WIS**를 대조한다.
- **높은 CON/WIS 값은 51레벨 이후 스탯을 순차 배분한 모델**임을 반영한다. 시작부터 CON/WIS 45로 80레벨까지 성장했다고 계산하는 **잘못된 비교를 금지**한다.
- 각 조합의 **기대 최소/최대/평균**, RKern 결과(고정 시드 및 다중 시드), 절대 오차, 상대 오차, 경계 불일치 건수, 클래스별 실패율을 산출한다.
- 선행 검수의 **군주 80레벨 CON12의 일본 연구 평균 HP 약 1,002 vs RKern 증가식 추정치 약 1,239**는 단순 누적 비교 **예시**이며 인게임 직접 관측 데이터가 아니다.
- WIS의 3/5 구간 변경과 CON의 구간별 증가, 25·35·45 순수 보너스, 장비 스탯 변화, 레벨 다운/재접속을 모두 포함.
- **자동 테스트 자체가 서버 소스 실행 경로(실제 CalcStat/최대HP/MP getter/CRegenController) 호출과 연결되어야** 재현율이 의미 있다.

## 9. 수정 실행 순서 (안전성 중심)

1. **테스트 고정**: 최신 권위 SRC 확보 및 Java 21 통합 컴파일, HP·MP 현재 출력값/저장값·실제 레벨업 경로 스냅샷.
2. **순수 스탯 보너스**: HPMP-01을 먼저 고쳐 임시 스탯에 의한 구간 발동을 차단; 기존 보너스 누적 여부 확인.
3. **성장 규칙**: HPMP-02/03을 클래스별 같은 판정 경로로 통일; 배정 타이밍/기록/클라이언트 표시까지 맞춤.
4. **회복 경로**: HPMP-04/05로 회복 계산 원천을 정리하고 45 무게 초과 예외 반영.
5. **레벨다운**: HPMP-06의 이력/저장 데이터 확인 후 안전한 역연산 정책 채택.
6. **전체 비교**: HPMP-07로 연구표와 교차검증 후, 2019년 공식·실측과 다른 항목만 연도별 예외화.
7. **운영 안정성**: 레벨업/레벨다운/스탯 초기화/사망/부활/로그아웃/재접속/재시작/DB 및 CacheD 영속화 검증.

**최종 완료 기준**:
- 순수 스탯 경계(24/25,34/35,44/45)와 임시 스탯 실험 100% 통과.
- RKern 실제 HP/MP 성장과 표시용 성장값이 동일 기준을 적용.
- CON45/WIS45 무게 초과 회복 예외가 각각 독립 작동.
- 레벨다운/재접속 후 저장된 HP/MP가 예상치 않게 증가·유실하지 않음.
- 연구표와의 불일치를 클래스·스탯·레벨별로 명확하게 보고. *일본 연구표 일치율을 NC 공식 재현율로 표기하지 않음.*
- 실제 수정한 파일만 점검·변경하고 기존 CIO/CacheD/네트워크 경로는 불필요하게 수정하지 않음.
