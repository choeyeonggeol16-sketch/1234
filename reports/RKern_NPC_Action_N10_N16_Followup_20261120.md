# RKern NPC Action N10–N16 후속 수정 및 검증

[11월 20일 감사 보고서](RKern_NPC_Action_N9_Followup_Optimization_Audit_20261120.md)를 기준으로 NPC Action 작업 브랜치와 공통 CacheD를 수정했다.

## 적용한 변경

| 범위 | 변경 내용 |
| --- | --- |
| N10 오림 | 파티를 한 번 스냅샷하고 컨트롤러 입장을 배타 예약한다. 전원의 구슬 410096을 한 CacheD 거래에 준비하고 파티·맵·세션을 SQL 실행 직전에 다시 확인한다. 거래와 인벤토리 반영이 끝나면 기존 컨트롤러를 시작하고 각 참가자의 CIO에서 이동한다. 기존 2인 이상 조건과 3~5인 안내문을 유지했다. CacheD의 6인 한도와 32비트 입장 마스크를 제거했다. |
| N10 카르마 | NPC 80050/80064 역교환과 80056/80074 순교환에서 결정 1/10/100개 및 카르마를 같은 InnoDB 거래에 저장한다. DB 확정 후 현재 캐릭터에 카르마를 반영하며, CacheD는 세션과 카르마 리비전이 오래된 자동저장 스냅샷을 배제한다. 기존 부호·배율·상한과 메시지 1078~1081 및 meet 페이지를 유지했다. |
| N11 훈련소 | 최대 99개 방과 맵 번호를 선점하고 관리 NPC를 준비한다. 결제, 열쇠 4/8/16개, 키 DB 행을 함께 확정한다. 미확정 방에는 입장할 수 없으며 결제 실패 시 예약을 정리한다. 키의 방 번호는 거래와 인벤토리 복사 뒤에도 보존한다. 만료 시 같은 맵 번호를 다시 사용하는 새 방은 해당 방에 발급된 키만 받는다. |
| N11 발라카스·펫 | 발라카스 준비/레이드가 각각 최대 49개의 방을 동시 요청에서도 선점한다. 스폰 데이터와 NPC 준비에 실패하면 냉한의 기운을 차감하거나 검을 지급하기 전에 종료한다. 펫은 대상·CHA·수용량 및 생성 가능 여부를 먼저 확인하고 비용·아뮬렛·펫 DB 행을 함께 확정한다. 라이브 펫 생성에 실패해도 저장된 아뮬렛과 펫 행은 남는다. |
| N11 직접 지급·차감 | 차원의 문 무료 지급과 봉인/보호 물품 회수, 오림 무료 항아리를 거래로 옮겼다. 보스 키는 템플릿 확인 후 차감하고 월드 소환하는 구조로 남아 있다. 공용 지급의 의도된 바닥 드롭과 카너스의 5,000 아데나 정책은 운영 동작을 유지했다. |
| N12 대화 | 유효한 Talk/HTML/Amount 진입에서 세션이 기존 월드 smart ID와 대화 세대를 기록한다. 제작, XML, 역카르마, 훈련소 완료에서는 현재 NPC·맵·거리·생존 여부를 재확인하고 오래된 HTML만 억제한다. 아이템 결과와 보상 알림은 유지한다. 페이지별 명령 제한을 전역 적용하려면 운영 HTML/XML 목록을 먼저 대조해야 한다. |
| N13–N14 디스패치·할당 | NPC 템플릿 ID는 레거시 분기에 한 번 전달한다. 고정 ID 60개를 primitive switch로 바꾸고 PC방 입구 조건과 등록 Action의 선행 처리 순서를 유지했다. 토템 경로 두 곳은 같은 불변 재료/보상 배열을 쓰고 수량 배열만 만든다. 펫 CHA 합산은 기존 목록 잠금 안에서 순회한다. 클래스별 명령은 기본 숫자 형식이 확인된 로캘에서 문자열을 재사용한다. |
| N15 CacheD·JDBC | 던전 타이머 저장은 이미 순서 보장 CacheD 작업을 사용한다. `hero21` JDBC는 캐릭터·계정 두 순서 키를 예약하는 기존 CacheD 작업으로 옮겼다. 훈련소와 펫 메타데이터 쓰기는 같은 거래로 이동했다. 발라카스 스폰 조회는 해당 타입 행만 읽으며 방 준비에서 동기 실행된다. 격리된 CacheD 작업은 순서 장벽만 남기고 람다와 캡처된 캐릭터·인벤토리 참조를 놓는다. |

## 확인한 결과

- JDK 21로 운영 Java 소스 1,933개 컴파일. 오류 0개, 기존 제거 예정 API 경고 5개.
- 카르마 양방향 226개 시나리오, 검사 1,390개. 펫 구매 검사 618개. 다중 참가자 예약/해제 검사 261개. 파티 2/3/6/7/8/35명, 참가자 로그아웃·busy·ID 중복 및 중복 해제를 검증했다.
- XML 484개 시나리오, 여관 4,692개 시나리오 및 동시 실행 100회. 귀걸이 조합 64개, Moonbow 1,406개 시나리오, Coma Gift 73,488개 시나리오, 수량 대상 범위 검사 1,324개, Grant Target 검사 13,896개 통과.
- 기존 코드와 고정 NPC ID 60개를 대조해 같은 핸들러로 연결됨을 확인했다. 바이트코드는 `lookupswitch`를 사용한다.

## 운영 환경에서 확인할 항목

- 현재 실행 환경에서 운영 MySQL, HTML/XML·스폰 데이터, 게임 클라이언트를 연결한 검증은 수행하지 못했다. 위 회귀 검사는 제어 가능한 거래 및 세션을 사용했다. 실제 COMMIT ACK 유실, 강제 종료·재접속, 롤백 및 방 정리, 1/1,024/5,000 접속의 p99·JFR는 검증 결과가 없다.
- DB는 아이템과 영속 데이터를 함께 확정한다. 오림 출항, 발라카스 입장, 라이브 펫 소환은 이후의 월드 동작이다. COMMIT 이후 세션/스케줄러가 사라지면 월드 동작이 실패할 수 있다. 오림과 발라카스에 DB 기반 자동 환불·재입장은 아직 없다. 거래 결과 또는 인벤토리 재생이 불명확하면 CacheD는 해당 owner 순서를 유지하고 추가 거래를 차단한다.
- 훈련소는 이전과 같이 서버 부팅 때 기존 방 키를 청소한다. 부팅을 넘겨 훈련소를 이어서 사용하는 기능은 없다.
