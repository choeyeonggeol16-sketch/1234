## 호출 흐름과 보존 정책

### 경험치 / 아인

`몬스터 사망·분배 → CalcExp.calcExp의 해당 수령자 AddExp(pc,exp,lawful) → ExpGainCalculator → 보너스 계산/레벨·캡차 확인 → Account.addBlessOfAin 1회 → pc.addExp 1회`.

파티·펫·소환수 기여 분배의 기존 합산/수령자 선택은 변경하지 않았습니다. CalcExp의 비사냥 보상 오버로드는 원래의 별도 정책을 유지하며 사냥 축복 소모를 새로 추가하지 않았습니다. 낚시는 기존 독립 경로를 유지하고 공통 감소량 helper를 사용합니다. 일반 UI send는 상태를 소비하지 않습니다.

축복 소비 효율/맵 가중치는 기존 SC_RestExpInfo가 소유합니다. 이번 사냥은 시작 축복값을 같은 helper에 전달하여 차감 중간에 등급이 달라져 보너스가 빠지지 않게 했습니다. Account.set/add/recover는 하나의 내부 갱신으로 모았고 CacheD에는 기존과 같은 절대 잔액을 제출합니다. 새로운 테이블·큐·워커·직접 JDBC를 사냥 경로에 넣지 않았습니다. 회복 정책의 온라인 상한2,000,000, 계정 상한50,000,000과 기존 내부 단위는 유지합니다.

`research/ain-calls.txt`는 최초 사용처 검색 기록입니다. 실제 전체 몬스터/파티 월드를 부팅해 각 기여 경로를 검증한 것은 아니며, 각 수령자 계산 진입점과 기존 분배 호출은 소스 추적했습니다.

### 아머 브레이크 / DR / 버닝

`PC 일반 무기 계산 → 기존 TrueTarget/Avatar 단계 → 나머지 공격 추가타와 PvP 무기 추가타 → applyArmorBreak → 기존 PvP 고정 방어 → DamageReductionHelper의 고정 DR → 기존 applyFinalPhysicalMultipliers(Burning/Fury) → 기존 퍼센트 방어 → commit → victim controller → HP`.

AB, 다른 상태 배율, 고정 DR, 버닝은 각 소유 경로를 유지합니다. 기존 applyTargetPcDamageMultipliers는 같은 AB helper에 위임하므로 NPC→PC 정책도 복제된 배율식을 갖지 않습니다. PC→PC 물리는 전체 preDR를 넘기고, 다른 상태 배율의 기존 위치를 AB와 함께 무작정 옮기지 않았습니다. 키링크/원거리는 기존 AB 비적용, NPC→NPC/PC→NPC의 기존 별도 정책도 유지합니다. 기존 시전자 표식이 있는 PC의1.58/다른 근접 공격의1.20 정책은 바꾸지 않았습니다. 기존 명중·이도류·더블브레이크·속성·독·패시브/반격·흡수 확률은 변경하지 않았습니다.

동일한 대상 DR을 두 번 빼거나 버닝을 두 번 곱하는 경로는 이번 일반 물리 흐름에서 발견하지 못했습니다. 기본 PvP DR, 장비 DR, 스킬 DR 등 서로 다른 감면은 중복으로 오인해 삭제하지 않았습니다. 기존 캐릭터 수신부의 별도 감면 정책도 유지합니다.

## 산출물 / 적용 / 한계

기존 Java8개 변경, 새 생산 클래스0개. 원본 변경 파일 목록과 diff, 입력 사용처 기록, 전체 src를 함께 제공합니다. 전체 src에는 이전 IOCP·스레드풀·마법·물리·HP/MP·재점검·맨손/속성 수정이 모두 들어 있습니다. **새 SQL은 없으며 기존 HP/MP SQL 컬럼은 필수입니다. 이미 적용한 DB는 다시 실행하지 않습니다.**

**Windows 실게임·운영 MySQL·CacheD 데몬·전체 파티 월드·운영 부하와 서버 강제 종료는 미검증입니다.** 테스트는 연결하지 않은 PC, 빈 맵/헌팅 설정과 로컬 H2를 사용합니다. 경험치 characters와 축복 accounts는 여전히 기존 별도 저장 행이므로 두 행 사이 강제 종료의 원자성을 새로 보장하지 않습니다. 오프라인 회복은 정상 로그아웃 기록을 기준으로 하며 비정상 종료 시간 추정이나 회복과 로그인 표식의 DB 원자 확정은 이번에 새로 구현하지 않았습니다. 내부1단위보다 작은 소모 소수점의 새 영속화도 도입하지 않았습니다. 공개 실측 모델과 운영 버전의 일치는 별도 실측이 필요합니다.
