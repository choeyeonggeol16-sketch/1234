# ABI10 후속: 방송 필터·매니저 진단·설정·중복 정리

요청한 1~5번을 기존 구현과 대조했다. 게임 native DLL/ABI/기존 코덱/PSS는 유지하고 Java의 수신자 판정, 방송 적용 범위, 매니저 진단과 설정을 수정했다. 원본 전체 함수 복원 완료를 뜻하지 않는다.

| 항목 | 처리 결과 |
|---|---|
| 1. 거리·구역 필터 | L1의 기존 맵별 격자·화면·타일 거리·직사각형 AOI를 유지. 공통 `CTLMFilter`로 같은 맵/자기 제외/거리·사각형 판정을 통합하고 다른 맵으로 이동한 대상은 거절 |
| 2. 운영 진단 | 기존 매니저 메뉴의 패킷 카운트/초기화, 시간 분석/초기화, 프로파일, 소켓, 참조·수명 상태, 전송률/초기화 연결. 최근 128개 패킷 조회 추가 |
| 3. 시간 정책 | 원본 helper와 소켓 소비자 4곳을 재확인. 기존 L1 monotonic64·부분 수신/송신 정체/정상 종료 타임아웃 유지. 로그인 제한은 기존 기본 60초를 유지하며 config로 변경 가능 |
| 4. 공유 방송 확대 | 이동·방향 변경·오브젝트 삭제에 적용. 기존 액션·이펙트까지 다섯 serializer의 수신자 순회를 `CSharedBroadcast`로 통합 |
| 5. MAC/HWID | 기존 서버 측 제한/반환/API를 재사용. DB 없이 설정 파일과 기존 JVM 옵션으로 제어. 실제 클라이언트 식별값 전달/검증 연결은 현재 제공된 서버 자료에 없어 미연동 |

## 필터와 중복 정리

`LocalWorldMap`의 일반 객체/유저 수집/유저 존재 검사에 반복된 동일 조건을 공통화했다. 원본 `CTLMFilter`의 수신자 판정 역할을 L1에 맞춘 정적 adapter이며 원본 C++ 객체/vtable ABI 재현은 아니다. 거리 단위와 화면 모양은 기존 L1 함수를 그대로 사용한다. L2의 Z 좌표나 territory 데이터 구조를 L1 맵으로 임의 치환하지 않았다.

화면/맵 판정이 이미 구현돼 있던 격자는 다시 만들지 않았다. 사각형의 역전 범위는 빈 영역으로 유지한다. 스냅샷을 얻은 뒤 방송할 때에도 같은 맵/자기 제외를 확인한다.

다섯 방송의 반복된 스냅샷 대여/반환, 연결 검사, 공유 송신과 기존 직접 작성 경로 선택을 한곳에 모았다. M 이펙트 설정, wide 반경 50, 이동 목적지·heading·상수/예약 바이트, 개별 자기 전송은 유지한다. 팩 전체에서 중복 코드가 사라졌다는 뜻은 아니다.

## 매니저에서 확인할 수 있는 것

- 최근 기록: 연결당 opcode·단조 시각 128개. 본문·암호·채팅 내용은 저장하지 않는다. 연결 종료 후 최대 64개 연결 기록만 유지한다.
- 패킷 카운트: 복호화 후 opcode별 접수 수. 시간 분석: 실제 실행된 필터/handler의 완료 횟수·평균·최대 경과 시간. 큐 대기 시간이나 CPU 실행 시간과 구분한다.
- 프로파일: 기존 native CPerfMon 샘플·worker 콜백 정보와 실행 중 Java 패킷 작업의 연결/코드/시간. 활성 작업은 thread 256개·중첩 32단계까지 표시한다.
- 소켓: 기존 native 소켓 상태와 진단 id. 화면은 최대 512개 연결을 표시하고 id로 최근 패킷을 조회한다.
- 참조·수명 상태: 등록/대여 패킷/READ·WRITE pending 상태. 공개되지 않은 정확한 native 객체 refcount를 만들어 표시하지 않는다.
- 전송률: 복호화 후 수신 본문 바이트, Java 송신 접수 wire 바이트/초. 실제 OS/TCP 완료량이 아니다. 소켓 outputBytes도 native 출력 큐만이며 실행 전 예약량·Java 준비량과 구분해 표시한다.

진단은 연결 추적 기본 상한 10,000개, 종료 기록 64개로 제한했다. 초기화는 카운트/시간/전송량마다 독립적이며 초기화 전 실행 중인 작업은 새 시간 통계를 오염시키지 않는다. 종료 기록에는 게임 객체 참조를 보관하지 않는다.

매니저 조회는 SwingWorker에서 읽고 결과 표시만 EDT에서 수행한다. 기존 보고서 창에 스크롤을 붙였다. 아직 연결하지 않은 NPC 분포·프로파일 초기화 등의 메뉴는 비활성을 유지한다.

## 설정

기본 파일 `config/ctransport.properties`를 게임 서버 실행 폴더에 둔다. UTF-8이며 `-Dctransport.config=다른파일`로 경로를 바꾸고 개별 `-D` 옵션은 파일보다 우선한다. 변경 후 재시작한다. 파일이 없어도 기존 기본값으로 동작한다. 명시한 경로가 잘못되거나 값이 범위를 벗어나면 시작 시 거절한다.

```properties
ctransport.macLimit=0
ctransport.perf.intervalMs=1000
ctransport.loginTimeoutMs=60000
ctransport.diagnostics.enabled=true
ctransport.diagnostics.maxConnections=10000
```

MAC 제한 기본 0은 비활성이다. 양수 제한은 신뢰할 식별자 공급자가 로그인 전에 `bindVerifiedMacIdentity`로 연결해야 사용할 수 있다. 제공된 자료만으로 원격 PC의 식별값을 알아낼 수 없어 IP·계정·난수를 HWID로 대신하지 않았다. **클라이언트 연동까지 완료한 기능으로 해석하면 안 된다.** 독립 PSS에 식별자 전송을 임의로 붙이지 않았다.

## 검증 및 한계

- 운영 Java 1,709개 전체 컴파일 및 기존 DLL ABI/hash 검사 통과.
- 진단 검사: 8개 thread/8,000개 동시 표본, 128 ring/64 종료 기록 상한, 중첩 작업 복원, 초기화 epoch 격리, 연결 상한·반환, 파일 설정/JVM 우선순위 통과.
- 방송 검사: 실제 다섯 production encoder의 공유 입력과 기존 직접 작성 wire 바이트 일치, 8방향·좌표 경계, 맵/자기/연결/M 필터, wide 50, 반경/사각형 경계, 예외 시 snapshot/source 반환 통과. 이 검사는 월드·전송 fixture를 사용한다.
- 허용된 기존 소스 10개 수정/3개 추가 외 1,697개 소스는 직전 ABI10과 바이트 단위로 같다. PSS와 native C++/DLL/코덱은 변경하지 않았다.
- 원본 시간 소비자 정적 재현 자료는 `research/followup/clock-policy-audit.json`과 ASM에 있다. 원본 EXE는 실행하지 않았다. L2 VersionPacket의 프로토콜별 분기 전체를 L1에 이식한 것은 아니다.

실제 Windows 검사 [43395445331](https://github.com/choeyeonggeol16-sketch/1234/actions/runs/43395445331), 소스 `eef6429a3e2615e67dbf7cb89c341d27409ba335`가 통과했다. 실행 결과·검사 커밋은 `WINDOWS_VERIFICATION.json`과 `logs/followup-windows-actual.log`를 따른다. 실제 게임 클라이언트/운영 DB/장시간 부하와 매니저 창의 실제 클릭 조작은 미검증이다. 진단 활성화에는 표본 수집 비용이 있으며 config로 비활성화할 수 있다.

최신 전체 src와 core 묶음의 설정·보고서를 함께 적용하고 clean build한다. ABI는 `0xa0000`이며 DLL SHA는 기존 `de61cd0f15ec1895dfd91340156b3ba91c880837aeb66e034ab6d21666f29014`를 유지한다. 추가 SQL은 없다.
